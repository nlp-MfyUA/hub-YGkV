## 2. 核心功能详细设计

### 2.1 F1 智能问答（NL2SQL）—— 主链路

**用户故事**

> 作为业务运营，我希望直接用中文提问就能得到准确的数字和结论，这样我不需要等分析师排期取数。

**功能流程**

```
用户输入
  → ① 意图识别：取数 / 归因 / 闲聊 / 超范围
  → ② 问题改写：歧义检测（澄清）、指代消解（依赖 F3）、同义词归一（依赖 F7）
  → ③ 表选择：Schema 感知（字段统计 + 样例数据）→ 候选表打分
  → ④ SQL 生成：语义层指标定义 + Few-shot 示例注入 Prompt
  → ⑤ SQL 校验：静态检查（AST）→ 试执行
  →     失败 → SQL 自修复（报错信息回注重写，≤3 次）→ 回到 ⑤
  → ⑥ 权限执行：行/列级过滤注入 → 只读账号执行
  → ⑦ 结果处理：行数保护（>1000 行截断提示）、敏感字段脱敏
  → ⑧ 答案总结：结论句 + 数据表格（转 F2 呈现）
```

**输入 / 输出定义**

- 输入：自然语言问题（≤200 字），会话上下文（会话 ID）；
- 输出：结构化应答 JSON：

```json
{
  "answer_type": "query",
  "conclusion": "albums 表中共有 347 张专辑。",
  "sql": "SELECT COUNT(*) FROM albums;",
  "data": {"columns": ["COUNT(*)"], "rows": [[347]]},
  "metrics_used": [],
  "elapsed_ms": 3200,
  "confidence": 0.92
}
```

**关键规则**

1. 生成的 SQL **只允许引用 Schema 注入中出现的表与字段**，出现未知对象即判定为幻觉，直接拒绝并重生成；
2. 每个问答保存完整轨迹（问题、改写、选中表、SQL、执行结果、耗时），用于审计与回流；
3. 结果超过 1000 行时不直接返回，提示"结果集较大，是否导出/聚合"。

**边界与异常场景**

| 场景 | 处理 |
|---|---|
| 问题歧义（"销售额"未定义口径且语义层缺失） | 追问澄清："请问销售额指含税还是不含税？" |
| 问题超出数据范围（问库存，库里没有） | 明确回答"当前数据源无法回答"，并提示可查主题 |
| 非取数意图（闲聊/写作请求） | 礼貌拒绝并引导回数据问答 |
| SQL 3 次自修复仍失败 | 降级：展示失败原因 + 建议用户换个问法（记录 bad case） |
| 查询超时（>30s） | 终止并提示"数据量较大，建议加时间/维度条件" |

**示例（chinook 数据源）**

| 用户问题 | 生成 SQL | 结论 |
|---|---|---|
| 一共有多少张专辑？ | `SELECT COUNT(*) FROM albums;` | 共有 347 张专辑 |
| 销售额前 10 的客户 | `SELECT c.FirstName||' '||c.LastName AS customer, SUM(i.Total) AS amount FROM invoices i JOIN customers c ON i.CustomerId=c.CustomerId GROUP BY 1 ORDER BY amount DESC LIMIT 10;` | Top10 客户排名 |
| Rock 流派有多少首歌？ | `SELECT COUNT(*) FROM tracks t JOIN genres g ON t.GenreId=g.GenreId WHERE g.Name='Rock';` | Rock 流派共 1297 首 |

### 2.2 F2 可视化生成与图表编辑

**用户故事**

> 作为业务人员，我希望提问后自动得到合适的图表，并可以一键切换图表类型，而不是只看数字。

**设计要点**

1. **图表类型推荐（NL2Viz）**：基于数据特征规则 + LLM 辅助判断：

| 数据特征 | 推荐图表 |
|---|---|
| 单值 | 大数字卡片（Stat Card） |
| 类别 + 数值（类别 ≤ 30） | 柱状图 / 条形图 |
| 时间 + 数值 | 折线图 / 面积图 |
| 类别 + 数值（占比） | 饼图 / 环形图（类别 ≤ 6） |
| 两数值维度分布 | 散点图 |
| 多维交叉 | 分组柱状图 / 热力图 |

2. **图表配置输出**：结构化 Vega-Lite 风格 JSON（图表类型、轴、系列、聚合方式），前端统一渲染；
3. **交互编辑**：切换图表类型、切换排序、TopN 截断、显示数值标签、导出 PNG / 复制到报告；
4. **图表与数据联动**：点击图元可下钻（依赖维度层级定义）或触发追问（"看看这家的订单明细"）。

### 2.3 F3 多轮对话与上下文理解

**用户故事**

> 作为业务人员，我希望像和人聊天一样追问："那 Q4 呢？"、"换成柱状图"、"只看加拿大的"。

**设计要点**

1. **上下文继承**：维护会话级状态（当前主题表、当前过滤条件、当前指标、当前图表类型）；
2. **指代消解**：将"那 Q4 呢"结合上轮问题改写为完整问题："2013 年 Q4 的销售额是多少？"（改写发生在 F1-②，本功能提供状态与改写依据）；
3. **对话操作类指令**：换图表 / 换排序 / 加条件 / 去条件 —— 识别为"查询修改"意图，不重新生成 SQL，而是在上轮 SQL 基础上改写（降低错误率与延迟）；
4. **上下文窗口**：默认携带最近 5 轮问答摘要（问题 + SQL + 结论），超出部分摘要压缩。

**多轮示例**

| 轮次 | 用户输入 | 系统行为 |
|---|---|---|
| 1 | "按月看 2013 年销售额" | 新查询 → 折线图 |
| 2 | "只看 Q4" | 条件修改（月份过滤） |
| 3 | "换个柱状图" | 仅换呈现，不重查 |
| 4 | "和 2012 年同期比呢" | 新查询（对比）→ 分组柱状图 |

### 2.4 F4 查询过程透明

**设计要点**

1. 回答卡片默认展示：结论 + 图表；提供「查看过程」折叠区，展开后按时间线显示：
   - 理解后的问题（改写结果）
   - 命中的指标口径（来自语义层，含口径描述）
   - 生成的 SQL（带语法高亮）
   - 数据来源表 + 执行耗时 + 返回行数
2. **信任锚点**：指标名旁展示 ⓘ 图标，悬浮显示口径定义与负责人；
3. SQL 一键复制，方便分析师复核与复用。

### 2.5 F5 反馈闭环

**设计要点**

1. 每条回答提供 👍/👎；点踩需选择原因（数字不对 / 口径不对 / 图表不合适 / 其他）并可补充说明；
2. 点踩条目自动进入 Bad case 池，附带完整轨迹（问题、SQL、结果）；
3. 运营界面支持：标注正确 SQL → 进入评测集/Few-shot 库；标记口径问题 → 转语义层治理；
4. 每周产出质量周报：点踩率、Top 错误类型、修复进展。

### 2.6 F6 归因分析与洞察（V3）

**用户故事**

> 作为业务负责人，我看到销售额跌了，希望系统直接告诉我"为什么"。

**设计要点**

1. **异动检测**：指标同比/环比偏离阈值（默认 ±10%）触发；
2. **维度拆解归因**：对预设维度（地区、品类、客群、渠道）逐层拆解，计算各维度值对总变化的贡献度（贡献 = Δ 维度值 / Δ 总量）；
3. **洞察生成**：LLM 基于拆解结果生成自然语言结论与建议（"销售额环比下降 12%，主要由加拿大市场（贡献 -68%）与摇滚品类（-45%）导致"）；
4. 归因结果以"瀑布图 + 结论卡"呈现，可逐层下钻验证。

### 2.7 F7 语义层/指标与同义词管理（后台）

**设计要点**

1. **指标对象模型**：

```yaml
metric_name: 销售额
display_name: 销售额
definition: 所有发票的总金额（含税）
calculation: SUM(invoices.Total)
dimensions: [时间, 国家, 客户, 流派]   # 可下钻维度
owner: 数据团队
synonyms: [营业额, 交易额, 总收入]
```

2. **管理功能**：指标 CRUD、版本与变更审批、口径冲突检测（同名不同义）、同义词维护、指标血缘（引用了哪些表字段）；
3. **生成时引用**：NL2SQL 的 Prompt 中注入候选指标定义，命中指标时强制使用 `calculation`，不得自由改写。

### 2.8 F8 数据权限管理（后台）

**设计要点**

1. 权限模型：用户 → 角色 → 数据域（数据源/表/行规则/列脱敏）；
2. 行级规则：如 `country IN (用户负责国家列表)`、`dept = 用户部门`，在 SQL 执行前以子查询方式强制拼入；
3. 列级控制：无权限列不进入 Schema 注入（模型层面"看不见"），敏感列（手机号等）默认脱敏函数包裹；
4. 权限与问答解耦：模型不参与权限判断，权限在执行层强制生效（防提示词注入绕过）。

### 2.9 F9 评测与 Bad case 管理（内部）

**设计要点**

1. **评测集构建**：
   - 冷启动：用 LLM 批量生成"问题 → SQL"对（复用课程 Demo 的 question_prompt / answer_prompt 思路），人工抽检；
   - 持续：线上点踩与修正回流；
   - 覆盖度矩阵：单表/多表 × 单指标/多指标 × 聚合/排序/过滤/时间；
2. **自动评测指标**：
   - 执行准确率：生成 SQL 与标准 SQL 的执行结果一致；
   - 结果准确率：最终自然语言答案与标准答案数值一致（LLM as judge 辅助判定）；
3. **回归机制**：Prompt/模型/参数变更必须跑全量评测集，报告对比上一版本。

### 2.10 F10 会话管理 / F11 数据源管理

- **F10**：会话列表、重命名、收藏、删除；收藏的问答可"固化为卡片"沉淀到个人看板（V3）；
- **F11**：管理员配置数据源连接（只读账号）、元数据同步（表/字段统计刷新）、接入审批；V1 支持 SQLite / MySQL。

## 4. 非功能需求（功能性相关部分）

| 类别 | 要求 |
|---|---|
| 响应时间 | P95 < 10s（含 LLM 与 SQL 执行）；流式输出首 token < 2s |
| 并发 | 支持 100 并发问答（V2） |
| 可用性 | 99.5%；LLM 服务故障时降级提示 |
| 审计 | 全量问答轨迹留存 ≥ 90 天，可按用户/时间/表检索 |
| 兼容 | Web 端响应式；图表支持导出 PNG/SVG |
