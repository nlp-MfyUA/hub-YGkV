## 1. 项目背景与问题定义

### 1.1 业务痛点

ChatBI（见 `../chatbi/`）解决了"快速取数与呈现"，但企业的数据消费中还存在大量**任务型**需求，其特征是"多步骤、多工具、需要加工与产出物"：

1. **分析报告类**："出一份上季度各市场销售分析报告"—— 需要查数、统计、画图、撰写结论，分析师耗时以天计；
2. **数据处理类**："把这份数据清洗规范后给我"—— 需要 SQL 之外的代码处理（格式转换、异常值处理、多源拼接）；
3. **探索建模类**："预测下月销量"、"找出高价值客户群"—— 需要统计/建模代码与迭代验证；
4. **临时脚本类**：重复性的数据小脚本，开发排期成本高。

这些任务的共同点是：**目标明确、过程多步、手段多样（SQL + 代码 + 工具）**，恰好是大模型 Agent（规划 + 工具调用 + 代码执行 + 反思）的适用场景。

### 1.2 技术机会

- 课程 Demo 已验证两条关键链路：SQL Agent（表选择 → SQL 生成 → 执行/修复 → 总结）与 Code Agent（规划 → 代码生成 → 反思修复 → 汇总）；
- 大模型 Function Calling 与多 Agent 编排框架（OpenAI Agents SDK）成熟，可将上述链路组装为自主智能体；
- 沙箱容器技术（Docker）使"让模型写代码并执行"具备生产级安全性。

### 1.3 问题定义

构建 Data Agent 系统，使用户以**一句自然语言任务描述**驱动智能体**自主规划并执行**数据查询、处理、分析、可视化与报告产出，做到：**任务能完成（成功率）、过程可监督（透明）、执行可隔离（安全）、经验可复用（记忆）**。

## 2. 与 ChatBI 的关系和边界

| 维度 | ChatBI | Data Agent |
|---|---|---|
| 交互单位 | 一问一答（秒级） | 一个任务（分钟级） |
| 自主性 | 低（固定 Pipeline） | 高（动态规划） |
| 执行手段 | SQL 查询 | SQL + Python + 多工具 |
| 产出 | 数字 / 图表 / 结论 | 报告 / 数据集 / 图表 / 简报 |
| 准确性策略 | 约束式生成（稳） | 规划-执行-反思（活） |
| 定位 | 取数快路径 | 任务闭环 |

**协同关系**：

1. 共享底座：语义层、DBParser 元数据、SQL 生成与安全检查模块；
2. 路由互通：ChatBI 识别到复杂任务（多步/需建模/需产出物）时，升级移交给 Data Agent；Data Agent 中的简单取数子任务可调用 ChatBI 管线作为工具；
3. 数据同源：同一只读数据账号与权限体系。

## 3. 项目目标与成功指标

### 3.1 目标

1. **任务闭环**：覆盖四类高频任务（报告生成、数据处理、探索分析、可视化产出）的端到端自动完成；
2. **安全可控**：代码执行 100% 在沙箱内，高危操作 100% 人工确认，安全事故为 0；
3. **越用越强**：成功任务沉淀为可检索经验，同类任务效率与成功率持续提升。

### 3.2 成功指标

| 类别 | 指标 | V1 目标 | 说明 |
|---|---|---|---|
| 能力 | 端到端任务成功率 | ≥ 70% | 评测集任务产物达标 |
| 能力 | 子任务（SQL/代码）成功率 | ≥ 85% | 步骤级 |
| 效率 | 典型任务平均耗时 | < 5 min | 报告类任务 |
| 成本 | 单任务平均 token 消耗 | < 100k | 分级模型控制 |
| 可信 | 人工修正率 | ≤ 20% | 产物需人工大改的比例 |
| 安全 | 沙箱逃逸/越权事故 | 0 | 一票否决 |

## 4. 目标用户与使用场景

### 4.1 目标用户

| 用户角色 | 核心诉求 |
|---|---|
| 业务运营 | 自动产出周期性数据简报，替代手工汇总 |

| 业务负责人 | 一句话获得专题分析报告 |

### 4.2 典型场景（示例数据源：chinook 音乐商店）

| T1 | 分析报告 | "分析 2013 年各国家的销售情况，出一份图文报告" | 报告（md/html）+ 多张图表 |
| T2 | 数据处理 | "把客户表按国家拆分成多个 CSV，并统计每个国家的客户数" | N 个 CSV + 统计表 |

## 5. 业界现状分析

| 产品/项目 | 形态 | 可借鉴点 |
|---|---|---|
| Microsoft Data Copilot | 数据任务 Agent | 任务分解为 API 化数据技能，按需调度 |
| TaskWeaver（微软开源） | Code Interpreter Agent | 代码片段插件化、执行状态在会话中延续 |
| Open Interpreter / ChatGPT Code Interpreter | 通用代码执行 | 对话式代码执行 + 自修复循环 |
| Databricks Genie | 数据问答+任务 | 语义治理与权限继承 |
| 课程 Code Agent Demo | 教学验证 | planer → code_gen → reflection → summary 闭环已跑通 |

**结论**：技术路线收敛为"**Planner + 工具集 + 代码沙箱 + 反思循环 + 产物管理**"，差异化与难点在**安全隔离、任务成功率、经验复用**三处，本项目重点投入。

## 6. 产品定位与边界

### 6.1 定位

企业内部的**数据任务自动化智能体平台**：一句话下达任务，Agent 在受控环境中自主完成并交付产物。

### 6.2 范围内（In Scope）

- 任务规划、工具调用、SQL 查询、Python 代码沙箱执行；
- 数据处理（清洗、转换、导出）、可视化、报告生成；
- 任务过程透明、人工确认卡点、产物管理；
- 经验记忆与复用。

### 6.3 范围外（Out of Scope）

- 直接修改业务库数据（写操作一律人工确认且限临时区）；
- 生产级 ETL 调度平台替代（仅做 ETL 辅助脚本生成）；
- 非 SQL 数据源的大规模接入（V1 限关系型数据库 + 上传文件）。

## 7. 总体方案概述

核心思路：**"Planner-Executor-Reflector 三段式 + 工具与沙箱 + 记忆与产物"**。

```
任务描述
   │
   ▼
┌───────────── Planner（规划器）─────────────┐
│ 任务理解 → 子任务 DAG（查数/处理/建模/出图/报告）│
│ + 经验检索：相似成功任务的计划复用（记忆）      │
└──────────────┬───────────────────────────┘
               ▼
┌───────────── Executor（执行器，多 Agent）────┐
│ SQL Agent：表选择→生成→校验→修复→执行         │
│ Code Agent：代码生成→Docker 沙箱执行→反思修复  │
│ 工具调用：绘图 / 文件 / 统计                  │
└──────────────┬───────────────────────────┘
               ▼
┌───────────── Reflector（反思器）─────────────┐
│ 步骤结果检查；失败→重试→换路→重新规划         │
└──────────────┬─────────────────────────────┘
               ▼
┌───────────── Reporter & Artifact ───────────┐
│ 汇总产出报告/图表/文件 → 归档 → 交付用户       │
│ 任务经验入库（成功案例）                       │
└──────────────────────────────────────────────┘
全程：步骤时间线实时展示 · 高危操作人工确认 · 预算熔断
```

## 8. 版本规划

| 版本 | 主题 | 核心内容 | 验收要点 |
|---|---|---|---|
| **V1（MVP，6 周）** | 单 Agent 任务闭环 | Planner + 工具集（元数据/SQL/代码/绘图）+ Docker 沙箱 + 反思重试 + 产物归档 + 步骤时间线 | T1/T3/T5 类任务成功率 ≥70%；沙箱安全测试通过 |
| **V2（+6 周）** | 多 Agent 与记忆 | Planner/SQL/Code/Analyst/Reporter 分工协作；成功案例 RAG 复用；人工确认卡点；报告模板 | 复用命中任务耗时下降 ≥30%；报告类任务达标 |
| **V3（+8 周）** | 主动化 | 定时订阅任务（周报自动生成）；ETL 辅助（清洗脚本生成）；任务市场（沉淀常用任务） | 订阅任务按期产出率 ≥95% |

## 9. 风险与应对

| 风险 | 等级 | 影响 | 应对 |
|---|---|---|---|
| 模型生成代码执行危害环境 | 高 | 安全事故 | Docker 一次性沙箱：无网络、只读挂载、CPU/内存/时长限额 |
| 任务长链路累积误差，末端产物全错 | 高 | 交付质量 | 步骤级结果校验；关键中间产物 checkpoint；报告数据回链可查 |
| 规划错误（漏步骤/错顺序） | 中 | 任务失败 | 经验库复用成熟计划；Planner 输出自检；失败重规划 |
| token 成本失控 | 中 | 成本超预算 | 模型分级（规划/反思用 qwen-max，常规执行 qwen-plus）、步骤与 token 双预算熔断 |
| 长任务失败率随复杂度上升 | 中 | 体验差 | 任务拆分建议；已完成部分交付 + 断点续跑 |
| 权限放大（Agent 替用户越权取数） | 高 | 合规 | 工具层权限随用户上下文传递，执行层强制注入（同 ChatBI） |
