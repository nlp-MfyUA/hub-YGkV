## 2. 核心功能详细设计

### 2.1 F1 任务下达与澄清

**用户故事**

> 作为运营人员，我希望直接说"分析 2013 年各国家销售情况并出报告"，Agent 就能开始干活；如果它没听懂，会先问我，而不是闷头做错。

**设计要点**

1. **任务输入**：自然语言任务描述（≤1000 字）+ 可选附件（CSV/Excel 上传数据，进入工作区供任务引用）；
2. **任务预检**：Agent 接单后先输出「任务理解卡」：
   - 我理解的目标：……
   - 计划使用的表：……（含口径提示）
   - 计划产出的产物：报告 1 份、图表 N 张
   - 预计步骤：4~6 步，预计耗时约 X 分钟
3. **澄清机制**：关键信息缺失（时间范围、目标范围、口径歧义）时生成 ≤2 个澄清问题，一次问全，不连环追问；
4. **确认启动**：用户点「开始执行」后任务进入队列（高危任务见 F3）。

**边界场景**

| 场景 | 处理 |
|---|---|
| 任务超出能力边界（如"爬取外部网站数据"） | 拒绝并说明边界，建议替代方案 |
| 简单取数问题（"专辑总数是多少"） | 建议/自动转 ChatBI 快路径，秒回 |
| 含高危动作的任务（删数据、外发） | 标记高危，逐项确认后才排期 |

### 2.2 F2 任务执行计划展示（时间线）

**设计要点**

1. 任务页以**步骤时间线**实时展示执行过程，每步一个节点：

```
✅ ① 解析元数据        识别出相关表：invoices, customers, tracks (3s)
✅ ② 查询销售数据      SELECT ... 返回 612 行 (8s)   ▸ 查看 SQL
🔄 ③ 生成分析代码      正在沙箱中执行... (12s)
⬜ ④ 绘制图表
⬜ ⑤ 生成报告
```

2. 每个节点可展开：SQL / 代码 / 输出摘要 / 耗时 / token 消耗；
3. 状态机：`待确认 → 排队 → 执行中(步骤i/N) → 等待人工确认 → 完成 / 失败 / 已终止`；
4. 失败节点展示：失败原因 + Agent 的修复尝试记录（"第 2 次尝试：修正了列名拼写"）。

### 2.3 F3 过程干预（暂停/确认/终止）

**设计要点**

1. **人工确认卡点**：执行到高危操作时任务挂起，推送确认卡：

| 操作类型 | 确认方式 |
|---|---|
| 只读查询/沙箱内计算/沙箱内绘图 | 自动执行，无需确认 |
| 生成文件导出/下载 | 轻确认（点击放行） |
| 向临时工作区写入/修改数据 | 显式确认（展示影响范围） |
| 删除文件/数据、对接外部系统 | 强确认（输入任务编号二次确认） |

2. **暂停/恢复**：用户可暂停，Agent 停在当前步骤边界；恢复后继续；
3. **终止**：随时终止，沙箱销毁，已完成产物保留交付；
4. **纠偏消息**：执行中可发消息补充要求（"图表改用蓝色系"），Agent 评估：影响后续步骤则增量调整计划。

### 2.4 F4 产物查看与下载

**设计要点**

1. **产物中心**：任务产物统一列出（报告 md/html、图表 PNG、数据 CSV/Excel），预览 + 下载 + 复制链接；
2. **产物溯源**：每张图表/每段报告数据可回链到生成它的 SQL/代码与源数据快照（可信度关键设计）；
3. **产物再利用**：图表一键插入收藏夹；数据文件可作为新任务附件继续加工；
4. **保留策略**：默认保留 30 天，可续期。

### 2.5 F5 任务规划与分解（Planner）

**设计要点**

1. **输入**：任务描述 + 元数据摘要（可用表清单）+ 相似任务经验（F9）；
2. **输出**：子任务 DAG（JSON），每个节点含：目标、类型（query/code/plot/report/tool）、依赖、预期产物、预算（步数/token）；

```json
{
  "task_id": "t-1024",
  "goal": "2013 年各国销售分析报告",
  "steps": [
    {"id": 1, "type": "query", "goal": "按国家统计 2013 年销售额与订单数", "output": "country_sales.csv"},
    {"id": 2, "type": "query", "goal": "按国家×月份统计销售额", "output": "country_month.csv", "depends": []},
    {"id": 3, "type": "code", "goal": "计算各国同比/环比与集中度", "depends": [1, 2]},
    {"id": 4, "type": "plot", "goal": "各国销售额柱状图、月度趋势折线图", "depends": [1, 2]},
    {"id": 5, "type": "report", "goal": "汇总图文报告", "depends": [3, 4]}
  ],
  "budget": {"max_steps": 15, "max_tokens": 100000}
}
```

3. **规划自检**：Planner 自查（产物是否齐全、依赖是否成环、是否超出预算），不通过则自行修订一次；
4. **无依赖步骤并行**（V2，多 Agent 并发执行）。

### 2.6 F6 工具调用

**工具清单（V1）**

| 工具 | 功能 | 对应课程 Demo |
|---|---|---|
| `parse_table(table)` | 读取表字段统计与样例 | DBParser.get_table_fields |
| `get_relations()` | 获取外键关系（JOIN 依据） | DBParser.get_data_relations |
| `check_sql(sql)` | SQL 静态检查 + 试执行 | DBParser.check_sql |
| `execute_sql(sql)` | 只读执行查询 | DBParser.execute_sql |
| `run_code(code)` | 沙箱执行 Python | Code Agent execute（升级为 Docker） |
| `plot(df, spec)` | 绘图出图 | — |
| `read_file / write_file` | 工作区文件读写 | — |

**设计要点**：

1. 工具以 OpenAI Agents SDK `function_tool` 注册，带类型化参数与描述（Agent 自主选择）；
2. **工具结果回灌**：查询结果以 markdown 表格返回给 Agent（行数大时截断 + 存文件返回路径）；
3. **工具权限随人**：每个工具调用携带用户身份，权限在工具内部强制生效；
4. 插件化扩展（V2）：新工具注册即接入，Planner 通过工具描述感知新能力（F13）。

### 2.7 F7 代码解释器（沙箱执行 + 自修复）

**用户故事**

> 作为分析师，我希望 Agent 能写 Python 做复杂统计和预测，跑错了自己改，不用我盯。

**设计要点（对应课程 Code Agent Demo 的生产化升级）**：

1. **执行流程**（复用 Demo 的 planner → code_gen → reflection → summary 四段式）：
   - 子任务 + 上下文（相关数据文件路径、表 schema）→ 规划思路（可选）
   - → 生成代码（强制带依赖 import 与异常处理）
   - → **Docker 沙箱执行**（一次性容器：无网络、CPU/内存/时长限额、只读挂载数据卷、产物写到工作区）
   - → 失败则**报错回注重修**（reflection），≤3 次
   - → 成功后执行结果摘要返回
2. **代码规范约束**（写入 Prompt）：
   - 数据一律从工作区文件/数据库读取，不硬编码路径之外的位置；
   - 图表统一输出到 `artifacts/` 目录并返回文件路径；
   - 禁止 `os.system`、`subprocess`、网络访问、无限循环（沙箱兜底 + 代码静态扫描双重拦截）；
3. **环境预置**：沙箱镜像内置 numpy / pandas / matplotlib / scikit-learn / sqlalchemy 常用包；
4. **状态延续**：任务内多个代码步骤共享同一工作区（数据文件衔接），但容器每次新建（隔离）。

### 2.8 F8 反思与重规划

**设计要点**

1. **步骤级反思**（V1 内置）：每步执行后校验——SQL 是否可执行、代码是否成功、产物是否存在且非空；失败走重试（SQL ≤3 次、代码 ≤3 次，报错回注）；
2. **路径级反思**（V2）：连续失败 ≥2 次触发"换路"：Planner 给出替代方案（如多表 JOIN 失败 → 分表查询 + 代码拼接）；
3. **结果级反思**（V2）：关键产物做合理性自检（数值量级、空值比例、与粗验 SQL 结果交叉核对）；
4. **全局熔断**：步数/token/时长任一超预算即熔断，输出"已完成部分 + 失败点 + 建议"。

### 2.9 F9 记忆与经验复用

**设计要点**

1. **短期记忆**：任务会话内上下文（计划、中间产物、已执行代码）；
2. **长期记忆（经验库）**：任务成功后自动沉淀案例：

```json
{
  "task_desc": "分析 2013 年各国家销售情况并出报告",
  "plan": [ /* 子任务 DAG */ ],
  "key_code": ["..."],
  "used_tables": ["invoices", "customers"],
  "artifacts": ["report.html", "bar_country.png"],
  "rating": 1
}
```

3. **复用机制**：新任务的规划阶段检索 top-3 相似案例注入 Planner（相似度：任务描述 embedding）；命中度高时直接微调既有计划（改参数/时间范围）而非从零规划；
4. **记忆治理**：用户可对案例点赞（强化复用）/标记问题（下线该案例）。

### 2.10 F10 可视化产出 / F11 报告生成 / F12 数据加工

- **F10 可视化**：绘图工具内置主题与图表规范（复用 ChatBI 的 ChartSpec 体系）；多图产出时保持风格一致；报告插图自动编号与命名；
- **F11 报告生成**：
  - V1 简报版：结论段 + 图表 + 数据表（markdown/html）；
  - V2 模板版：运营周报/专题分析等模板（章节结构固定，Agent 填充内容）；报告数据点标注来源 SQL，可回链；
  - 约束：**所有数字必须来自查询/代码结果**，Prompt 中明确禁止编造，报告生成前做数字一致性校验（抽取报告数字与产物数据比对）；
- **F12 数据加工**：清洗（去重/缺失值/格式标准化）、转换（透视/合并/分组汇总）、导出（CSV/Excel）；加工过程生成"处理说明"（做了什么、丢弃多少行、依据）。

### 2.13-2.16 管理侧功能（概要）

| 功能 | 设计要点 |
|---|---|
| F13 工具与插件管理 | 工具注册/版本/描述维护；上线需安全评审（权限范围、副作用分级） |
| F14 任务与配额管理 | 用户/部门级任务配额（并发数、日 token 额度）；任务队列与优先级 |
| F15 安全审计 | 全量记录：任务、计划、每步工具调用与代码、沙箱资源消耗、确认记录；留存 ≥180 天 |
| F16 评测与案例库 | 评测集（任务 + 预期产物清单）；自动回归（成功率/成本）；案例库人工运营 |

### F17 定时订阅任务（V3，概要）

用户订阅周期任务（"每周一 9 点出上周销售周报"）：到点自动执行 → 产物推送（IM/邮件）；失败自动重试 1 次并告警。

## 4. 非功能需求（功能性相关部分）

| 类别 | 要求 |
|---|---|
| 任务时长 | 单任务 ≤ 15 分钟；超时熔断并交付已完成部分 |
| 并发 | 单用户并发任务 ≤ 2；平台沙箱池按队列弹性伸缩 |
| 可用性 | 99.5%；沙箱故障自动换容器重试 |
| 安全 | 沙箱无网络出站；审计全量留存；高危操作确认率 100% |
| 产物 | 所有产物可溯源（生成代码/SQL + 数据快照 ID） |
