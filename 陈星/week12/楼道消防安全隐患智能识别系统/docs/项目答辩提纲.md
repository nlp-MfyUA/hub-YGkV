# 项目答辩提纲（可直接参考）

## 一分钟介绍

我实现了一个基于多模态大模型的楼道消防安全隐患识别系统。
用户通过手机或电脑网页拍照、上传图片，Python FastAPI 接收图片并检查、压缩；
再把图片用 Base64 编码，发送到 DeepSeek Flash 或 Qwen 视觉模型。
AI 返回照片中可见的电动车、充电线路、堆积物和堵塞情况；
最后由 Python 固定风险规则输出高风险、中等风险、低风险、无隐患或非楼道，
并在网页展示识别依据与处理建议。

## 老师可能提的问题

**Q：什么是前端、后端？**
A：HTML/CSS/JavaScript 负责拍照、上传、展示；FastAPI 负责图片接收、调用 AI 和统一返回结果。

**Q：为什么用多模态模型？**
A：传统文本模型不能直接理解照片；视觉语言模型能够同时处理图片和文字要求，输出场景观察。

**Q：为什么 AI 不直接输出最后的风险等级？**
A：判定标准需要稳定且可测试。我让模型返回可见事实，Python 使用 if 语句计算固定优先级，避免风险等级规则随机变化。不过它不能修正模型识别错误。

**Q：为什么要转成 Base64？**
A：把 JPEG 的二进制数据编码为可放进 JSON 的字符串，通过 `data:image/jpeg;base64,...` 传到模型接口。Base64 本身不具有图像识别能力。

**Q：什么是 API Key？**
A：用于认证调用方的访问凭据，应保存在后端 `.env` 文件中，不要放在浏览器 JavaScript 或提交给他人。

**Q：手机为什么打不开实时摄像头？**
A：网页 `getUserMedia` 需要 HTTPS 或 localhost 等安全上下文；手机通过普通局域网 IP 的 HTTP 访问通常不允许。可以改用系统拍照入口或配置可信 HTTPS。

**Q：系统有没有局限？**
A：存在误报和漏报；相机画质、遮挡和提示词影响效果；部署公网还需要认证、限流和隐私保护。

## 演示顺序

1. 打开网页，展示左侧图片入口与右侧空报告。
2. 选择 DeepSeek/Qwen 模型，说明密钥只配置在后端。
3. 选一张楼道图片，点击「开始 AI 风险检测」。
4. 指出风险级别、描述、识别依据和整改建议。
5. 展示 `backend/risk.py` 的高→中→低→无隐患分级代码。
6. 打开终端执行 `python -m pytest -q` 展示通过的测试。
7. 如无真实 Key，明确使用的是「静态示意报告」，不是实时 AI 检测。
