# SQL Agent 作业测试与验收报告

## 测试环境

- 语言：Python 3.13（兼容设计目标为 3.10+）
- 数据库：课程提供的 Chinook SQLite，共 11 张业务表
- 测试框架：pytest，SQLAlchemy，Pydantic
- Agents SDK：当前验收环境未安装真实包，测试时提供其最小接口替身并使用 Monkeypatch 替代 `Runner.run`；因此**不代表真实模型 API 已通过验收**。

## 测试命令

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
python examples/offline_demo.py
```

## 独立核对的业务数字

- 专辑总数：347
- `albums` 中不同的 `ArtistId`：204（与 artists 表的 275 行不是同一统计口径）
- 购买 Rock 音乐的不同客户：59

老师原示例的一个测试 Mock 曾把 `COUNT(ArtistId)` 的结果描述为“275 位艺人”，这与 SQL 统计含义不一致。提交版将其改为 `COUNT(DISTINCT ArtistId)` 与 204 位，保持查询口径和 Mock 摘要一致。

## 不应过度声称的结果

1. 离线测试不证明真实模型能对任意自然语言问题准确选表。
2. SQLite `EXPLAIN` 只能做有限的语法/对象编译检查，不能保证业务 JOIN 语义正确。
3. 结构最短 BFS 路径不等于业务最佳关联路径。
4. 执行保护适合作业展示，并非完整的生产安全隔离。
