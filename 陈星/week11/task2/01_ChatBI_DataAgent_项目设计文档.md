# ChatBI / Data Agent 项目设计文档

**版本：** V1.0（生产实施设计基线）  
**文档状态：** 生产参考实施版；待现场参数核验、联合评审与上线签收  
**适用范围：** 通用企业内部数据分析平台；具体行业与部署环境待确认  
**关联文档：** 02《功能设计文档》、03《技术设计文档》

## 1. 项目决策摘要

本项目建议定位为**企业数据分析 Agent 平台**，而不是独立的“自然语言转 SQL”工具。平台让业务用户以自然语言提出分析需求，在既有数据权限和统一指标口径下，完成指标理解、可信查询、多轮下钻、可视化与分析解释。

项目采用七项建设原则：**语义优先、领域先行、只读默认、源端鉴权、证据可追溯、确定性计算、评测驱动**。大模型负责意图理解、任务规划和语言表达；指标公式、权限、SQL 安全与统计计算由确定性组件执行。

**本轮建议批准的范围：** 先选择一个业务域、一个主数据仓库、20—50 个已治理核心指标和 50—100 条初始代表性问题，完成 PoC；之后以真实业务 Golden Set 和权限红队测试作为 MVP 上线门槛。此数量为项目规划建议，不代表现有业务事实。

**需要决策的事项：** 试点业务域、数据源与数据量、现有 BI/指标平台复用方案、身份与数据权限机制、数据出域限制、预算上限及 Pilot 用户范围。

## 2. 背景、问题与价值

### 2.1 当前痛点与机会

- **找数慢：** 业务人员依赖分析师定位表、字段和指标，临时需求排队。
- **口径不一：** 相同名称的收入、GMV、活跃用户可能对应不同过滤、去重、时间与退款规则。
- **分析断点：** 传统问数只能给一张表，用户仍需手动下钻、解释波动和制作图表。
- **风险难控：** 直接让模型生成并执行 SQL，可能带来越权、资源耗尽、错误结论和敏感信息泄露。
- **质量难复现：** 模型、提示词、语义模型或数据结构变化后，回答质量可能回退。

原始调研材料提及腾讯云 ChatBI、阿里云 Quick BI 智能小Q、Databricks Genie、Snowflake Cortex Analyst、Looker Conversational Analytics、SuperSonic 和 dbt Semantic Layer，支持“受治理的业务语义 + 自然语言分析”的方向。但原稿中的研究引用是会话标识；本版第19章补充了官方参考 URL，相关竞品功能和版本仍须在采购或技术定型前复核。

### 2.2 项目目标与非目标

| 类别 | 目标 / 边界 | 验收或约束 |
|---|---|---|
| 业务价值 | 降低常见取数和分析的人工成本 | Pilot 记录任务完成率、节省时间、满意度 |
| 数据可信 | 统一指标口径、时间语义、Join 规则 | 关键指标与人工核对结果一致 |
| 用户体验 | 自然语言问数、多轮追问、图表、来源解释 | 典型 P0 场景可独立完成 |
| 安全合规 | 不突破用户/租户/行列权限 | 高风险安全回归用例全部通过 |
| 工程运营 | 可评测、可追踪、可降级、可控成本 | 发布 Gate 和监控看板齐备 |
| MVP 非目标 | 数据写入、任意代码执行、无人审批外部操作 | 默认禁用；后续单独立项 |
| MVP 非目标 | 自建大模型预训练、复杂预测建模、跨所有业务域联邦分析 | 不作为首期验收要求 |

## 4. 用户画像与核心业务场景

| 角色 | 核心任务 | 成功体验 | 风险关注 |
|---|---|---|---|
| 业务运营/销售 | 趋势、排名、占比、下钻 | 不会 SQL 也能独立完成常见分析 | 指标口径错误 |
| 管理者 | KPI、异常概览、业务解释 | 快速获得带证据的摘要 | 把相关性误当因果 |
| 数据分析师 | 复杂筛选、多表探索、SQL 检查 | 减少重复写 SQL 和制图 | Join、时间逻辑错误 |
| Analytics Engineer | 维护指标、实体、Join 和术语 | 一个口径被多个入口复用 | 口径漂移 |
| 数据/安全管理员 | 授权、审计、成本限制 | 访问可控、查询可追溯 | 越权与泄漏 |
| AI 平台管理员 | 工作流、模型、评测、监控 | 回归可定位、成本可观测 | 模型不稳定 |

| 场景编号 | 用户问题示例 | 期望结果 | 阶段 |

| UC-003 | “本月收入同比多少？” | 明确比较区间、币种和时间口径 | MVP |
| UC-004 | “GMV 的计算口径是什么？” | 返回已发布指标定义与版本 | MVP |
| UC-005 | “最近销售怎么样？” | 必要时澄清时间、指标或地区 | MVP |
| UC-006 | “为什么昨天订单下降？” | 先验证下降，再做贡献度拆解；不臆断因果 | V1 |
| UC-007 | “生成每周经营分析报告。” | 报告草稿、引用、人工确认 | V1 |

### 4.2 典型业务旅程

```mermaid
flowchart LR
    Q[业务用户提问] --> C[理解指标与范围]
    C --> S[语义查询或安全 NL2SQL]
    S --> P[权限与成本检查]
    P --> E[只读查询]
    E --> V[结果核验与计算]
    V --> A[图表、解释、来源]
    A --> F[追问、反馈与审计]
```

例如“最近 30 天 GMV 趋势”，系统必须展示采用的 GMV 指标定义、时区、日期区间和过滤条件；如 GMV 存在“下单口径/支付口径”两种定义，应先澄清或展示明确选择，不能静默猜测。

| 阶段 | 建设范围 | 明确不做 | 退出门槛 |

| MVP W9—W20 | P0 功能：对话、澄清、语义优先问数、NL2SQL、权限、基础图表、解释、评测、审计 | 高级归因、跨域联邦、自动 Action | P0 功能验收与质量 Gate 通过 |
| Pilot W21—W24 | 小范围业务试用、培训、反馈、性能/成本调优 | 不直接全面开放 | 业务负责人签收，生产风险可接受 |
| V1（后续） | 高级归因、报告、文件分析、复杂图表、管理增强 | 无审批外部写操作 | 洞察质量专项评测 |

**范围冲突修订：** 原稿将“图表”同时放在 MVP 和 P1。本版统一为：**基础趋势/排名图表属于 MVP P0；智能高级图表和复杂洞察属于 V1 P1**。

## 7. 项目成功指标与评测定义

以下门槛沿用原稿的规划方向并补充统计口径，**均是待 PoC 验证的目标值，不是行业标准或现状实测**。

| 指标 | MVP 建议值 | 统计口径 / 说明 |
|---|---:|---|
| Schema Recall@5 | ≥90% | 有标注表/字段的样本中，Top5 召回包含必要 Schema 的比例 |
| 指标定义 Top3 命中率 | ≥95% | 需有标准指标 ID 的标注集 |
| SQL 语法有效率 | ≥97% | 进入 SQL 生成路径的候选语句，按目标方言解析/校验 |
| Golden Set 执行结果正确率 | ≥85% | 全部可执行问数样本，以结果等价而非 SQL 字符串等价判定 |
| P0 核心指标结果正确率 | ≥95% | 核心指标子集，按统一口径与人工验证结果对比 |
| 多轮指代解析正确率 | ≥90% | 有标注多轮对话集 |
| 数据可追溯率 | ≥95% | 有事实性结论的回答中，能定位指标、过滤、数据源/查询的比例 |
| 简单问数端到端 P95 | ≤15 秒 | 规定数据规模、缓存条件和测试并发后测量 |
| 复杂分析端到端 P95 | ≤40 秒 | 单独定义复杂任务集合，不能与简单问数混算 |
| 用户有效回答率 | ≥80% | Pilot 用户按“可用于业务决策/后续分析”判定 |
| 安全回归 | 高风险用例 100% 通过 | 包括越权、跨租户、危险 SQL、注入和资源上限；零已知严重缺陷 |

**指标解释：** 全集 SQL 执行结果正确率和核心指标正确率的分母不同，不应混为一谈。安全“零事故”不能通过有限测试证明绝对安全，因此以高风险用例全通过、零已知严重缺陷及上线监控共同把关。

### 7.1 Golden Set 结构

每条样本记录：`case_id、question、domain、intent、expected_metric_ids、expected_dimensions、expected_filters、reference_result、permission_context、difficulty、semantic_version、dataset_snapshot`。初始按基础问数、复杂分析、语义陷阱、安全红队四类分层；发布时锁定样本和数据快照，记录回归差异。

## 9. 预算与成本测算（已修正算术）

采用原稿假设：人员综合成本 **4—8 万元/人月**；基础设施与模型费用为阶段估算。按区间端点分别相乘：

| 阶段 | 团队 × 周期 | 人月 | 人力费用（万元） | 模型/基础设施（万元） | 总费用（万元） |
|---|---|---:|---:|---:|---:|
| PoC | 3.5—4.5 FTE × 2.5—3 月 | 8.75—13.5 | 35—108 | 3—10 | **38—118** |
| MVP | 6—8 FTE × 4—5 月 | 24—40 | 96—320 | 10—40 | **106—360** |
| 生产级 | 9—12 FTE × 6—9 月 | 54—108 | 216—864 | 40—150 | **256—1014** |

**说明：** 三行是不同建设规模的独立估算场景，不能直接相加为项目累计预算；如果 PoC 团队进入 MVP，应按实际重叠人月去重。PoC 费用假设包含 W1—W8 的准备与验证工作及额外 2—4 周评审/资源缓冲，因而不等于 W5—W8 的纯开发周期；MVP 费用则按从项目启动到功能与质量门槛的 4—5 个月整体测算。原稿 PoC/MVP 的部分最大值与“8 万元/人月”假设不一致，本版已按统一公式修正。生产成本需在 Pilot 取得真实 Token、查询扫描量、并发和供应商报价后重新核算。

模型费用应按输入 Token、输出 Token、不同模型单价、每问题调用次数、缓存命中率及失败重试分别计算，不能用单一平均 Token 单价代替全部调用。

## 10. 风险、依赖与缓解措施

| 风险 | 影响 | 早期信号 | 缓解与负责人 |
|---|---|---|---|
| 指标口径不统一 | 回答不可信 | 同一问题不同系统结果不同 | 指标负责人签收语义模型；数据负责人 |
| 权限继承失败 | 严重泄漏 | 服务账号看到超出用户权限的数据 | 源端鉴权/强制策略与红队；安全负责人 |
| 数据源质量差 | SQL 正确但结论错误 | NULL/重复/延迟高 | 数据质量检查、时效提示；数据工程师 |
| NL2SQL 长尾失败 | 有效回答率低 | 多表/复杂时间问题失败集中 | 检索、示例 SQL、有限修复；Agent 工程师 |
| 查询成本失控 | 数据仓库费用和延迟上升 | 扫描量、超时、重试升高 | 预算阈值、EXPLAIN、并发限制；SRE |
| 模型与数据出域 | 合规或商业风险 | Prompt 含敏感字段/结果 | 分类分级、脱敏、网关路由；安全负责人 |
| 评测集失真 | 虚高指标 | Demo 高分、Pilot 低满意度 | 冻结数据快照、分层盲测；QA/Eval |
| 供应商锁定 | 迁移成本高 | Prompt/工具耦合厂商 SDK | 模型网关、标准契约；架构师 |

## 11. 待确认问题与评审签收

- **业务负责人：** 首期领域、Top 20 分析任务、GMV/收入等核心指标定义、Pilot 人员和成功标准。
- **数据负责人：** 数据源清单、数据量、更新频率、数据质量、已有语义平台、字段敏感级别。
- **安全负责人：** 用户身份透传、RLS/CLS 实施位置、审计留存、数据出域/跨境约束。
- **技术负责人：** 模型部署方式、SQL 方言、数据库隔离、并发与性能基线、预算上限。
- **项目 Sponsor：** PoC/MVP 的投资 Gate、是否允许延期或缩减范围、最终上线审批人。

## 13. 生产实施基线（本版正式采用）

本章将前文“未指定”事项收敛为**可用于研发估算、压测和验收的参考部署场景**。它是工程设计输入，不是企业现网调查结果。实施时只允许通过配置清单和变更审批调整，不得在代码里散落未经审批的默认值。

| 项目 | 生产参考值 | 实施说明 / 调整条件 |
|---|---|---|
| 业务边界 | 企业内部销售经营分析；首期一个业务域 | 示例域：订单、地区、产品、渠道；不得据此认定公司已有这些表 |
| 用户与请求 | 200 个注册用户、50 DAU、1,000 问题/工作日 | 峰值按 1 请求/秒、30 个在途 Agent 任务压测 |
| 数据域 | 一个主数仓、5—15 张治理表、30 个发布指标 | 首期仅支持一个已验证 SQL 方言；其余连接器暂不上线 |
| 数据分类 | 首期仅接入已批准的内部经营数据 | 薪酬、身份证号、个人联系方式等敏感字段默认不接入 |
| 身份 | 企业 SSO/OIDC，后端验证签名与受众 | `tenant_id/user_id` 只来自可信身份层，不能从 Prompt 取值 |
| 权限 | 元数据 ACL + 查询前授权 + 源端强制策略 | 源端不能有效隔离用户时，相关敏感数据集禁止上线 |
| 部署 | 单区域、两个可用区，开发/预发/生产隔离 | API/Worker 双副本起步，数据库采用托管高可用或等效方案 |
| 模型 | 已批准区域内模型网关，主备路由 | 不允许未经批准把数据发送至跨区域备份模型 |
| 存储 | 原始事实留在数仓；平台存元数据/必要状态 | 不建立全量数据副本；临时结果遵守最短保留策略 |
| 功能边界 | 只读问数、澄清、多轮、基础图表、证据链 | 导出、定时报告、外部 Action、跨域联邦默认关闭 |

### 13.1 关键假设冻结与变更机制

基线编号 `BASE-2026-10`。生产上线前，产品负责人签收指标与业务范围，数据负责人签收源端权限和数据新鲜度，安全负责人签收数据分类与模型出域，技术负责人签收性能容量，SRE 签收监控/灾备。任何调整数据源、模型区域、行列权限机制或导出范围的变更均视为**重大变更**，需要重新运行安全和 Golden Set 验证。

### 13.2 数据资产准入清单

| 准入门槛 | 责任人 | 可核验交付物 |
|---|---|---|
| 数据集有所有者、用途、保留期和敏感级别 | 数据 Owner | Data Catalog 条目 |
| 30 个核心指标有公式、过滤、时间字段、币种/单位 | Analytics Engineer | 已发布语义模型与版本 |
| Join 基数、重复行、空值和时区规则可复核 | 数据工程师 | 数据质量报告、样例对账 |
| 行列权限在真实执行身份下有效 | 安全/DBA | 两用户两租户交叉验证记录 |
| 数据时效和源端 SLA 已明确 | 数据 Owner | `data_as_of`/watermark 映射 |
| 数据源账号最小权限、只读、限额可执行 | DBA/SRE | 权限清单与拒绝性测试 |

## 14. 生产服务等级与容量决策

以下指标为**上线前必须用压测证明的目标**；未完成压测不能在对外承诺中宣称达标。

| SLI / SLO | 生产初始目标 | 计算口径 |
|---|---|---|
| API 月可用性 | ≥99.9% | 成功响应且能创建任务的请求 / 合法请求；区分源端故障 |
| 首次进度可见时间 | P95 ≤2 秒 | 从请求接收至首个有效 SSE 状态事件 |
| 简单问数时延 | P95 ≤15 秒 | 单指标/单域、基线并发、含模型与数仓时间 |
| 复杂问数时延 | P95 ≤45 秒 | 多维/多轮/多表；超时不计作成功但计入失败率 |
| 业务问数正确率 | Golden Set ≥90% | 300 条冻结业务样本；结果等价，分场景统计 |
| 核心指标正确率 | ≥98% | 已治理 30 指标相关样本，人工对账 |
| 安全回归 | 100% 高风险用例通过 | 另建 ≥100 条安全红队样本；零已知严重缺陷 |
| 端到端任务成功率 | ≥98% | 合法且有授权数据的问题；排除用户主动取消但不排除系统失败 |
| 备份恢复 | RPO ≤15 分钟，RTO ≤60 分钟 | 平台元数据与配置；数仓按源端 SLA 独立约定 |
| 数据新鲜度 | 100% 回答展示水位 | `data_as_of` 源自数据资产契约，不以回答生成时间冒充 |

**容量核算示例：** 1,000 问题/工作日 × 22 工作日 = 22,000 问题/月。按峰值 1 QPS、平均 15 秒在途计算，Little 定律约需 15 个在途任务；按 2 倍峰值裕量设置 30 个 Agent 并发槽。数据库查询并发独立限为 12，超过后入队；**此估算不等于压测结果**。数仓侧扫描量与模型供应商的 RPM/TPM 必须单独校验，不能只按 API QPS 估算。

**错误预算：** 99.9% 月可用性对应约 43 分钟/月的不可用预算（按 30 天计）。持续消耗超过 50% 时冻结非紧急发布，超过 100% 时停止功能发布并优先修复可靠性问题。数据源停机要在仪表盘独立归因，但不能从用户感知失败中隐去。

## 15. 生产发布门禁与实施任务包

| Gate | 最迟阶段 | 交付物 | 不通过时的处理 |
|---|---|---|---|
| G0 数据准入 | W4 | 数据分级、授权链路、指标 Owner、语义覆盖表 | 不允许接入真实敏感数据 |
| G1 PoC | W8 | 100 条初始业务题、只读查询闭环、威胁模型 | 限制为实验环境 |
| G2 MVP 功能 | W16 | FR-001—013 + FR-019—026 适用项的验收证据 | 继续预发联调，不开放 Pilot |
| G3 质量与安全 | W20 | 300 业务题 + 100 安全题、压测、渗透、恢复演练 | 拒绝发布或缩减功能/数据范围 |
| G4 生产试点 | W24 | 灰度计划、监控、值班、回滚、业务签收 | 仅内部白名单试点，不全量放开 |
| G5 规模化 | Pilot 后 | 真实成本、业务采用率、故障复盘、扩容决策 | 保持单领域并优化，不盲目多域扩张 |

**发布策略：** 5% → 20% → 100% 白名单灰度；每档至少覆盖一个完整业务工作周期和核心问数场景。指标正确率、越权事件、P95、失败率、单问成本任一越线时立即停止放量。语义模型版本、Prompt、模型路由、SQL Guard 策略和应用版本应能独立回滚；回滚后运行权限和数据快照一致性检查。

**责任分工：** 产品负责业务 UAT，Analytics Engineer 负责指标对账，QA/Eval 负责冻结集，安全负责权限/红队，SRE 负责 SLO/备份/回滚，技术负责人对上线技术风险签字。业务负责人对数据解释边界和试点范围签字。

## 16. 生产运营模型与持续成本控制

### 16.1 运维职责与响应

| 事件级别 | 判定示例 | 初始响应目标 | 处置负责人 |
|---|---|---|---|
| SEV-1 | 跨租户泄漏、未授权执行、广泛不可用 | 15 分钟内响应；立即冻结相关能力 | 安全负责人 + SRE 值班 |
| SEV-2 | 核心指标大面积错误、模型主备均不可用 | 30 分钟内响应 | Tech Lead + 数据 Owner |
| SEV-3 | 单数据集失败、个别图表异常、非核心延迟 | 4 工作小时内响应 | 模块 Owner |

故障闭环：检测 → 分类 → 熔断/撤权/回滚 → 证据保全 → 影响面确认 → 通知 → 根因复盘 → 回归用例入库。**发生数据泄漏时优先隔离与保全证据，不让 Agent 自动处理事件。**

### 16.2 成本预算控制

| 成本池 | 计费驱动 | 控制措施 |
|---|---|---|
| LLM | 输入/输出 Token、调用次数、模型层级 | 预算配额、上下文裁剪、缓存、主备成本阈值 |
| 数据仓库 | 扫描量、计算时长、并发资源 | 查询计划估算、配额、超时、只读资源组 |
| 应用服务 | Pod/Worker、队列、日志和存储 | HPA、日志采样、生命周期策略 |
| 人工治理 | 指标建模、评测标注、值班 | 需求优先级、领域 Owner、自动回归 |

月模型预算初始设为 **3 万元人民币软上限**，月查询量基线 22,000，对应平均约 **1.36 元/问题** 的预算空间；这是**预算倒推值，不是已验证的模型成本**。到 70% 触发告警，90% 禁用非必要高成本模式，100% 由业务负责人审批预算扩容或降级服务；不能在预算耗尽时绕过权限或偷偷改用未批准模型。数据仓库费用和基础设施费用另列，不混入模型预算。

### 16.3 数据与会话保留基线

| 对象 | 初始保留期 | 要求 |
|---|---|---|
| 会话文本 | 90 天 | 用户可删除；法定/企业保留要求优先 |
| SQL/查询元数据 | 30 天 | 默认不保留敏感结果集；审计关联 query_id |
| 安全审计 | 180 天 | 防篡改、分权访问；最终按公司合规政策调整 |
| 详细 Trace | 14 天 | 默认不采集完整 Prompt、结果行和凭据 |
| 查询缓存 | 最长 5 分钟 | 绑定租户、身份、权限版本、数据版本并支持撤权失效 |
| 备份 | 30 天滚动 + PITR | 加密、恢复演练、备份权限独立 |

## 17. 业务采用、质量复盘与退出条件

**Pilot 运行 4 周**，每周按业务域统计：周活用户、首次任务成功率、重复提问率、人工改写 SQL 比例、平均节省分析时间、负反馈分类、指标对账偏差和单位成本。有效回答率建议 ≥85%，但须由用户明确反馈或人工抽样定义，不使用模型自评分替代。

**继续投资的条件：** 核心指标正确率与安全门槛达标、业务方确认节省时间、每月成本在预算内、至少一名数据 Owner 持续维护语义层。若两次迭代后仍无法达到核心指标正确率，应优先收缩业务域并完善语义治理，而非直接增加模型自主权。

**退出/暂停条件：** 源端权限不可强制、敏感数据流向无法控制、Golden Set 缺乏可重复数据快照、没有数据 Owner、无法满足关键 SLO。上述任一条件存在时只能保持隔离 PoC，不应以“生产试运行”名义扩大访问范围。
