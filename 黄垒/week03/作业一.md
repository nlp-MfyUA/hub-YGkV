1、 langchain 工具调用 和 llm function call 有什么区别？

* langchain: 对原生的API进行统一抽象和封装，提供统一接口，可无缝切换不同 LLM 提供商，提供 @tool 装饰器等便捷方式，从函数签名和文档自动生成 Schema，集成回调、记忆管理、重试、错误处理等高级功能，LangChain 通过封装，能用更少的代码、更统一的方式调用不同模型的工具能力。

* llm function call: LLM 提供商的原生 API 功能, 与特定模型提供商绑定，接口可能存在差异，需按各平台规范编写 JSON Schema，仅提供基础的函数调用能力。


2、 langchain 工具调用 的 速度是受到什么影响？

LangChain 的速度瓶颈主要来自其框架本身的开销：
* 多层抽象开销，这是框架带来的必不可少的开销，一次工具调用会穿过内部多个层次结构，这些开销会叠加到工具本身的调用上
* 隐式的重试与决策逻辑，LangChain 的工具调用会自动重试，并根据当前的上下文进行决策，这也会增加额外的开销，一次调用，底层可能已经跑了2-3轮
* Schema 的重复生成，在 LangChain 内部，工具的 JSON Schema 可能会在每次模型调用时被重复构建
* Agent 状态维护，LangChain 的 Agent 会自动维护一个状态，用于存储历史对话和当前的上下文，这也会增加额外的开销
