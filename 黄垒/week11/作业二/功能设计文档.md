## 1. 文档目的

本文档描述 ChatBI 一期（MVP）的**功能边界、功能清单、交互规则与验收标准**，作为产品、研发、测试的共同依据。

功能设计遵循三条原则：

1. **宁可说不会，不给错数**：无法确定时澄清或拒绝，不默认猜测；
2. **每个结论都可追溯**：任何答案都能展开看到 SQL、口径、数据来源与新鲜度；
3. **权限先于功能**：无权限的指标在检索阶段就不可见，而不是展示后再拦截。

## 4. 核心用户流程

### 4.1 问数主流程

```
用户输入问题
    │
    ▼
[意图识别] ──非查询类──▶ F-19 说明能力边界 + 给出可用的问法
    │
    ▼
[资产检索] ──无匹配指标──▶ 提示"暂不支持该指标" + 推荐相近指标
    │
    ▼
[歧义检查] ──多个候选──▶ F-03 澄清反问（选择题）
    │                          │
    │◀─────────用户选择─────────┘
    ▼
[生成查询计划 IR] ──必填槽位缺失──▶ 追问（仅在影响正确性时）
    │
    ▼
[SQL 生成] → [校验] ──失败──▶ [自动改写]（≤2 次）──仍失败──▶ 明确失败 + 建议
    │
    ▼
[权限注入] → [执行] ──超时/报错──▶ F-20 降级提示
    │
    ▼
[结果自检] ──异常──▶ 标注可疑 + 提示确认口径
    │
    ▼
[图表选型 + 结论生成]
    │
    ▼
展示：结论 + 图表 + 数据表 + 可展开的 SQL/口径/新鲜度
```

### 4.2 澄清流程

```
检索到多个候选指标
   │
   ├── 候选互斥（不同口径）──▶ 必须澄清：以选择题返回
   ├── 候选可并存（父子指标）──▶ 默认选最常用，同时明示"我按 X 理解"
   └── 用户已在上文指定过──▶ 沿用会话状态，不再重复询问
```

**规则**：

- 澄清问题**必须给选项**，不允许开放式提问（"您想查什么？"是反例）；
- 最多同时问 2 个问题，超过则拆成多轮；
- 每个选项附带一句话说明，帮助非专业用户判断；
- 用户不选择直接追问时，沿用上一轮的候选排序第一条并在结果中标注。

### 4.3 多轮追问

| 情况 | 处理 |
| --- | --- |
| 只修改过滤条件（"只看华东"） | 保留指标/时间/维度，替换过滤 |
| 只修改维度（"按产品线拆"） | 保留指标/时间/过滤，替换维度 |
| 只修改时间（"那 Q4 呢"） | 保留其它槽位，替换时间 |
| 指代（"这个""上面那个"） | 绑定到上一轮结果中的实体（指标或维度值） |
| 完全无关的新问题 | 开启新查询上下文，历史仅作展示 |

**规则**：会话状态是结构化的 `{指标, 维度, 过滤, 时间, 粒度, 排序, limit}`，不把历史对话全文拼进提示词。

### 4.4 反馈流程

```
用户点击"不对" → 选择原因（口径不对 / 数字不对 / 理解错了 / 数据问题）
    → 写入反馈表（含问题、IR、SQL、结果快照）
    → 每周归因 → 补语义层 / 补 few-shot / 加澄清规则 / 报数据团队
    → 回归评测
```

## 5. 功能清单

### 5.1 对话问答

#### F-01 自然语言输入与意图识别　`P1`

**描述**：接收用户输入，判断是否为数据查询类问题，并抽取问题类型与显式槽位。

**规则**：

- 问题类型：单指标 / 对比 / 趋势 / 排名 / 明细 / 归因 / 非查询；
- 抽取槽位：时间、维度、过滤、度量、排序、TopN；
- 时间表达必须用确定性规则 + 当前日期锚点解析（"上个月""Q3""最近一周"），不让大模型计算日期；
- 归因类问题不做因果推断，转入 F-19。

**验收标准**：

- 20 条时间表达测试用例解析准确率 100%；
- 非查询类问题 100% 不生成 SQL，并给出能力边界说明。

#### F-02 指标 / 维度检索与选表　`P1`

**描述**：把问题中的自然语言词映射到语义层的指标、维度、实体，确定事实表与 JOIN 路径。

**规则**：

- 向量检索 + 别名精确匹配 + 业务域过滤，召回 Top-K（K=5~10）；
- 仅召回当前用户有权限的指标；
- JOIN 路径来自语义层实体关系，不由模型猜测；
- 多表时自动补全最短 JOIN 路径上的中间表。

**验收标准**：Golden Set 中资产检索 Recall@5 ≥ 95%；越权指标召回数为 0。

#### F-03 歧义澄清反问　`P1`

**描述**：当问题存在多个合理理解时，以选择题形式反问。

**规则**：见 4.2。

**验收标准**：多义指标测试集中，100% 触发澄清或明示口径；澄清后一次通过率 ≥ 90%。

#### F-04 SQL 生成　`P1`

**描述**：基于查询计划 IR 与语义层资产生成 SQL。

**规则**：

- 优先走语义层编译器（IR → SQL），编译不了才由大模型生成；
- 模型生成时必须注入方言（一期：目标数仓方言）与 few-shot 示例；
- 只允许单条 SELECT / WITH 查询；
- 明细类查询必须带 LIMIT（默认 100，上限 10000）。

**验收标准**：生成的 SQL 执行成功率 ≥ 90%；兜底率 < 10%。

#### F-05 SQL 校验与自动改写　`P1`

**描述**：执行前对 SQL 做静态与动态校验，失败时把错误喂回模型自动改写。

**校验规则**：

| 层级 | 检查项 | 处理 |
| --- | --- | --- |
| 静态 | 单条语句 | 拒绝 |
| 静态 | 必须以 SELECT / WITH 开头 | 拒绝 |
| 静态 | 禁止 INSERT/UPDATE/DELETE/DROP/ALTER/CREATE 等 | 拒绝 |
| 静态 | 表 / 字段必须在语义层白名单内 | 拒绝 |
| 静态 | JOIN 必须有 ON 条件（防笛卡尔积） | 拒绝 |
| 静态 | 大表查询必须带分区过滤 | 拒绝 |
| 动态 | 用目标库 parser / EXPLAIN 编译 | 失败则改写 |
| 动态 | 预估扫描量超阈值 | 拒绝并提示缩小范围 |

**规则**：自动改写最多 2 次；失败后明确告知"暂时无法生成正确查询"，不返回未经校验的结果。

**验收标准**：50 条危险 SQL 拦截率 100%；自动改写成功率 ≥ 60%。

#### F-06 SQL 执行　`P1`

**描述**：以只读方式执行查询。

**规则**：独立只读账号；语句超时 60s；结果行数上限 10000；超时给出降级提示。

**验收标准**：连续 100 次查询无写操作成功；超时请求 100% 在 60s 内终止。

#### F-19 能力边界提示　`P1`

**描述**：对超出能力范围的问题明确说"不会"，并给出可执行的替代问法。

**文案示例**：

> 这个问题属于归因分析（为什么下降），我只能基于查询结果描述事实，无法判断因果关系。
> 你可以试试："近 6 个月各渠道的订单量趋势""9 月与 8 月的订单量对比"。

### 5.2 结果呈现

#### F-07 结果表格　`P1`

- 列名使用业务名称，不直接暴露物理字段名；
- 数值右对齐、千分位、保留合适小数位；
- 超过 100 行分页，导出 CSV 受权限约束。

#### F-08 图表自动选型　`P1`

**规则（确定性规则，不让模型自由决定）**：

| 结果结构 | 图表 |
| --- | --- |
| 单值（1 行 1 列） | 指标卡 |
| 1 个时间维度 + 1 个度量 | 折线图 |
| 1 个分类维度 + 1 个度量 | 柱状图 |
| 1 个分类维度 + 1 个占比度量（≤8 类） | 饼图 |
| 2 个维度 + 1 个度量 | 分组柱状图 |
| 其它 | 表格兜底 |

**验收标准**：给定 30 组结果结构，选型正确率 100%（规则可复核）。

#### F-09 结论生成　`P1`

**规则**：

- 只做**基于查询结果的事实描述**：数值、同比/环比、TopN、占比、极值；
- 不做因果推断，不使用结果中不存在的数据；
- 低基数结果逐条列出，高基数只给 TopN 与合计；
- 长度 ≤ 150 字。

**文案示例**：

> 昨天华东区订单量 12,480 单，较前一日下降 3.2%；其中上海 4,120 单（33.0%），占比最高。

#### F-10 可信度展示　`P0`

**必须展示**：

- 可展开的 SQL（默认收起）；
- 业务口径说明（"GMV：含税、不含退款，按支付时间统计"）；
- 使用的数据表与数据新鲜度（"订单表最后更新：2026-10-21 03:00"）；
- 置信度提示（低置信度时显示"我按 X 口径理解，如不对请纠正"）。

#### F-20 空结果与异常处理　`P1`

| 情况 | 处理 |
| --- | --- |
| 结果为 0 行 | 区分"确实无数据"与"条件可能有误"，给出放宽建议 |
| 查询超时 | 提示缩小时间范围，或自动降级到预聚合表 |
| 结果异常（比率为负 / >100%、计数为负） | 标注"结果异常，请确认口径" |
| 数据不新鲜 | 结果区显示醒目的新鲜度告警 |

### 5.3 会话

#### F-11 多轮对话与上下文　`P1`

**规则**：见 4.3；会话状态保存在服务端，按 session_id 隔离；不把完整历史拼进提示词。

**验收标准**：连续 5 轮增量修改场景，槽位继承正确率 ≥ 95%。

#### F-12 会话历史　`P2`

- 会话列表、重命名、删除；
- 历史消息可回看当时的 SQL 与结果快照；
- 按用户隔离，不可跨用户访问。

---

### 5.4 数据与治理

#### F-13 语义层管理　`P0`

**描述**：管理指标、维度、实体关系、同义词。

**指标定义字段**：名称、别名、业务口径描述、计算表达式、默认过滤、可用维度、粒度、数据源、owner、更新时间。

**规则**：指标变更走评审；变更后自动触发 Golden Set 回归评测。

#### F-17 数据源管理　`P1`

一期只支持一个数仓连接；记录连接信息、只读账号、资源组、SLA。

#### F-18 评测与回归　`P1`

- Golden Set 管理与版本化；
- 每次语义层 / 提示词变更自动跑回归；
- 展示分阶段指标（检索召回、SQL 执行成功率、结果集一致率）。

---

### 5.5 安全与合规

#### F-14 权限管理　`P0`

三层权限：

| 层 | 控制 | 实现位置 |
| --- | --- | --- |
| 指标级 | 能否查询某指标 | 检索阶段过滤 |
| 行级 | 能看哪些行 | IR → SQL 阶段注入 `WHERE` |
| 列级 | 敏感字段如何展示 | 结果返回前脱敏（掩码 / 哈希 / 拒绝） |

**验收标准**：两个区域账号问同一问题，SQL 自动带不同过滤；越权指标检索不到；脱敏字段在日志与缓存中也不出现明文。

#### F-15 审计日志　`P0`

每条记录包含：用户、问题、IR、SQL、访问的表、返回行数、耗时、时间、IP、是否被拦截。
保留期按合规要求（默认 180 天）。敏感指标访问单独告警。

---

### 5.6 运营

#### F-16 反馈与 bad case 闭环　`P1`

见 4.4。每周输出归因报告：口径缺失 / 表选错 / 歧义未澄清 / 数据问题各占比及处理进展。

## 6. 界面与交互要点

### 6.1 主界面布局

```
┌────────────┬──────────────────────────────────────────────┐
│ 会话列表    │  对话区                                       │
│            │  ┌────────────────────────────────────────┐  │
│ · 今日      │  │ 用户：昨天华东区的订单量是多少？          │  │
│ · 上周      │  └────────────────────────────────────────┘  │
│            │  ┌────────────────────────────────────────┐  │
│            │  │ 结论：昨天华东区订单量 12,480 单，         │  │
│            │  │      较前一日下降 3.2%。                 │  │
│            │  │ ┌──────────┐                            │  │
│            │  │ │ 12,480 单 │  ← 指标卡                  │  │
│            │  │ └──────────┘                            │  │
│            │  │ [查看 SQL] [口径说明] [数据更新于...]     │  │
│            │  │ 👍 采纳   👎 不对                          │  │
│            │  └────────────────────────────────────────┘  │
│            │  ┌────────────────────────────────────────┐  │
│            │  │ 输入问题...                        [发送] │  │
│            │  └────────────────────────────────────────┘  │
└────────────┴──────────────────────────────────────────────┘
```

### 6.2 关键交互规则

| 场景 | 规则 |
| --- | --- |
| 处理中 | 展示阶段进度（"正在理解问题 / 正在生成查询 / 正在执行"），超过 3s 显示具体阶段 |
| 澄清 | 以选项按钮呈现，可直接点击；也允许用户直接输入新问法 |
| 展开 SQL | 只对有权限的用户展示；SQL 只读，不允许在界面直接执行修改后的 SQL |
| 错误 | 说清"哪里失败 + 用户能做什么"，不暴露堆栈和内部表名 |
| 空结果 | 不显示空表格，显示提示与放宽建议 |

### 6.3 文案规范

- 不说"AI 认为"，直接给结论；
- 不确定时明确写"我按 X 口径理解"；
- 不使用"可能""大概"等模糊词修饰具体数字；
- 失败时给出下一步动作，不只说"出错了"。
