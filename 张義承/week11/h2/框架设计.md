# ChatBI 项目框架设计

> **早期框架草案。正式版本见 [`项目设计文档.md`](项目设计文档.md)。**

- 状态：**框架已定（含两条硬验收：数据可追溯、隐私与鉴权），尚未实现**
- 数据域：自建电商销售库（5 表）——待确认造数边界
- 开发方式：vibe coding
- 原则：先定边界与契约，再写实现

## 0. 验收标准（最高优先级）

功能可以少，以下两条不能破。

### A. 数据不编造、全可追溯

- 回答中的一切数字必须来自本次数据库查询结果
- 摘要只允许复述结果集中的值，禁止推算未查询到的数字
- 每轮日志必须记录：问题、完整 SQL、访问的表与字段、结果行数、耗时、修复次数
- 查不到就说"查不到"，不得给出猜测值
- 日志足以复现整次查询

### B. 隐私安全与鉴权

- 客户信息不得泄露；**仅对姓名脱敏而返回其订单，仍然构成泄露**
- 默认只允许聚合查询；涉及具体客户/账号的个体级查询**默认拒绝**
- 鉴权：每次查询必须绑定请求者身份（账号 + 角色）
- 无权限时统一回复「该用户不存在，或您无权查询该用户的记录」，不得暴露账号是否存在
- 授权范围内的展示仍需脱敏（姓名 `张*`、手机号 `138****1234`、地址只保留到省市）
- 脱敏发生在**结果进入 LLM 与展示之前**，原始 PII 不离开数据层
- 日志与审计记录禁止落原始 PII
- 权限相关行为必须审计：请求者账号、角色、行为、时间、目标主体（哈希）、决策

### 待确认

"不允许造数据"指：
- **A 读法**：仅约束系统回答不得编造（示例数据仍可由脚本生成）← 当前框架按此设计
- **B 读法**：数据准备阶段也不允许脚本生成，必须使用真实数据源

## 1. 目标与非目标

### 目标

1. 用户用自然语言提问，系统自动生成 SQL、查询本地数据库、以表格/图表呈现，并附一段结论。
2. 生成的 SQL 始终可见，用户可核对。
3. 出错时能自我修复，而不是直接报错给用户。
4. 覆盖电商销售域的常见问题形态：单值、趋势、排名、占比、同环比、比率、下钻、明细。
5. **满足第 0 节两条硬验收。**

### 非目标（本版不做）

- 生产级权限体系（行级/列级权限的完整体系）
- 多数据源接入
- 大数据量性能优化
- 移动端适配
- 复杂语义层可视化配置界面

## 2. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│ 表现层  UI                                                    │
│   登录 · 对话输入 · 消息流 · 结果表格 · 图表 · SQL 展开        │
├──────────────────────────────────────────────────────────────┤
│ 应用层  Orchestrator                                          │
│   身份认证 · 权限校验 · 流程编排 · 澄清反问 · 审计记录         │
├──────────────────────────────────────────────────────────────┤
│ 智能层  Intelligence                                          │
│   意图识别 · 上下文组装 · NL2SQL · 自修复 · 图表选型 · 摘要    │
├──────────────────────────────────────────────────────────────┤
│ 数据层  Data                                                  │
│   只读连接 · Schema 元数据 · 语义层 · 安全校验 · 执行器        │
│   隐私脱敏 · 数据溯源                                          │
├──────────────────────────────────────────────────────────────┤
│ 基础设施  Infra                                               │
│   配置 · 日志 · 审计 · 错误模型 · 评测集                       │
└──────────────────────────────────────────────────────────────┘
```

**依赖方向**：上层依赖下层，下层不感知上层。

**硬约束**：
- 智能层只通过接口拿**已脱敏、已登记来源**的数据，不直接连数据库
- 原始 PII 不得离开数据层
- 所有回答的数字必须能回溯到一次 `ExecutionResult`
- 每次查询先鉴权后执行；未授权查询不生成 SQL、不访问数据库
- 权限拒绝与"用户不存在"返回同一话术，避免枚举

## 3. 主流程

```
会话建立
  │
  ├─> 0. 身份认证（账号 + 角色）→ 失败则终止
  │
用户提问
  │
  ├─> 1. 会话记录（追加到上下文）
  │
  ├─> 2. 意图识别
  │      ├─ 闲聊/不支持 → 直接回复，结束
  │      └─ 问数 → 继续
  │
  ├─> 3. 权限预检（主体 + 客体）
  │      ├─ 个体级查询且无权限 → 统一话术「不存在或无权」+ 审计，结束
  │      ├─ 目标不存在 → 同一话术 + 审计，结束
  │      └─ 通过 → 继续
  │
  ├─> 4. 槽位检查（时间范围、指标是否明确）
  │      └─ 缺失 → 澄清反问，等待用户补充
  │
  ├─> 5. 上下文组装
  │      表/字段描述 + 指标口径 + 同义词 + 相关历史轮次 + few-shot
  │
  ├─> 6. 生成 SQL
  │
  ├─> 7. SQL 安全与客体校验
  │      ├─ 非只读/越界/含禁用字段 → 拒绝并说明原因（或触发一次重写）
  │      └─ 通过 → 继续
  │
  ├─> 8. 执行
  │      ├─ 报错 → 自修复（最多 2 次），仍失败 → 返回可读错误
  │      └─ 成功 → 继续
  │
  ├─> 9. 空结果判断
  │      └─ 疑似 SQL 问题 → 自修复一次；否则如实告知"无数据"
  │
  ├─> 10. 溯源记录
  │      记录 SQL、访问的表/字段、行数、耗时、修复次数
  │
  ├─> 11. 隐私脱敏
  │      在结果进入 LLM 与展示之前完成 PII 遮蔽
  │
  ├─> 12. 图表选型
  │      按结果形态选择：指标卡 / 折线 / 柱状 / 饼图 / 表格
  │
  ├─> 13. 生成自然语言摘要（只复述结果集中的数字）
  │
  └─> 14. 返回答案：SQL + 表格 + 图表 + 摘要 + 数据来源
```

**状态机**：一轮对话内部有五个可中断点——认证失败、权限拒绝、澄清（等用户输入）、安全拒绝、自修复耗尽、隐私拦截。全部是一等公民，不是异常分支。

## 4. 模块职责与接口

| 模块 | 职责 | 输入 | 输出 | 失败策略 |
|---|---|---|---|---|
| `ui/login` | 登录与身份选择 | 账号密码 | `Principal` | 显示登录失败 |
| `ui/chat` | 展示对话、接收输入 | 用户输入 | `ChatRequest` | 显示错误横幅 |
| `core/session` | 保存多轮上下文、澄清状态 | `ChatRequest` | `SessionContext` | 新建会话 |
| `core/intent` | 判断问数/闲聊/不支持，抽取实体 | 问题 + 会话 | `IntentResult` | 降级为"问数" |
| `guard/auth` | 身份认证、角色与权限判定 | `Principal` + `IntentResult` + SQL | 允许/拒绝 | **默认拒绝** |
| `core/context` | 拼接 schema、口径、历史、few-shot | `IntentResult` + 元数据 | `PromptContext` | 截断超长上下文 |
| `core/nl2sql` | 调用 LLM 生成 SQL | `PromptContext` | `SQLPlan` | 返回空计划，走澄清 |
| `guard/sql_guard` | 只读校验、表白名单、危险关键字、禁用字段 | `SQLPlan` | 校验结果 | 拒绝并说明 |
| `data/executor` | 执行查询，超时/行数限制 | SQL | `ExecutionResult` | 返回结构化错误 |
| `guard/privacy` | PII 识别与脱敏 | `ExecutionResult` | 脱敏后的 `ExecutionResult` | 默认遮蔽 |
| `infra/provenance` | 记录来源与 SQL，可复现 | 全流程事件 | `ProvenanceRecord` | 不影响主流程 |
| `infra/audit` | 权限事件审计 | 权限事件 | `AuditRecord` | 不影响主流程 |
| `core/repair` | 用错误信息重写 SQL | SQL + 错误 + 问题 | 新 `SQLPlan` | 超过次数即放弃 |
| `core/chart` | 按结果形态选图并生成配置 | `ExecutionResult` | `ChartSpec` | 降级为表格 |
| `core/summary` | 生成自然语言结论 | 问题 + 结果 + 口径 | 文本摘要 | 省略摘要 |
| `data/schema` | 抽取表/字段/外键与示例值 | 连接 | `SchemaMeta` | 启动时失败即中止 |
| `data/semantic` | 指标口径、同义词、时间规则 | 配置文件 | `SemanticMeta` | 缺失项记录警告 |
| `data/connection` | 只读数据库连接 | 配置 | 连接 | 启动时报错 |
| `llm/client` | 统一模型调用、重试、超时、计费统计 | 提示词 | 文本/JSON | 指数退避重试 |
| `infra/logging` | 日志 | 全流程事件 | 日志文件 | 忽略 |
| `eval/runner` | 批量跑验收集、统计准确率 | 问题集 | 报告 | 记录失败用例 |

**契约原则**：
- 每个模块的失败都表现为契约字段（`error` / `missing_slots` / `AuthDecision`），而不是抛异常穿透到 UI
- 摘要生成只能使用 `ExecutionResult` 中的值（脱敏后）
- `ChatAnswer` 必须携带 `sql` 与 `sources`
- 拒绝路径与"不存在"路径返回同一 `uniform_message`

## 7. 提示词架构

提示词分四层，按顺序拼接：

| 层 | 内容 | 量级 |
|---|---|---|
| 1. 角色与规则 | 你是数据分析师；只输出 JSON；只读；必须使用给定 schema；不得编造数据 | 短，固定 |
| 2. 数据上下文 | 相关表的结构、字段描述、示例值、表关系 | 中，按问题筛选 |
| 3. 口径与示例 | 指标定义、同义词、3～5 条 few-shot | 中，固定 |
| 4. 本轮问题 | 用户问题 + 必要的会话历史 | 短 |

### 各提示词的职责

- **intent.md**：做分类、范围（聚合/个体）判定和实体抽取，不生成 SQL。
- **nl2sql.md**：输入 PromptContext，输出 SQLPlan（严格 JSON）。
- **repair.md**：输入原问题、错误 SQL、数据库报错、schema，输出修正后的 SQLPlan。
- **summary.md**：输入问题、结果（已脱敏）、口径，输出 1～3 句结论；**只能复述结果中的数字，禁止编造或推算**。

### 关键约束

- SQL 必须在给定 schema 内，不得自造表名/字段名。
- 时间字段必须显式选择（order_date 或 pay_date），并在 explanation 中说明。
- 输出必须是可解析 JSON；解析失败时降级重试一次。
- 摘要中每个数字必须能在结果集中找到。
- 个体级问题不得进入 NL2SQL；权限预检在 LLM 之前拦截。

## 8. 语义层

语义层是"人话 ↔ 数据库"的翻译表，独立于代码，用 YAML 维护。

### tables.yaml（结构示意）

- 表名、人话名称、一行代表什么
- 字段：物理名、中文名、类型、是否度量、同义词、示例值、**是否 PII**
- 表关系：from、to、on、基数

### metrics.yaml（结构示意）

- 指标名、同义词、口径描述、计算逻辑、默认时间字段
- 例：`GMV`：有效订单的 pay_amount 之和，默认 order_date

### 时间规则

- "上个月" = 上一个自然月
- "本月" = 当前自然月
- "最近 N 天" = 含今天往前推 N 天
- 同环比一律按自然月计算

## 9. 隐私与脱敏

### PII 登记

在 `config/privacy.yaml` 中登记每类 PII 字段及脱敏规则：

| 字段类型 | 示例字段 | 脱敏规则 |
|---|---|---|
| 姓名 | customer_name | 保留首字，其余 `*` |
| 手机号 | phone | 保留前 3 后 4 |
| 邮箱 | email | 保留首字符与域名 |
| 详细地址 | address | 保留到省市，详细部分遮蔽 |
| 生日 | birth_date | 转为年龄段 |
| 客户编号 | customer_id | 默认不展示；需要展示时哈希化 |

### 脱敏时机

```
数据库 → 执行器 → 【脱敏】→ 图表 / 摘要 / LLM / 日志 / UI
```

- **必须早于 LLM**：模型上下文里不能出现原始 PII
- **必须早于日志**：日志中记录脱敏后的值
- 聚合结果（如"各省销售额"）不涉及 PII，无需处理

### 个体级查询策略：默认拒绝

- **默认只允许聚合查询**；涉及具体客户/账号的查询一律拒绝
- 仅当请求者具备权限（customer 查本人 / admin 查明细）时才可执行
- 授权后的明细仍需脱敏展示
- 需要精确匹配客户时，原始姓名只用于数据层内部过滤，**不得进入 LLM 上下文或日志**
- 小样本聚合防护：分组计数 < K（建议 K=5）时合并或隐藏，避免反推个体（可选）

## 10. 鉴权与审计

### 身份与角色

- 会话建立时认证，绑定 `Principal { user_id, role, customer_id }`
- 应用账号独立于业务库，密码哈希存储，会话有有效期
- customer 角色的账号绑定 `customer_id`

| 角色 | 聚合查询 | 个体明细 | 说明 |
|---|---|---|---|
| analyst 分析师 | 允许 | 拒绝 | 只能看统计 |
| customer 客户 | 允许 | 仅本人 | 结果仍脱敏 |
| admin 管理员 | 允许 | 允许 | 展示仍脱敏，全程审计 |

### 两级校验（默认拒绝）

1. **主体预检**（意图识别后、NL2SQL 前）：判断是聚合还是个体系查询，无权限直接拒绝
2. **客体校验**（SQL 生成后、执行前）：表白名单、禁选字段、只读校验

### 统一拒绝，防枚举

- 「存在但无权」与「不存在」返回同一话术、同一结构
- 拒绝路径**不查库**，避免响应时间差异暴露账号是否存在
- 统一话术：「该用户不存在，或您无权查询该用户的记录。」

### 审计

权限相关行为必须留痕：

| 字段 | 说明 |
|---|---|
| timestamp | 时间 |
| principal_id / role | 请求者账号与角色 |
| action | 登录 / 查询 / 拒绝 / SQL 拦截 |
| question_masked | 问题文本（姓名先遮蔽） |
| target_subject_hash | 目标客户标识（哈希） |
| decision / reason | 允许或拒绝及原因码 |
| sql / row_count | 执行时记录 |

**审计日志不落原始 PII**。审计日志与溯源日志分开存储。

## 11. 溯源设计

每轮对话生成一条 `ProvenanceRecord`，落盘为 JSONL：

- 用户问题原话（若含 PII，先遮蔽）
- 生成的 SQL（完整）
- 访问的表与字段
- 结果行数、耗时
- 自修复次数与每次的错误
- 脱敏了哪些字段
- 最终答复摘要

**可复现性**：拿着 `sql` + `db` 文件即可重新执行并得到同样结果。

**展示**：UI 每条回答下提供"查看 SQL / 数据来源"展开区。

**与审计的区别**：溯源用于复现查询，审计用于追责权限行为；两者都不得落原始 PII。

## 12. 安全与容错

| 项 | 策略 |
|---|---|
| 数据库连接 | 只读账号 / 只读模式打开 |
| 表访问 | 白名单，仅允许业务表 |
| SQL 语句 | 禁止 INSERT/UPDATE/DELETE/DROP/ALTER/PRAGMA |
| 查询主体 | 个体级查询默认拒绝，按角色放行 |
| 结果规模 | 自动追加 LIMIT，最大行数上限 |
| 执行时长 | 超时中断 |
| 自修复 | 最多 2 次，每次必须带上错误信息与 schema |
| 空结果 | 先判断是否 SQL 问题，再答复用户 |
| 溯源 | 每轮记录问题、SQL、表字段、行数、耗时、修复次数 |
| 审计 | 权限事件记录账号、角色、行为、时间、决策 |
| PII 脱敏 | 进入 LLM 与展示前遮蔽；日志禁止落原始 PII |
| 个体明细 | 默认拒绝；授权后仍需脱敏 |
| 账号枚举 | 统一话术 + 拒绝路径不查库 |

## 13. 里程碑与验收

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **M0 数据就绪** | 建表、数据、schema 元数据、口径文档 | 手写 SQL 能回答验收集中的每一个问题 |
| **M1 单表问数** | 意图识别 + NL2SQL + 执行 + 表格 + 溯源 | 单表问题执行成功率 ≥ 90%；每轮日志含 SQL 与来源 |
| **M2 多表与口径** | join、时间口径、聚合 | 验收集答案正确；摘要数字均可回溯 |
| **M3 容错与呈现** | 自修复、空结果判断、图表选型、SQL 展示 | 构造错误 SQL 能自动修复；图表类型正确 |
| **M4 隐私、鉴权与审计** | 登录与角色、个体查询拦截、PII 脱敏、审计留痕 | 无权限个体查询被统一拒绝；存在/不存在返回一致；审计含账号、行为、时间；日志无原始 PII |
| **M5 多轮与打磨** | 上下文继承、澄清、README、演示 | 追问能继承条件；形成演示材料 |

**建议档位**：M0～M4 为必做（两条硬验收落在此），M5 视时间而定。

**贯穿所有阶段的硬标准**（每条验收都必须同时满足）：

1. 回答中的数字均可在本次 `ExecutionResult` 中找到；日志含 SQL 与来源
2. 客户信息不泄露；个体查询默认拒绝；日志与审计无原始 PII

## 14. 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| 口径歧义 | 答案"看起来对但不对" | 语义层 + 摘要中注明口径 |
| 时间字段选错 | 月度数据错位 | 提示词强制显式选择并说明 |
| join 漏条件 | 金额翻倍 | 元数据提供关系 + 结果行数异常提示 |
| 空结果误判 | 用户被误导 | 自动重试一次 + 如实说明 |
| LLM 输出非 JSON | 流程中断 | 严格 schema + 重试 + 降级 |
| 图表选错 | 展示效果差 | 按结果形态规则化选择，非自由发挥 |
| LLM 编造数字 | 答案不可信 | 摘要只允许复述结果集；来源可查 |
| **越权查询个体** | 数据泄露 | 默认拒绝 + 角色矩阵 + 客体校验 |
| **账号枚举** | 泄露客户是否存在 | 统一话术 + 拒绝路径不查库 |
| 脱敏破坏分析 | 数字对不上 | 脱敏只作用于展示字段，不影响聚合计算 |
| 小样本反推 | 聚合泄露个体 | 分组计数 < K 时合并或隐藏（可选） |
| 审计日志泄露 PII | 二次泄露 | 目标主体哈希、问题文本遮蔽 |
