## 1. 项目概述

### 1.1 背景

业务人员获取数据通常依赖数据分析师排期取数，链路长、响应慢。ChatBI 将"自然语言提问 → 自动生成 SQL → 查询数据库 → 可视化呈现"串成闭环，让非技术用户可以直接问数。

本项目在本地电商销售库上实现一个可运行、可演示的 ChatBI 原型，重点不在功能堆叠，而在**数据可信**与**隐私合规**两条底线。

### 1.2 项目目标

1. 用户以自然语言提问，系统生成 SQL、查询本地数据库，返回表格或图表，并附简要结论。
2. 每条回答都展示所用 SQL 与数据来源，可人工核对。
3. 查询出错时能自我修复，避免把数据库报错直接抛给用户。
4. 覆盖电商销售域的常见问题形态：单值、趋势、排名、占比、同环比、比率、下钻、明细。
5. 满足第 2.4 节两条硬验收标准。

### 1.3 建设原则

| 原则 | 含义 |
|---|---|
| **数据可信优先** | 宁可答"查不到"，不可编造数字 |
| **隐私默认拒绝** | 个体级查询默认拒绝，授权后才执行 |
| **全程可追溯** | 每个数字可回溯到 SQL；每次权限行为可审计 |
| **小步可验证** | 每个里程碑都有明确的验收标准 |
| **关注点分离** | 界面、编排、智能、数据、安全分层，接口契约先行 |

### 1.4 范围

**范围内**

- 单一 SQLite 数据库（电商销售域，5 张表）
- 单用户会话，支持多轮上下文（P1）
- 聚合分析与授权范围内的明细查询
- 本地部署，单机运行
- SQL 生成、执行、自修复、可视化、摘要
- 登录鉴权、PII 脱敏、溯源与审计

**范围外**

- 生产级行级/列级权限体系
- 多数据源、跨库查询
- 大数据量性能优化（百万级以上）
- 移动端适配
- 语义层可视化配置界面
- 模型微调

### 1.5 术语

| 术语 | 说明 |
|---|---|
| ChatBI | 以自然语言交互完成取数与可视化的 BI 形态 |
| NL2SQL | 自然语言转 SQL |
| 聚合查询 | 结果不指向具体个人的统计查询，如"各省销售额" |
| 个体查询 | 指向具体客户/账号的查询，如"张三买了什么" |
| PII | 个人可识别信息（姓名、手机号、地址、生日等） |
| 溯源 | 记录一次查询的 SQL、来源、结果规模，用于复现 |
| 审计 | 记录权限相关行为（账号、角色、时间、决策），用于追责 |
| 统一拒绝 | 对"存在但无权"与"不存在"返回完全一致的答复，防止枚举 |
| 金标准 | 人工确认正确的 SQL 与期望结果，作为评测基线 |

## 2. 需求

### 2.1 用户角色

| 角色 | 标识 | 权限概述 |
|---|---|---|
| 分析师 | `analyst` | 仅聚合查询；不得查询个体 |
| 客户 | `customer` | 聚合查询 + 仅本人数据；结果脱敏 |
| 管理员 | `admin` | 聚合 + 个体明细；展示仍脱敏，全程审计 |

### 2.2 功能需求

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| FR-01 | 登录与身份绑定 | 账号密码认证，会话绑定 `Principal` | P0（M4） |
| FR-02 | 自然语言问数 | 输入问题，返回数据结果 | P0 |
| FR-03 | NL2SQL | 基于 schema 与语义层生成 SQL | P0 |
| FR-04 | SQL 展示 | 每条回答可展开查看完整 SQL 与来源 | P0 |
| FR-05 | 查询执行 | 只读执行，超时与行数限制 | P0 |
| FR-06 | 结果呈现 | 表格 + 图表 + 自然语言摘要 | P0 |
| FR-07 | 错误自修复 | 执行报错时携带错误重写 SQL，最多 2 次 | P1 |
| FR-08 | 空结果处理 | 区分"无数据"与"SQL 错误" | P1 |
| FR-09 | 权限预检 | 意图识别后判断聚合/个体，无权限即拒绝 | P0 |
| FR-10 | 个体查询授权 | customer 查本人、admin 查明细；结果脱敏 | P0 |
| FR-11 | PII 脱敏 | 结果进入 LLM/展示/日志前遮蔽 | P0 |
| FR-12 | 溯源记录 | 每轮记录 SQL、表字段、行数、耗时 | P0 |
| FR-13 | 审计记录 | 权限事件记录账号、角色、行为、时间、决策 | P0 |
| FR-14 | 多轮上下文 | "那华东呢？"继承上一轮条件 | P1 |
| FR-15 | 澄清反问 | 缺时间范围等槽位时主动提问 | P1 |
| FR-16 | 图表自动选型 | 按结果形态选择指标卡/折线/柱状/饼图/表格 | P1 |
| FR-17 | 评测集运行 | 批量执行验收集并统计通过率 | P1 |

### 2.3 非功能需求

| 编号 | 需求 | 指标 |
|---|---|---|
| NFR-01 | 数据可信 | 回答中 100% 的数字可在本次查询结果中找到 |
| NFR-02 | 隐私合规 | 未授权个体查询 0 放行；日志与审计无原始 PII |
| NFR-03 | 可复现 | 凭 `ProvenanceRecord.sql` + 数据库文件可复现结果 |
| NFR-04 | 响应性能 | 不含 LLM 推理的单次查询 < 3 秒；端到端 < 30 秒 |
| NFR-05 | 安全 | 只读连接；非查询语句 100% 拦截 |
| NFR-06 | 可维护 | 提示词、口径、脱敏规则均为配置，不写死在代码 |
| NFR-07 | 可观测 | 结构化日志，可按 `turn_id` 串联一轮对话 |
| NFR-08 | 本地可运行 | 单机、单进程、无外部服务依赖（LLM API 除外） |

### 2.4 硬验收标准

功能可以少，以下两条不能破。

#### A. 数据不编造、全可追溯

- 回答中的一切数字必须来自本次数据库查询结果
- 摘要只允许复述结果集中的值，禁止推算未查询到的数字
- 每轮日志记录：问题、完整 SQL、访问的表与字段、结果行数、耗时、修复次数
- 查不到就答"查不到"，不得给出猜测值
- 日志足以复现整次查询

#### B. 隐私安全与鉴权

- **仅对姓名脱敏但返回其购买记录，仍构成隐私泄露**
- 默认只允许聚合查询；个体级查询默认拒绝
- 每次查询必须绑定请求者身份（账号 + 角色）
- 无权限或目标不存在，统一回复：「该用户不存在，或您无权查询该用户的记录。」
- 两种情况返回内容、结构、响应时间一致，防止账号枚举
- 授权范围内展示仍需脱敏
- 脱敏发生在结果进入 LLM 与展示之前
- 日志与审计不得落原始 PII
- 权限相关行为必须审计：账号、角色、行为、时间、目标主体（哈希）、决策

## 3. 数据设计

### 3.1 概念模型

```
customers ──1:N──> orders ──1:N──> order_items <──N:1── products
                      │
                      └──1:N──> refunds
```

### 3.2 表结构

#### 3.2.1 `customers` 客户表

| 字段 | 类型 | 约束 | 说明 | PII |
|---|---|---|---|---|
| customer_id | TEXT | PK | 客户编号 | 是 |
| customer_name | TEXT | NOT NULL | 姓名 | 是 |
| gender | TEXT | — | 性别 | 否 |
| birth_date | DATE | — | 生日 | 是 |
| province | TEXT | — | 省份 | 否 |
| city | TEXT | — | 城市 | 否 |
| register_date | DATE | NOT NULL | 注册日期 | 否 |
| member_level | TEXT | — | 普通/银卡/金卡/钻石 | 否 |

**教学点**：维度表；会员分层、新老客户、客户贡献分析。

#### 3.2.2 `products` 商品表

| 字段 | 类型 | 约束 | 说明 | PII |
|---|---|---|---|---|
| product_id | TEXT | PK | 商品编号 | 否 |
| product_name | TEXT | NOT NULL | 商品名 | 否 |
| category | TEXT | NOT NULL | 一级类目 | 否 |
| sub_category | TEXT | — | 二级类目 | 否 |
| brand | TEXT | — | 品牌 | 否 |
| list_price | REAL | ≥ 0 | 标价 | 否 |
| cost_price | REAL | ≥ 0 | 成本价 | 否 |

**教学点**：多级维度下钻；成本价支持毛利计算。

#### 3.2.3 `orders` 订单表

| 字段 | 类型 | 约束 | 说明 | PII |
|---|---|---|---|---|
| order_id | TEXT | PK | 订单号 | 否 |
| customer_id | TEXT | FK → customers | 客户编号 | 否 |
| order_date | DATETIME | NOT NULL | 下单时间 | 否 |
| pay_date | DATETIME | 可空 | 支付时间 | 否 |
| status | TEXT | NOT NULL | 待支付/已支付/已发货/已完成/已取消/已退款 | 否 |
| channel | TEXT | — | App/小程序/PC/线下 | 否 |
| shipping_province | TEXT | — | 收货省份 | 否 |
| pay_amount | REAL | ≥ 0 | 实付金额 | 否 |
| discount_amount | REAL | ≥ 0 | 优惠金额 | 否 |

**教学点**：两个时间字段制造时间口径问题；`status` 决定"销售额是否含取消订单"。

#### 3.2.4 `order_items` 订单明细表

| 字段 | 类型 | 约束 | 说明 | PII |
|---|---|---|---|---|
| item_id | TEXT | PK | 明细编号 | 否 |
| order_id | TEXT | FK → orders | 订单号 | 否 |
| product_id | TEXT | FK → products | 商品编号 | 否 |
| quantity | INTEGER | > 0 | 数量 | 否 |
| unit_price | REAL | ≥ 0 | 成交单价 | 否 |
| item_amount | REAL | ≥ 0 | 小计 | 否 |

**教学点**：拆解 orders ↔ products 的多对多；商品维度分析的必经表。

#### 3.2.5 `refunds` 退款表

| 字段 | 类型 | 约束 | 说明 | PII |
|---|---|---|---|---|
| refund_id | TEXT | PK | 退款编号 | 否 |
| order_id | TEXT | FK → orders | 订单号 | 否 |
| refund_date | DATETIME | NOT NULL | 退款时间 | 否 |
| refund_amount | REAL | ≥ 0 | 退款金额 | 否 |
| reason | TEXT | — | 退款原因 | 否 |

**教学点**：指标口径第二层（销售额是否减退款、退款率定义）。

#### 3.2.6 索引建议

| 表 | 索引 |
|---|---|
| orders | `(order_date)`、`(customer_id)`、`(status)` |
| order_items | `(order_id)`、`(product_id)` |
| refunds | `(order_id)`、`(refund_date)` |

### 3.3 指标口径

| 指标 | 定义 | 默认时间字段 |
|---|---|---|
| 有效订单 | `status ∈ {已支付, 已发货, 已完成}` | order_date |
| GMV / 销售额 | 有效订单的 `pay_amount` 之和（含退款） | order_date |
| 净销售额 | GMV − 退款金额 | order_date / refund_date |
| 客单价 | 销售额 ÷ 下单客户数 | order_date |
| 退款率 | 退款金额 ÷ GMV | order_date |
| 复购率 | 购买 ≥ 2 次的客户 ÷ 有购买记录的客户 | order_date |
| 毛利率 | (销售额 − 商品成本) ÷ 销售额 | order_date |
| 活跃客户数 | 有效订单的去重客户数 | order_date |

**默认约定**：问"销售额"一律指 GMV；只有问题涉及退款时才关联 `refunds`。

### 3.4 时间规则

| 表达 | 解析 |
|---|---|
| 上个月 | 上一个自然月 |
| 本月 | 当前自然月 |
| 最近 N 天 | 含今天往前推 N 天 |
| 今年 | 当前自然年 |
| 同比 | 与去年同期自然月比较 |
| 环比 | 与上一个自然月比较 |

时间字段选择规则：

- 销售、订单量、客单价 → `order_date`
- 支付相关 → `pay_date`
- 退款相关 → `refund_date`
- 生成 SQL 时必须显式选择并在 `explanation` 中说明

### 3.5 PII 字段登记

| 表.字段 | 类型 | 脱敏规则 |
|---|---|---|
| customers.customer_name | 姓名 | 保留首字，其余 `*` |
| customers.birth_date | 生日 | 转为年龄段（如 25-34） |
| customers.customer_id | 标识 | 默认不展示；必要时哈希化 |
| customers.phone（待定） | 手机号 | 保留前 3 后 4 |
| customers.email（待定） | 邮箱 | 保留首字符与域名 |
| customers.address（待定） | 地址 | 保留到省市，详细部分遮蔽 |

### 3.6 数据规模与特征

| 项 | 规模 | 说明 |
|---|---|---|
| 客户 | 1,000 | 覆盖 3 个会员等级 |
| 商品 | 200 | 8 个一级类目，每类 2～4 个子类目 |
| 订单 | 10,000 | 时间跨度 2 年 |
| 明细 | ~30,000 | 平均每单 3 件 |
| 退款 | ~500 | 退款率约 5% |

**数据真实性要求**（若允许生成数据）：

- 双 11、618 有明显峰值
- 金卡会员客单价更高、复购更频繁
- 不同品类存在季节性（服饰换季、食品平稳）
- 少数商品为爆款，销量集中
- 退款原因分布合理（质量问题、七天无理由、尺码不合适等）

### 3.7 数据来源约束（待决）

"不允许造数据"存在两种解释：

| 读法 | 含义 | 影响 |
|---|---|---|
| A | 仅约束系统回答不得编造，示例数据可用脚本生成 | 按本文档 3.6 执行 |
| B | 数据准备也不允许脚本生成，必须用真实数据源 | 需重新选择数据源并调整表结构 |

**当前设计按 A 读法编写。** 若采用 B 读法，第 3.2 节的表结构需按真实数据源重新映射。

## 4. 系统架构

### 4.1 分层架构

```
┌──────────────────────────────────────────────────────────────┐
│ 表现层  UI                                                    │
│   登录 · 对话输入 · 消息流 · 结果表格 · 图表 · SQL 展开        │
├──────────────────────────────────────────────────────────────┤
│ 应用层  Orchestrator                                          │
│   身份认证 · 权限校验 · 流程编排 · 澄清反问 · 审计记录         │
├──────────────────────────────────────────────────────────────┤
│ 智能层  Intelligence                                          │
│   意图识别 · 上下文组装 · NL2SQL · 自修复 · 图表选型 · 摘要    │
├──────────────────────────────────────────────────────────────┤
│ 数据层  Data                                                  │
│   只读连接 · Schema 元数据 · 语义层 · 安全校验 · 执行器        │
│   隐私脱敏 · 数据溯源                                          │
├──────────────────────────────────────────────────────────────┤
│ 基础设施  Infra                                               │
│   配置 · 日志 · 审计 · 错误模型 · 评测集                       │
└──────────────────────────────────────────────────────────────┘
```

**依赖规则**

- 上层依赖下层，下层不感知上层
- 智能层只拿已脱敏、已登记来源的数据，不直接连数据库
- 原始 PII 不离开数据层与安全层
- 每次查询先鉴权后执行；未授权查询不生成 SQL、不访问数据库

### 4.2 部署形态

| 项 | 设计 |
|---|---|
| 运行形态 | 单机单进程 |
| 界面 | Streamlit Web 应用 |
| 数据库 | 本地 SQLite 文件（只读连接） |
| 模型 | 通过 HTTPS 调用 LLM API（供应商待定） |
| 配置 | YAML 文件 |
| 日志 | 本地 JSONL 文件 |

### 4.3 主流程

```
会话建立
  │
  ├─> 0. 身份认证（账号 + 角色）→ 失败则终止
  │
用户提问
  │
  ├─> 1. 会话记录（追加到上下文）
  │
  ├─> 2. 意图识别
  │      ├─ 闲聊/不支持 → 直接回复，结束
  │      └─ 问数 → 继续
  │
  ├─> 3. 权限预检（主体 + 客体）
  │      ├─ 个体级查询且无权限 → 统一话术 + 审计，结束
  │      ├─ 目标不存在 → 同一话术 + 审计，结束
  │      └─ 通过 → 继续
  │
  ├─> 4. 槽位检查（时间范围、指标是否明确）
  │      └─ 缺失 → 澄清反问，等待用户补充
  │
  ├─> 5. 上下文组装
  │      表/字段描述 + 指标口径 + 同义词 + 相关历史轮次 + few-shot
  │
  ├─> 6. 生成 SQL
  │
  ├─> 7. SQL 安全与客体校验
  │      ├─ 非只读/越界/含禁用字段 → 拒绝并说明原因（或触发一次重写）
  │      └─ 通过 → 继续
  │
  ├─> 8. 执行
  │      ├─ 报错 → 自修复（最多 2 次），仍失败 → 返回可读错误
  │      └─ 成功 → 继续
  │
  ├─> 9. 空结果判断
  │      └─ 疑似 SQL 问题 → 自修复一次；否则如实告知"无数据"
  │
  ├─> 10. 溯源记录
  │      记录 SQL、访问的表/字段、行数、耗时、修复次数
  │
  ├─> 11. 隐私脱敏
  │      在结果进入 LLM 与展示之前完成 PII 遮蔽
  │
  ├─> 12. 图表选型
  │      按结果形态选择：指标卡 / 折线 / 柱状 / 饼图 / 表格
  │
  ├─> 13. 生成自然语言摘要（只复述结果集中的数字）
  │
  └─> 14. 返回答案：SQL + 表格 + 图表 + 摘要 + 数据来源
```

### 4.4 中断状态

一轮对话有六个可中断点，全部作为正常状态处理，不以异常穿透到 UI：

| 状态 | 触发 | 处理 |
|---|---|---|
| 认证失败 | 账号或密码错误 | 返回登录失败，不进入问数 |
| 权限拒绝 | 个体查询且无权限 | 统一话术 + 审计，不查库 |
| 目标不存在 | 主体查询无匹配 | 与权限拒绝同一话术 |
| 待澄清 | 缺槽位 | 保存 `pending_clarification`，等待补充 |
| 安全拒绝 | SQL 非只读/越界 | 说明原因；必要时重写一次 |
| 修复耗尽 | 连续 2 次执行失败 | 返回可读错误 + SQL + 报错摘要 |

## 6. 提示词设计

### 6.1 分层结构

| 层 | 内容 | 说明 |
|---|---|---|
| 1. 角色与规则 | 数据分析师；只输出 JSON；只读；必须使用给定 schema；不得编造 | 固定 |
| 2. 数据上下文 | 相关表结构、字段描述、示例值、表关系 | 按问题筛选 |
| 3. 口径与示例 | 指标定义、同义词、3～5 条 few-shot | 固定 |
| 4. 本轮问题 | 用户问题 + 必要历史 | 动态 |

### 6.2 各提示词职责

| 提示词 | 输入 | 输出 | 约束 |
|---|---|---|---|
| `intent.md` | 问题 + 会话摘要 | `IntentResult` JSON | 只分类与抽实体，不生成 SQL |
| `nl2sql.md` | `PromptContext` | `SQLPlan` JSON | 只用给定 schema；显式时间字段 |
| `repair.md` | 问题 + 错误 SQL + 报错 + schema | 新 `SQLPlan` | 只修正语法/字段错误，不改变业务意图 |
| `summary.md` | 问题 + 已脱敏结果 + 口径 | 1～3 句文本 | **只能复述结果中的数字** |

### 6.3 输出约束

- 所有结构化输出必须为合法 JSON
- `SQLPlan` 必须包含 `sql`、`explanation`、`time_field`
- 自修复不得改变问题的业务含义
- 摘要中不得出现结果集之外的数字
- 不得输出数据库连接信息、表名之外的系统信息

### 6.4 few-shot 选择

- 从金标准问答对中挑选 3～5 条，覆盖：时间过滤、分组聚合、多表 join、比率计算
- few-shot 中的客户姓名一律使用脱敏值或虚构占位符

## 8. 安全设计

### 8.1 权限模型

| 角色 | 聚合查询 | 个体明细 | 说明 |
|---|---|---|---|
| analyst | 允许 | 拒绝 | 只能看统计 |
| customer | 允许 | 仅本人 | 账号绑定 `customer_id`；结果脱敏 |
| admin | 允许 | 允许 | 展示仍脱敏；全程审计 |

**两级校验**

1. **主体预检**：意图识别后判断 `scope`；个体查询无权限直接拒绝，不进入 NL2SQL
2. **客体校验**：SQL 生成后校验表白名单、禁用字段、只读语法

**默认拒绝**：未明确匹配到允许规则的一律拒绝。

### 8.2 隐私与脱敏

**脱敏时机**

```
数据库 → 执行器 → 【脱敏】→ 图表 / 摘要 / LLM / 日志 / UI
```

- 必须早于 LLM：模型上下文中不得出现原始 PII
- 必须早于日志：日志记录脱敏后的值
- 聚合结果不涉及 PII，无需处理

**个体级查询策略**

- 默认只允许聚合查询
- 仅授权角色可执行个体查询，结果仍脱敏
- 精确匹配所需的原始姓名只在数据层内部使用，不进入 LLM 上下文或日志
- 小样本聚合防护（可选）：分组计数 < K（建议 5）时合并或隐藏，防止反推个体

**脱敏规则**

| 类型 | 规则 | 示例 |
|---|---|---|
| 姓名 | 保留首字，其余 `*` | 张三 → 张* |
| 手机号 | 保留前 3 后 4 | 13812341234 → 138****1234 |
| 邮箱 | 保留首字符与域名 | zhangsan@x.com → z***@x.com |
| 地址 | 保留到省市 | 浙江省杭州市西湖区xx路1号 → 浙江省杭州市 |
| 生日 | 转年龄段 | 1995-03-02 → 25-34 |
| 客户编号 | 哈希 | C000123 → sha256:... |

### 8.3 审计

权限相关行为必须留痕，写入独立审计文件（JSONL）：

| 字段 | 说明 |
|---|---|
| timestamp | 时间 |
| principal_id / role | 请求者账号与角色 |
| action | 登录 / 查询 / 拒绝 / SQL 拦截 |
| question_masked | 问题文本（姓名先遮蔽） |
| target_subject_hash | 目标客户标识（哈希） |
| decision / reason | 允许或拒绝及原因码 |
| sql / row_count | 执行时记录 |

**审计日志不落原始 PII。** 审计与溯源分开存储，互不替代。

### 8.4 溯源

每轮生成一条 `ProvenanceRecord`，落盘为 JSONL：

- 问题（含 PII 时先遮蔽）
- 完整 SQL
- 访问的表与字段
- 结果行数、耗时
- 自修复次数与每次错误
- 脱敏字段列表
- 最终摘要

**可复现性**：凭 `sql` + 数据库文件可重新执行并得到同样结果。

**展示**：UI 每条回答提供"查看 SQL / 数据来源"展开区。

### 8.5 SQL 安全

| 控制项 | 策略 |
|---|---|
| 连接 | 只读模式打开 SQLite；或使用只读账号 |
| 表白名单 | 仅允许 5 张业务表 |
| 语句类型 | 仅允许 SELECT；拦截 INSERT/UPDATE/DELETE/DROP/ALTER/PRAGMA/ATTACH |
| 多语句 | 禁止分号拼接多条语句 |
| 结果规模 | 自动追加 `LIMIT 1000` |
| 执行时长 | 5 秒超时中断 |
| 参数化 | 用户输入不得直接拼接进 SQL |
| 注入防护 | 提示词注入不得改变只读约束，由本地校验兜底 |

### 8.6 威胁与对策

| 威胁 | 后果 | 对策 |
|---|---|---|
| 未授权查询个体 | 隐私泄露 | 默认拒绝 + 角色矩阵 + 主体预检 |
| 账号枚举 | 泄露客户是否存在 | 统一话术 + 拒绝路径不查库 |
| 通过购买记录反推身份 | 隐私泄露 | 个体查询默认拒绝；明细脱敏 |
| 小样本聚合反推 | 间接泄露 | K 匿名（可选） |
| 提示词注入 | 越权/写操作 | 本地 SQL 校验优先于模型输出 |
| 日志泄露 PII | 二次泄露 | 脱敏前置于日志；审计哈希 |
| 模型编造数字 | 数据不可信 | 摘要只复述结果集；溯源可查 |
| SQL 误写导致数据翻倍 | 结论错误 | 关系元数据 + 行数异常提示 |

| 自修复成功率 | 修复后成功的次数 ÷ 触发修复次数 | ≥ 60% |

### 9.4 验收流程

1. 用测试账号分别以三种角色登录
2. 执行 9.1 正向用例，记录 SQL、结果与耗时
3. 执行 9.2 负向用例，重点检查拒绝话术一致性与日志脱敏
4. 抽查 `ProvenanceRecord`，用其中的 SQL 重跑并比对结果
5. 检查审计日志是否包含账号、行为、时间、决策
6. 检查日志文件中是否存在原始 PII

## 11. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 口径歧义 | 答案"看起来对但不对" | 语义层 + 摘要注明口径 |
| 时间字段选错 | 月度数据错位 | 提示词强制显式选择并说明 |
| join 漏条件 | 金额翻倍 | 关系元数据 + 行数异常提示 |
| 空结果误判 | 用户被误导 | 自动重试一次 + 如实说明 |
| LLM 输出非 JSON | 流程中断 | 严格 schema + 重试 + 降级 |
| 图表选错 | 展示效果差 | 按结果形态规则化选择 |
| 模型编造数字 | 数据不可信 | 摘要只复述结果集 |
| 越权查询个体 | 隐私泄露 | 默认拒绝 + 角色矩阵 |
| 账号枚举 | 泄露客户存在性 | 统一话术 + 拒绝路径不查库 |
| 小样本聚合反推 | 间接泄露 | K 匿名（可选） |
| 日志泄露 PII | 二次泄露 | 脱敏前置 + 审计哈希 |
| 造数边界未定 | 数据方案返工 | M0 前确认 A/B 读法 |
| 模型 SQL 能力不足 | 成功率低 | 选型时用金标准集做对比测试 |
