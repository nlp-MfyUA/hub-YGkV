## 1. 文档目的

本文档定义每个功能的**用户可见行为、处理规则、异常分支与验收标准**，回答"用户做什么、系统怎么响应、什么情况算完成"。

不涉及：

- 技术实现与类设计
- 数据结构与 SQL 细节
- 部署与运维

架构、数据模型、接口契约以《项目设计文档.md》为准。

## 3. 全局交互规则

### 3.1 默认规则

| 项 | 规则 |
|---|---|
| 时间缺失 | 反问澄清，不擅自默认 |
| "销售额" | 默认 GMV（有效订单的实付金额之和） |
| 时间字段 | 默认 `order_date`；涉及支付/退款时才切换 |
| 订单状态 | "销售额""订单量"默认只统计有效订单 |
| 排序 | 时间类默认升序；排名类默认降序 |
| 明细展示 | 界面最多展示 100 行，查询上限 1000 行 |
| 图表 | 按 4.11 的规则选择，不自由发挥 |
| 多轮继承 | 未明确覆盖的条件沿用上一轮 |
| 单位 | 元；摘要中超过 1 万可用"万元"，保留 2 位小数 |

### 3.2 数字与时间格式

| 类型 | 格式 | 示例 |
|---|---|---|
| 金额 | 千分位，2 位小数 | 1,234,567.89 |
| 数量 | 千分位，整数 | 12,345 |
| 百分比 | 1 位小数 | 8.2% |
| 空值 | 破折号 | — |
| 日期 | `YYYY-MM-DD` | 2026-10-01 |
| 月份 | `YYYY-MM` | 2026-10 |
| 时间范围 | 起止同时展示 | 2026-09-01 至 2026-09-30 |

**数字一致性**：摘要、表格、图表使用的数字必须来自同一份查询结果，不得二次换算产生差异；单位换算需在摘要中标注"约"。

### 3.3 统一文案

| 场景 | 文案 | 备注 |
|---|---|---|
| 登录失败 | 账号或密码错误。 | 不区分账号不存在与密码错误 |
| 权限拒绝 / 目标不存在 | **该用户不存在，或您无权查询该用户的记录。** | 两种情况完全一致 |
| 无数据 | 没有查询到符合条件的数据。 | 附 SQL 与时间范围 |
| 生成失败 | 暂时无法生成查询，请换一种问法。 | 不显示内部错误 |
| SQL 被拦截 | 该查询涉及不安全操作，已被拦截。 | 不执行、不回显危险语句 |
| 查询超时 | 查询超时，请缩小查询范围后重试。 | 附 SQL |
| 修复耗尽 | 查询执行失败，已尝试自动修复但未成功。 | 附 SQL 与错误摘要 |
| 空输入 | 请输入问题。 | 不发送 |
| 问题过长 | 问题过长，请精简到 200 字以内。 | 200 字上限 |
| 服务异常 | 服务暂时不可用，请稍后重试。 | LLM/网络故障 |
| 澄清 | 你想看哪个时间段？（本月 / 上月 / 近 30 天 / 自定义） | 一问一答 |

**文案原则**

- 不暴露数据库结构、报错堆栈、模型提示词
- 不确认客户是否存在
- 不出现"抱歉，我作为 AI"等无信息量表述
- 拒绝类文案不随场景变化，避免侧信道

### 3.4 会话规则

| 项 | 规则 |
|---|---|
| 会话有效期 | 登录后 8 小时 |
| 空闲超时 | 30 分钟无操作需重新登录 |
| 历史窗口 | 保留 10 轮；送入模型的为最近 5 轮 |
| 新建会话 | 侧栏"新对话"清空上下文，不退出登录 |
| 待澄清状态 | 只保留最近一次；用户提出新问题则丢弃 |
| 并发 | 同一会话同时只处理一个请求，处理中输入框禁用 |
| 重复提交 | 相同问题在 3 秒内重复提交视为一次 |

### 3.5 消息卡片结构

每条助手回答包含：

```
┌──────────────────────────────────────────────┐
│ 摘要（1～3 句）                               │
│ ┌──────────────────────────────────────────┐ │
│ │ 图表 / 指标卡                             │ │
│ └──────────────────────────────────────────┘ │
│ ┌──────────────────────────────────────────┐ │
│ │ 结果表格                                  │ │
│ └──────────────────────────────────────────┘ │
│ 口径说明：销售额按 GMV 统计，时间按下单日期    │
│ ▸ 查看 SQL 与数据来源                         │
└──────────────────────────────────────────────┘
```

## 4. 功能详细设计

### F-01 登录与身份绑定

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 里程碑 | M4 |
| 关联 | FR-01 |

**用户故事**

作为用户，我需要登录后使用系统，系统据此判断我能查询什么。

**前置条件**：系统已初始化账号。

**主流程**

1. 用户打开应用，未登录时展示登录页。
2. 输入账号与密码，点击登录。
3. 系统校验凭据。
4. 校验通过：建立会话，绑定 `Principal { user_id, role, customer_id }`，进入主页面。
5. 页面顶栏展示用户名与角色。
6. customer 角色在侧栏提示"仅可查询本人数据"；analyst 提示"仅支持聚合查询"。

**分支与异常**

| 情况 | 处理 |
|---|---|
| 账号不存在 | 返回"账号或密码错误。" |
| 密码错误 | 返回"账号或密码错误。" |
| 连续失败 5 次 | 锁定 5 分钟，提示"尝试次数过多，请稍后再试。" |
| 会话过期 | 跳转登录页，提示"登录已过期，请重新登录。" |
| 已登录重复访问登录页 | 直接进入主页面 |

**业务规则**

- 账号独立于业务数据库，不复用 `customers` 表
- 密码哈希存储，不记录明文
- 登录成功与失败均写审计

**验收标准**

- 正确凭据可进入主页面，顶栏显示角色
- 错误账号与错误密码提示完全一致
- 未登录无法访问问数功能

### F-02 发起问数

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 里程碑 | M1 |
| 关联 | FR-02 |

**用户故事**

作为用户，我输入一个业务问题，希望得到数据答案。

**前置条件**：已登录。

**主流程**

1. 用户在输入框输入问题。
2. 按 Enter 或点击"发送"。
3. 用户消息进入消息流。
4. 系统显示加载状态（"正在理解问题…"）。
5. 进入 F-03 意图识别。

**分支与异常**

| 情况 | 处理 |
|---|---|
| 空输入或仅空白 | 不发送，提示"请输入问题。" |
| 超过 200 字 | 不发送，提示"问题过长，请精简到 200 字以内。" |
| 正在处理中 | 输入框禁用；不接收新消息 |
| 网络/服务异常 | 展示 F-03 之后的统一错误文案 |
| 用户点击"停止" | 中断当前请求，保留已输入内容 |

**业务规则**

- 一次只处理一个问题
- 问题原文写入会话与溯源（含 PII 时先遮蔽）
- 用户消息与助手消息成对展示，失败时也保留用户消息

**验收标准**

- 空输入不产生请求
- 处理中无法重复提交
- 每条用户消息都有对应的助手响应或错误状态

### F-03 意图识别

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 里程碑 | M1 |
| 关联 | FR-02、FR-09 |

**用户故事**

作为系统，我需要判断用户是在问数、闲聊还是提出无法支持的需求，并识别查询范围。

**输入**：问题文本 + 会话上下文。

**输出**：`IntentResult`

| 字段 | 说明 |
|---|---|
| type | `query` / `chitchat` / `unsupported` |
| scope | `aggregate` / `individual` |
| subject | 个体查询的目标（名称或编号，哈希后传递） |
| entities | 指标、维度、筛选条件、时间范围 |
| missing_slots | 缺失的必填槽位 |

**识别规则**

| type | 判定 |
|---|---|
| `query` | 涉及数据统计、明细、趋势、排名等 |
| `chitchat` | 问候、询问系统能力、感谢 |
| `unsupported` | 预测未来、外部数据、实时行情、修改数据 |

| scope | 判定 |
|---|---|
| `individual` | 指向具体客户：姓名、客户编号、"某客户""这个客户""他的/她的"；customer 角色下的"我的" |
| `aggregate` | 结果不指向具体个人，如分组统计、排名、占比 |

**处理规则**

- `chitchat`：返回能力说明与示例问题，结束本轮
- `unsupported`：说明不支持的原因，并给出可替代的问法建议
- 置信度低或类型不明确：按 `query` 处理（宁可进入澄清，不轻易拒绝）
- 意图识别不生成 SQL
- 识别到 PII（姓名、手机号等）时，原文只在内存中使用，不写入日志与模型上下文

**分支与异常**

| 情况 | 处理 |
|---|---|
| 模型输出非法 JSON | 重试 1 次；仍失败则按 `query` 处理，槽位置空 |
| 模型不可用 | 返回"服务暂时不可用，请稍后重试。" |
| 无法识别指标 | 进入澄清，反问"你想查询哪个指标？" |

**验收标准**

- "你好" → chitchat，不触发查询
- "预测下个月销售额" → unsupported，不编造数据
- "客户张三买了什么" → query + individual
- "各省份销售额" → query + aggregate

### F-04 澄清反问

| 项 | 内容 |
|---|---|
| 优先级 | P1 |
| 里程碑 | M1 |
| 关联 | FR-15 |

**用户故事**

作为用户，我的问题缺少必要信息时，希望系统主动问清楚，而不是猜。

**触发条件**

| 缺失项 | 示例问题 | 反问 |
|---|---|---|
| 时间范围 | "销售额是多少？" | "你想看哪个时间段？" |
| 指标 | "卖得怎么样？" | "你想看销售额、订单量，还是客单价？" |
| 对比对象 | "增长了多少？" | "和哪个时间段对比？" |
| 分组维度 | "占比是多少？" | "按什么维度看占比？" |

**主流程**

1. 意图识别发现 `missing_slots` 非空。
2. 系统生成一个澄清问题，附快捷选项。
3. 保存 `pending_clarification`，等待用户。
4. 用户选择或输入补充信息。
5. 合并原问题与补充信息，重新进入意图识别。

**业务规则**

- 每轮最多提 1 个澄清问题
- 连续澄清最多 2 次；第 3 次仍缺信息时，采用默认值并在答复中注明假设
- 用户回答"随便/都行/你看着办" → 采用默认（时间默认本月）
- 用户提出新问题 → 丢弃待澄清状态，按新问题处理
- 快捷选项：本月 / 上月 / 近 30 天 / 自定义
- 澄清问题不计入"已回答"的轮次

**分支与异常**

| 情况 | 处理 |
|---|---|
| 用户补充仍不完整 | 进入第 2 次澄清或采用默认 |
| 用户取消 | 清除待澄清状态，回到空闲 |
| 会话超时 | 清除待澄清状态 |

**验收标准**

- "销售额是多少"触发时间澄清
- 选择"上月"后正确生成本月/上月区间
- 新问题不会错误继承上一个待澄清状态

### F-05 权限预检

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 里程碑 | M1 基础 / M4 完整 |
| 关联 | FR-09 |

**用户故事**

作为系统，我必须在生成 SQL 之前判断当前用户能否查询这个问题。

**触发时机**：意图识别之后、上下文组装与 NL2SQL 之前。

**判定矩阵**

| scope | analyst | customer | admin |
|---|---|---|---|
| aggregate | 允许 | 允许 | 允许 |
| individual（本人） | 拒绝 | 允许 | 允许 |
| individual（他人） | 拒绝 | 拒绝 | 允许 |

**主流程**

1. 读取 `Principal` 与 `IntentResult`。
2. scope 为 aggregate → 放行。
3. scope 为 individual：
   - analyst → 拒绝
   - customer → 判断 subject 是否等于本人 `customer_id`；是则放行，否则拒绝
   - admin → 放行
4. 拒绝时：
   - 返回统一文案
   - 写审计（`query_denied`）
   - 不生成 SQL、不访问数据库、不调用 NL2SQL
5. 放行时继续 F-04 / F-06。

**业务规则**

- **默认拒绝**：未明确命中的规则一律拒绝
- 拒绝与目标不存在使用同一文案、同一结构
- 拒绝路径不查库，避免通过响应时间判断客户是否存在
- 姓名匹配必须唯一；同名多个或无法确认时，按"不存在或无权"处理
- 个体查询的 subject 以哈希形式传递，原文不进入模型上下文

**分支与异常**

| 情况 | 处理 |
|---|---|
| scope 识别错误（聚合被误判为个体） | 拒绝；提示可改用聚合问法，不暴露具体原因 |
| subject 缺失 | 拒绝 |
| 权限配置缺失 | 拒绝（fail closed） |

**验收标准**

- analyst 问个体 → 统一拒绝，无 SQL
- customer 问本人 → 放行
- customer 问他人 → 统一拒绝
- admin 问个体 → 放行
- 存在与不存在的目标返回一致

### F-06 SQL 生成

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 里程碑 | M1 |
| 关联 | FR-03 |

**用户故事**

作为系统，我需要把用户问题转换成可执行的只读 SQL。

**输入**：`PromptContext`（相关表结构、字段描述、指标口径、few-shot、问题与必要历史）

**输出**：`SQLPlan { sql, explanation, confidence, metric_used, time_field }`

**生成规则**

| 规则 | 说明 |
|---|---|
| 仅使用给定 schema | 不得自造表名、字段名 |
| 仅生成 SELECT | 不生成写操作 |
| 显式时间字段 | 必须说明使用 `order_date` 还是 `pay_date` |
| 有效订单 | 销售额、订单量默认加状态过滤 |
| 表关系 | 多表必须按元数据给定的外键连接 |
| 聚合别名 | 中文或英文别名，稳定可读 |
| 行数限制 | 自动追加 `LIMIT 1000` |
| PII 字段 | 聚合查询不得 SELECT 姓名等字段；仅可用于 COUNT DISTINCT |
| 不使用用户输入拼接 | 值作为参数或经过转义 |

**分支与异常**

| 情况 | 处理 |
|---|---|
| 输出非 JSON | 重试 1 次；仍失败 → "暂时无法生成查询，请换一种问法。" |
| SQL 为空 | 进入澄清或返回生成失败 |
| confidence 过低 | 仍继续生成，但摘要中注明口径与假设 |
| 引用了不存在的表/字段 | 交给 F-07 校验拦截 |

**业务规则**

- 生成失败不展示模型原文
- SQL 与解释同时保存，供展示与溯源
- 模型调用记录 token 用量与耗时（不进入用户界面）

**验收标准**

- 单表问题生成可执行 SQL
- 多表问题按外键正确 join
- 时间字段与问题语义一致
- 生成内容不含写操作

### F-07 SQL 安全校验

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 里程碑 | M1 |
| 关联 | NFR-05 |

**用户故事**

作为系统，我必须保证任何进入数据库的语句都是只读、在允许范围内的。

**校验项**

| 类别 | 规则 | 处理 |
|---|---|---|
| 语句类型 | 仅允许 SELECT / WITH | 拦截 |
| 危险关键字 | INSERT、UPDATE、DELETE、DROP、ALTER、PRAGMA、ATTACH、VACUUM | 拦截 |
| 多语句 | 出现分号拼接 | 拦截 |
| 表白名单 | 仅 5 张业务表 | 拦截 |
| 禁用字段 | 按角色禁止 SELECT 的 PII 字段 | 拦截 |
| 结果规模 | 无 LIMIT 时自动追加 | 修正 |
| 注释注入 | 检测 `--`、`/* */` 异常使用 | 拦截或剥离 |

**主流程**

1. 对 `SQLPlan.sql` 做词法与结构校验。
2. 通过 → 进入 F-08。
3. 不通过 → 触发一次重写（携带拒绝原因），重写后再次校验。
4. 仍不通过 → 返回"该查询涉及不安全操作，已被拦截。"，写审计 `sql_blocked`。

**业务规则**

- 校验以本地规则为准，不信任模型输出
- 重写不得改变业务意图
- 被拦截的 SQL 不执行、不在界面回显
- 白名单在配置中维护，新增表需显式登记

**验收标准**

- `DROP TABLE orders` 被拦截
- 两条语句拼接被拦截
- 访问白名单外的表被拦截
- 未加 LIMIT 的查询被自动加上限制

### F-09 错误自修复

| 项 | 内容 |
|---|---|
| 优先级 | P1 |
| 里程碑 | M3 |
| 关联 | FR-07 |

**用户故事**

作为用户，我希望系统能自己纠正 SQL 错误，而不是把报错扔给我。

**触发条件**：F-08 返回执行错误或超时。

**主流程**

1. 记录原始 SQL、错误信息、错误类型。
2. 调用修复提示词：问题 + 失败 SQL + 错误 + schema。
3. 得到新 `SQLPlan`。
4. 重新经过 F-07 校验。
5. 校验通过 → 再次执行。
6. 成功 → 标注"已自动修复 1 次"，继续 F-10。
7. 失败 → 重复，最多 2 次。
8. 超过 2 次 → 返回修复耗尽文案 + SQL + 错误摘要。

**业务规则**

- 修复只针对技术错误，不得改变业务意图（如偷偷改时间范围）

- 修复后的 SQL 同样展示给用户
- 超时类错误修复时，优先建议缩小时间范围或增加过滤
- 用户可点击"重试"发起新一轮，而不是无限自动重试

**分支与异常**

| 情况 | 处理 |
|---|---|
| 修复后仍是同类错误 | 继续计次 |
| 修复后触发安全拦截 | 放弃修复，按拦截处理 |
| 模型不可用 | 直接返回原始错误摘要 |

**验收标准**

- 字段拼写错误可自动修复
- 语法错误可自动修复
- 修复次数超过上限后停止并提示
- 修复记录可在溯源中查看

### F-10 空结果处理

| 项 | 内容 |
|---|---|
| 优先级 | P1 |
| 里程碑 | M3 |
| 关联 | FR-08 |

**用户故事**

作为用户，查询没有结果时，我希望知道是"确实没有数据"还是"条件写错了"。

**触发条件**：执行成功但 `row_count = 0`。

**主流程**

1. 判断 SQL 是否存在明显过严条件（时间范围、过滤值）。
2. 允许一次自动修复：提示模型检查过滤条件，但不允许修改用户明确指定的条件。

   - 提示"可能是筛选条件下没有匹配记录"

- 不得用其他区间的数据"顶替"

- 不把空结果解释为"销售额为 0"，除非聚合查询确实返回 0

**验收标准**

- 无匹配数据时明确提示无数据
- 条件过严时可自动放宽（仅限非用户显式条件）
- 任何情况下不出现编造数值


**业务规则**

- 评测使用独立的测试会话，不污染真实会话
- 负向用例必须 100% 通过
- 报告可输出到文件，供作业报告引用

**验收标准**

- 一条命令跑完全部用例
- 报告包含各项指标与失败明细

## 6. 功能状态机

### 6.1 会话级

```
未登录 ──登录成功──> 已登录空闲
   ^                    │
   │                    ├──空闲超时 30 分钟──> 未登录
   └──退出/过期──────────┘
```

### 6.2 单轮问答

```
空闲
  │ 提交问题
  ▼
理解中 ──chitchat/unsupported──> 已回复 ──> 空闲
  │
  ├──需要澄清──> 待澄清 ──用户补充──> 理解中
  │                 └──新问题──> 理解中（丢弃待澄清）
  ▼
鉴权中 ──拒绝──> 已拒绝（统一文案 + 审计）──> 空闲
  ▼
生成中 ──失败──> 生成失败 ──> 空闲
  ▼
校验中 ──拦截──> 已拦截（审计）──> 空闲
  ▼
执行中 ──错误/超时──> 修复中 ──成功──> 呈现中
  │                        └──耗尽──> 执行失败 ──> 空闲
  ├──0 行──> 空结果处理 ──> 呈现中 / 无数据
  ▼
呈现中 ──> 空闲
```

### 6.3 状态与用户可见反馈

| 状态 | 反馈 |
|---|---|
| 理解中 | 正在理解问题… |
| 待澄清 | 澄清问题 + 快捷选项 |
| 鉴权中 | 正在校验权限… |
| 生成中 | 正在生成查询… |
| 校验中 | 正在检查查询安全性… |
| 执行中 | 正在查询数据… |
| 修复中 | 查询失败，正在尝试自动修复（第 N 次）… |
| 呈现中 | 正在整理结果… |
| 已拒绝 | 统一拒绝文案 |
| 无数据 | 无数据文案 |
| 执行失败 | 失败文案 + SQL + 错误摘要 |
