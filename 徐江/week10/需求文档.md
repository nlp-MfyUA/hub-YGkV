## 1. 项目背景与目标

随着多语言内容处理需求日益增长，需要一个「输入任意语言文本 → 自动识别语种 → 按规则翻译」的智能工具。本项目基于 **OpenAI Agents 架构**（OpenAI 官方 Agents SDK）与 **MCP（Model Context Protocol）** 协议实现该应用：

- **目标 1（需求一）**：用户输入一段文本，系统判断其语种，并按规则翻译——**中文翻译为英文，其他语言翻译为中文**，最终输出规定格式的 JSON。
- **目标 2（需求二）**：基于课程已有的「2-兼容OpenAI-Agent」MCP 基线代码，**新增 3 个翻译类 MCP 工具**（由大模型设计生成），并通过 Agent 调用这些工具。

## 2. 术语与缩略语

| 术语 | 说明 |
| --- | --- |
| Agent | OpenAI Agents SDK 中的智能体，由 instructions + model + tools/mcp_servers 构成 |
| MCP | Model Context Protocol，模型上下文协议，本文通过官方 Python SDK（mcp 2.x）实现 |
| Runner | OpenAI Agents SDK 中驱动 Agent 执行的运行时 |
| stdio | MCP Server 的标准输入输出通信方式（客户端以子进程拉起 Server） |
| ISO 639-1 | 两位语言代码标准，如 `zh`（中文）、`en`（英语）、`ja`（日语） |

## 4. 功能需求详述

### 4.1 需求一：语种检测与智能翻译应用（双 Agent）

#### 4.1.1 用户故事

> 作为用户，我希望输入任意语言的一段文本，系统能告诉我这是什么语言，并把它翻译成中文（英文输入时）或英文（中文输入时），并以结构化 JSON 返回结果。

#### 4.1.2 处理流程

```
用户输入文本
    │
    ▼
┌─────────────────────┐
│ Agent 1             │  调用 MCP 工具 detect_language
│ LanguageDetector    │ ─────────────────────────────▶  {"language": "ja",
│ (语种检测专家)       │                                "language_name": "日语"}
└─────────┬───────────┘
          │ 语种判定结果
          ▼
    路由规则判断
    ├─ 源语言 == 中文(zh)  → 目标语言 = 英文(en)
    └─ 源语言 == 其他语言  → 目标语言 = 中文(zh)
          │
          ▼
┌─────────────────────┐
│ Agent 2             │  调用 MCP 工具 translate_text
│ Translator          │ ─────────────────────────────▶  {"translated_text": "..."}
│ (翻译专家)           │
└─────────┬───────────┘
          │
          ▼
   组装输出 JSON
```

#### 4.1.3 Agent 设计

| Agent | 名称 | 职责 | 使用能力 | 输出约定 |
| --- | --- | --- | --- | --- |
| Agent 1 | `LanguageDetector`（语种检测专家） | 判断用户输入文本的语种 | MCP 工具 `detect_language` | 只输出 JSON：`{"language": "<ISO代码>", "language_name": "<中文语言名>"}` |
| Agent 2 | `Translator`（翻译专家） | 按路由规则翻译文本：**中文 → 英文，其他语言 → 中文** | MCP 工具 `translate_text` | 只输出译文本身，不带任何解释、引号或 JSON |

> 说明：两个 Agent 均通过 `mcp_servers` 参数挂载同一个 MCP Server，由 OpenAI Agents SDK 自动完成「工具发现 → 参数填充 → 调用 → 结果回传」的闭环。主程序采用**顺序编排**（先检测、后翻译）而非 handoff，以保证路由规则确定性，流程清晰可预期。

#### 4.1.4 输出格式规范

最终输出必须是且仅是一个包含 3 个字段的 JSON 对象：

| 字段 | 类型 | 含义 | 示例 |
| --- | --- | --- | --- |
| `query_input` | string | 用户输入的原始文本 | `"你好，世界"` |
| `language` | string | 检测出的语种（中文语言名） | `"中文"` / `"英语"` / `"日语"` |
| `result` | string | 翻译结果（中文→英文，其他→中文） | `"Hello, world"` |

输出示例：

```json
{
  "query_input": "你好，世界",
  "language": "中文",
  "result": "Hello, world"
}
```

```json
{
  "query_input": "こんにちは、世界",
  "language": "日语",
  "result": "你好，世界"
}
```

```json
{
  "query_input": "Hello, world",
  "language": "英语",
  "result": "你好，世界"
}
```

### 4.2 需求二：翻译类 MCP 工具扩展与 Agent 调用

#### 4.2.1 基线代码

基线为课程「2-兼容OpenAI-Agent」示例 `mcp_server_demo/mcp_server.py`：

- 基于官方 Python SDK `mcp >= 2.0`，采用 `Server(..., on_list_tools=..., on_call_tool=...)` **构造函数回调注册**风格（mcp 2.x 已移除 `@server.list_tools()` 装饰器风格）；
- 通过 **stdio** 与客户端通信，客户端以子进程方式拉起；
- 基线已具备：Tools（`get_weather`、`calculate`）、Resources（`config://app`、`greeting://{name}`）、Prompts（`code_review`、`translate`）。

本项目 `mcp/translation_server.py` **完整保留基线全部能力**，仅在其上**新增 3 个翻译类 MCP 工具**。

#### 4.2.2 新增 MCP 工具设计（由大模型生成）

| # | 工具名 | 用途 | 实现原理 | 是否调用大模型 |
| --- | --- | --- | --- | --- |
| 1 | `detect_language` | 检测文本语种 | 本地 Unicode 区段匹配（假名→日语、谚文→韩语、汉字→中文、西里尔→俄语等）+ 拉丁字母语言停用词投票（英/法/德/西/葡/意） | 否（零 Token 消耗） |
| 2 | `translate_text` | 翻译文本 | 内部调用 OpenAI 兼容大模型接口（`chat.completions`，temperature=0，只输出译文）；`source_language` 支持 `auto` 自动检测 | 是 |
| 3 | `get_language_info` | 查询语言元数据 | 内置 15 种语言的元数据表（代码、中/英文名、语系、书写系统、使用地区、使用人数），支持按代码/中文名/英文名查询 | 否 |

**工具 1：`detect_language`**

| 项 | 内容 |
| --- | --- |
| 入参 | `text`（string，必填）：待检测语种的文本 |
| 出参 | JSON：`{"language": "zh", "language_name": "中文", "confidence": 0.95, "script": "汉字"}` |
| 异常 | 空文本返回 `{"language": "unknown", "language_name": "未知", "confidence": 0.0}` |
| 置信度 | 非拉丁文字且占比 > 30% → 0.95；非拉丁文字占比 ≤ 30% → 0.85；停用词命中 → 0.9；拉丁字母无命中兜底英语 → 0.6 |

**工具 2：`translate_text`**

| 项 | 内容 |
| --- | --- |
| 入参 | `text`（string，必填）：待翻译文本；`target_language`（string，必填）：目标语言代码/名称；`source_language`（string，选填，默认 `auto`）：源语言，`auto` 时先本地检测 |
| 出参 | JSON：`{"source_language": "zh", "target_language": "en", "original_text": "...", "translated_text": "...", "model": "gpt-4o-mini"}` |
| 异常 | 未配置 `OPENAI_API_KEY` → 返回明确 error；目标语言无法识别 → 返回 supported 列表 |
| 依赖 | 环境变量 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`TRANSLATE_MODEL`（见 `.env.example`） |

**工具 3：`get_language_info`**

| 项 | 内容 |
| --- | --- |
| 入参 | `language`（string，必填）：语言代码（`zh`）/ 中文名（`中文`）/ 英文名（`Chinese`） |
| 出参 | JSON：`{"found": true, "language": "zh", "name_zh": "中文", "name_en": "Chinese", "family": "汉藏语系", "script": "汉字", "regions": "...", "speakers": "..."}` |
| 异常 | 未命中返回 `{"found": false, "query": "...", "supported": [...]}` |

#### 4.2.3 Agent 调用方式

两个 Agent 通过 OpenAI Agents SDK 的 MCP 客户端（`agents.mcp.MCPServerStdio`）挂载 MCP Server，SDK 自动将 MCP 工具注入 Agent 的工具列表，Agent 在推理中自行决定调用哪个工具、传什么参数：

```python
mcp_server = MCPServerStdio(
    name="translation-mcp-server",
    params={"command": sys.executable, "args": ["mcp/translation_server.py"]},
)
async with mcp_server:
    language_agent = create_language_agent(mcp_server)      # 挂载 detect_language
    translation_agent = create_translation_agent(mcp_server)  # 挂载 translate_text
    ...
```

## 12. 风险与约束

1. **大模型依赖**：`translate_text` 与 Agent 推理需要有效的 OpenAI 兼容 API Key；未配置时应用给出明确提示并以结构化 error 返回，不会静默失败。
2. **语种检测精度**：`detect_language` 为本地规则实现，覆盖 15 种常见语言；拉丁语系短文本依赖停用词投票，置信度已随输出返回，低置信度场景可在后续版本引入大模型兜底。
3. **MCP SDK 版本**：基线代码采用 mcp 2.x 构造函数回调风格，与 `mcp>=2.1.1` 匹配；若回退到 mcp 1.x 需改写为装饰器风格（需求文档已注明此约束）。
4. **输出解析**：主程序对 Agent 输出做了 JSON 提取与去引号容错，但极端输出格式仍可能导致解析失败，已通过 instructions 强约束 + 测试覆盖缓解。
