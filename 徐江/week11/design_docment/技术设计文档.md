## 1. 技术栈选型

| 层 | 选型 | 说明 |
|---|---|---|
| 后端框架 | Python 3.11+ / FastAPI | 异步原生，适合 SSE 流式与 LLM 编排[reference:0] |
| ORM | SQLAlchemy 2.0 async + asyncpg | 异步访问 PostgreSQL |
| 元数据库 | PostgreSQL 16 | 用户、权限、会话、审计、任务、知识库元数据 |
| 向量库 | pgvector（HNSW） | 复用 PostgreSQL，减少独立向量库运维 |
| LLM 编排 | LangChain + 云 LLM API | Provider 抽象，兼容 OpenAI 协议 |
| MCP Client | MCP Python SDK / 轻量客户端封装 | 支持工具发现与调用[reference:2] |
| SQL 解析与审核 | sqlglot | AST 级只读校验、表白名单、行数限制[reference:3] |
| 定时任务 | APScheduler + SQLAlchemyJobStore | 任务持久化，FastAPI lifespan 管理启停[reference:4] |
| 联网检索 | Tavily Search API | 参数可控，返回带来源结果[reference:5] |
| 前端 | React + Ant Design + ECharts | 聊天、SQL/图表、管理后台 |
| 流式传输 | SSE（Server-Sent Events） | FastAPI StreamingResponse 逐 token 推送[reference:6] |
| 部署 | Docker Compose 单机 | Demo 可运行，预留私有化配置 |

```text
┌──────────────────────▼──────────────────────────────┐

│  意图路由 → 问数 / 知识库 / MCP / 联网                 │
└───┬──────────┬──────────┬──────────┬────────────────┘

└───┬───┘ └───┬───┘ └───┬───┘ └───┬───┘ └─────┬──────┘
    │         │         │         │           │
┌───▼─────────▼─────────▼─────────▼───────────▼──────┐
│              PostgreSQL + pgvector                   │
│  元数据 / 权限 / 会话 / 审计 / 知识库 / 任务          │
└──────────────────────────────────────────────────────┘
    │                    │                    │
┌───▼───┐          ┌─────▼─────┐        ┌────▼────┐
│业务DB │          │外部MCP    │        │Tavily   │
│MySQL  │          │Server     │        │Search   │
│PG     │          └───────────┘        └─────────┘
└───────┘
```

**分层原则**：

1. 编排层不直接执行 SQL、不直接调搜索 API，只做路由和上下文组装；
2. 能力层每个模块独立封装，通过接口调用，便于后续替换；
3. 所有能力层出口统一经过治理层（权限、SQL 审核、审计）。

### 4.3 向量索引

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE INDEX idx_chunks_embedding
ON knowledge_chunks
USING hnsw (embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);
```

HNSW 参数 `m=16`、`ef_construction=64` 是 Demo 级平衡选择；后续按召回效果调大 `ef_search`。检索时按 `department_id IN (当前部门, NULL)` 先过滤再 ANN，避免跨部门泄漏。

## 6. 核心实现方案

### 6.1 NL2SQL 链路

```text
用户问题
  → Schema 检索：按问题关键词 + 向量相似度召回相关表/字段/指标口径
  → Prompt 组装：授权 Schema + 知识库口径 + 历史 SQL 示例
  → LLM 生成 SQL
  → sqlglot 审核（见 6.2）
  → 只读执行（独立连接，READ ONLY 事务，超时 + 行数上限）[reference:10]
  → 结果返回表格数据 + 图表建议
  → LLM 生成自然语言解释
```

**Schema 检索策略**：Demo 阶段用“表名/字段名关键词匹配 + 指标口径向量检索”混合召回；候选表数量限制在 10 张以内，避免 Prompt 过长。

**SQL 执行安全**：使用独立只读连接池；执行前设置 `statement_timeout`；无 LIMIT 时自动注入 `LIMIT 1000`；错误信息脱敏后再返回前端[reference:11][reference:12]。

### 6.2 SQL 安全审核（sqlglot）

```python

    exp.Insert, exp.Update, exp.Delete,
    exp.Drop, exp.Alter, exp.Create,

def assert_single_statement(sql: str):
    statements = [s for s in sqlglot.parse(sql) if s]
    if len(statements) != 1:
        raise ReadOnlyViolation("仅允许单条语句")

def assert_read_only(sql: str, dialect: str):
```

审核顺序：**单语句 → 只读 AST → 表白名单 → 行数上限**。任一失败即拒绝执行，原因写入审计[reference:13]。

### 6.3 知识库 RAG

**文档处理链路**：上传 → 按扩展名解析（pypdf/python-docx）→ 递归切分（chunk_size≈800，overlap≈100）→ 绑定部门标签 → 向量化 → 写入 `knowledge_chunks`。

**检索链路**：问题向量化 → `embedding <=> query_vector` 余弦距离排序 → 先按 `department_id IN (当前部门, NULL)` 过滤，再取 TopK（K=5）→ 相似度阈值过滤 → 组装引用卡片（文档名、片段、相似度）。

**引用规则**：每条引用必须包含 `document_name`、`chunk_content`、`similarity`；无引用时回答需显式标注“无直接引用”。

### 6.4 MCP Client

**配置模型**：每个 MCP Server 存 `name`、`url`、`auth_type`、`auth_config`（加密）、`is_enabled`。

**工具发现**：连接成功后调用 `list_tools()` 获取工具名、描述、inputSchema，缓存到内存并定时刷新[reference:14]。

**调用流程**：

```text
意图判定需要 MCP
  → 从已启用 Server 的工具列表中匹配
  → 参数校验（Pydantic Schema）
  → call_tool(tool_name, arguments)
  → 结果回填到消息
  → 失败时降级，不阻塞整体回答
```

Demo 只做 Client 模式，接 1～2 个外部 MCP Server（如一个天气/汇率类工具 Server、一个内部业务查询 Mock Server）[reference:15]。

### 6.5 联网检索（Tavily）

```python
from tavily import TavilyClient

client = TavilyClient(api_key=settings.TAVILY_API_KEY)
resp = client.search(
    query=user_query,
    search_depth="basic",
    max_results=5,
    topic="general",
    include_answer=False,
    include_raw_content=False,
)
```

参数约定：`max_results=5`，`search_depth="basic"` 控制成本；`topic` 根据问题选择 `general` / `news`；返回字段提取 `title`、`url`、`content` 作为引用来源[reference:16][reference:17]。

**触发条件**：仅当用户手动开启联网开关，且编排层判断需要外部信息时调用；未开启不调用[reference:18]。

### 6.6 定时任务（APScheduler）

**架构**：`AsyncIOScheduler` + `SQLAlchemyJobStore`，在 FastAPI `lifespan` 中启动和关闭[reference:19]。

```python
from apscheduler.schedulers.asyncio import AsyncIOScheduler
from apscheduler.jobstores.sqlalchemy import SQLAlchemyJobStore

scheduler = AsyncIOScheduler(
    jobstores={"default": SQLAlchemyJobStore(url=settings.SCHEDULER_DB_URL)},
    job_defaults={"coalesce": True, "max_instances": 1},
)
```

**任务类型**：

| 类型 | 执行逻辑 |
|---|---|
| report | 复用 SQL 审核 + 只读执行 → 结果通过 Webhook 推送 |
| reindex | 扫描 `knowledge_documents` 中待更新文档 → 重新切分/向量化 |

**启停策略**：所有任务都加入 scheduler，禁用状态的任务添加后立即 `pause_job`，保证后台可见、可控制[reference:20]。执行记录写 `task_runs`，失败不自动重试，保留错误信息供手动触发。

### 6.7 SSE 流式输出

聊天接口 `POST /api/chat` 返回 `StreamingResponse`，事件类型：

| 事件 | 数据 | 说明 |
|---|---|---|
| `step` | `{"step": "schema_retrieval"}` | 处理步骤提示 |
| `sql` | `{"sql": "..."}` | 生成的 SQL |
| `audit` | `{"passed": true, "risk": "high"}` | 审核结果 |
| `confirm_required` | `{"sql": "...", "reason": "..."}` | 高危需确认 |
| `result` | `{"columns": [...], "rows": [...]}` | 表格数据 |
| `chart` | `{"type": "bar", "option": {...}}` | 图表配置 |
| `citation` | `{"sources": [...]}` | 引用来源 |
| `token` | `{"text": "..."}` | 流式 token |
| `done` | `{"duration_ms": 1234}` | 结束 |

前端通过 `EventSource` 或 `fetch` + `ReadableStream` 消费；高危 SQL 场景先发 `confirm_required`，前端弹窗确认后再发 `POST /api/chat/confirm` 继续执行[reference:21]。

### 6.8 审计与权限

**鉴权**：JWT 放在 `Authorization: Bearer`，中间件解析用户、角色、部门；所有业务接口依赖当前用户。

**权限校验点**：

1. **表级**：Schema 检索前先按 `table_permissions` 过滤，未授权表不进入候选；
2. **知识库**：检索 SQL 强制附加 `department_id IN (current_dept, NULL)`；
3. **管理接口**：`@require_role("admin")` 装饰器校验。

**审计写入**：编排层在每个能力调用结束后异步写 `audit_logs`；写入失败只记录本地日志，不阻塞主流程。

## 8. 关键技术风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| NL2SQL 准确率不足 | 演示问题生成错误 SQL | 限定样例数据 + Schema 精简 + 知识库口径注入 + 失败重试一次 |
| pgvector 部门过滤与 ANN 性能冲突 | 检索变慢或结果不准 | 先过滤后检索，Demo 数据量小可接受；后续可加分区或预过滤索引 |
| APScheduler 单实例重复执行 | 多 worker 下任务跑多次 | Demo 用单 worker；`max_instances=1`；后续换分布式调度 |
| MCP Server 不稳定 | 工具调用失败影响体验 | 超时 + 降级回答 + 审计记录，不阻塞主流程[reference:24] |
| sqlglot 方言覆盖不全 | 合法 SQL 被误拒 | 显式传入数据源方言；严格模式拒绝，日志记录供调优[reference:25] |
| SSE 长连接断开 | 前端收不到完整结果 | 心跳 + 前端重连；后端完成结果落库，重连后可拉取 |
| 云 LLM 延迟 | 问数响应慢 | 流式输出 + 步骤提示 + 超时降级 |
