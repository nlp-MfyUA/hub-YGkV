## 2. 项目背景与定位

ChatBI 是一个面向内部用户的智能数据分析与问答系统。用户通过自然语言完成：

- 业务数据查询与分析；
- 业务知识库问答与引用溯源；
- 通过 MCP 调用外部工具或数据源；
- 在需要时手动开启联网检索；
- 通过定时任务完成报表推送、告警、知识库索引更新等。

**项目定位**：

> 单租户、内部使用的 ChatBI Demo/MVP，优先跑通“问数 + 知识库 + MCP + 联网 + 定时任务”的最小闭环，后续再逐步产品化。

**首期运行约束**：

- 先在有公网、可调用云 LLM API 的环境运行；
- 内网私有化和本地模型后续阶段再做；
- 权限先做用户/角色/部门、知识库部门过滤、表级权限；行/列级权限后续；
- SQL 审核先做自动规则 + 高危 SQL 前台确认；后台人工审核队列后续。

---

## 3. 建设目标与成功标准

### 3.1 建设目标

1. 用户能用自然语言完成基础问数，并得到可执行 SQL、表格/图表和解释；
2. 用户能对业务文档、表结构、历史 SQL 等进行知识库问答，回答带引用；
3. ChatBI 能作为 MCP Client 调用至少 1～2 个外部 MCP 工具；
4. 用户手动开启联网后，能获取带来源的外部补充信息；
5. 定时任务能完成报表推送和知识库索引更新等基础任务；
6. 具备最小权限、SQL 安全审核和审计能力。

### 3.2 MVP 成功标准

- 3 个典型自然语言问题能生成可执行只读 SQL，并输出表格/图表和解释；
- 知识库回答带引用，不同部门用户检索结果受权限过滤；
- 至少 1 个外部 MCP 工具可被识别并调用；
- 手动联网检索能返回带来源结果；
- 高危 SQL 会触发前台确认，审计日志可查；
- 定时报表推送和索引更新任务可触发并记录执行日志。

## 4. 项目范围

### 4.1 第一期范围（2 周 Demo）

| 能力 | 第一期范围 |
|---|---|
| 自然语言问数 | Schema 检索、SQL 生成、规则审核、高危前台确认、只读执行、表格/图表、解释 |
| 知识库问答 | 文档上传解析、切分、向量化、检索、引用、部门权限过滤 |
| MCP | ChatBI 作为 MCP Client，接 1～2 个外部 MCP Server 示例 |
| 联网检索 | 用户手动开启，调用通用搜索 API，结果带来源 |
| 定时任务 | 定时报表推送、知识库索引更新，任务日志可查 |
| 权限 | 登录、用户/角色/部门、知识库部门过滤、表级权限 |
| 安全审计 | SQL 只读、表白名单、敏感函数限制、审计日志 |
| 数据源 | MySQL/PostgreSQL、Excel/CSV、外部业务系统 API |

### 4.2 后续范围

- 内网私有化部署与本地模型；
- 行级/列级数据权限；
- SSO 完整对接；
- 后台人工 SQL 审核队列与审批流；
- 内部 MCP Server 封装；
- 分布式调度、复杂告警规则；
- ClickHouse/OLAP 等更多数据源；
- 多租户与团队空间；
- 更完整的 BI 看板与 Agent 自主规划。

### 4.3 明确不做

第一期不做多租户、不做复杂 Agent 自主规划、不做完整审批流、不做行列级细粒度权限、不做分布式调度、不做内部 MCP Server 对外服务。

## 5. 用户角色与权限概念

| 角色 | 主要能力 |
|---|---|
| 普通业务用户 | 提问、问数、知识库问答、手动联网、查看自己的历史与结果 |
| 部门用户 | 在普通用户基础上，只能检索本部门及授权知识库内容 |
| 管理员 | 管理用户/角色/部门、数据源、知识库、MCP 工具、定时任务、审计日志 |
| 数据/系统管理员 | 配置表白名单、SQL 审核规则、数据源连接、任务与推送 |

**权限原则**：

- 先自建用户/角色/部门体系；
- 知识库按部门过滤；
- 数据查询先做表级权限；
- 所有查询、知识库检索、MCP 调用、联网检索、定时任务执行均记录审计。

## 6. 总体能力架构（概念层）

系统按“入口—编排—能力—治理—基础设施”划分：

```text
用户入口
  └─ Chat 前端 / 任务管理 / 管理后台
       ↓
会话与意图编排
  ├─ 问数意图
  ├─ 知识库意图
  ├─ MCP 工具意图
  ├─ 联网检索意图
  └─ 多轮上下文
       ↓
核心能力模块
  ├─ NL2SQL 与数据分析
  ├─ 知识库检索与引用
  ├─ MCP Client
  ├─ 联网检索
  └─ 定时任务
       ↓
治理与安全
  ├─ 用户/角色/部门权限
  ├─ SQL 规则审核与高危确认
  ├─ 审计日志
  └─ 配置管理
       ↓
基础资源
  ├─ 业务数据库 / 文件 / 外部 API
  ├─ 知识库与向量索引
  ├─ 外部 MCP Server
  ├─ 搜索 API
  └─ LLM Provider
```

## 7. 模块划分与职责

| 模块 | 职责 | 第一期边界 |
|---|---|---|
| 会话与编排 | 识别用户意图，路由到问数、知识库、MCP、联网；维护多轮上下文 | 规则/LLM 辅助路由，不做复杂自主规划 |
| NL2SQL 与问数 | Schema 检索、SQL 生成、执行、图表建议、解释 | 支持首批数据源，复杂跨库优化后续 |
| SQL 安全审核 | 只读校验、表白名单、敏感函数限制、高危 SQL 前台确认 | 后台审批队列后续 |
| 知识库 | 文档上传、解析切分、向量化、检索、引用、部门过滤 | 行级知识权限后续 |
| MCP Client | 发现并调用外部 MCP Server 工具 | 只接 1～2 个示例 Server，不做内部 Server |
| 联网检索 | 手动开关、搜索 API 调用、结果引用 | 不自动触发，不做站点白名单爬取 |
| 定时任务 | 报表推送、索引更新、执行日志 | 轻量调度，单实例 Demo |
| 权限与审计 | 登录、角色部门、表级权限、审计日志 | SSO 完整对接、行列级权限后续 |
| 前端 | 聊天、SQL/图表、引用、高危确认、任务管理、管理页 | 以 Demo 可用为目标 |

## 8. 核心端到端链路

### 8.1 问数链路

用户提问 → 意图识别为问数 → 检索相关表结构与指标口径 → 生成 SQL → 规则审核 → 高危则前台确认 → 只读执行 → 表格/图表 → 生成解释 → 写审计日志。

### 8.2 知识库链路

文档上传 → 解析切分 → 向量化并打部门标签 → 用户提问 → 按部门权限检索 → 生成带引用回答 → 写审计日志。

### 8.3 MCP 链路

用户提问 → 判断需要外部工具 → MCP Client 列出可用工具 → 选择并调用 → 结果回填 → 生成回答/引用 → 写审计日志。

### 8.4 联网检索链路

用户手动开启联网 → 判断需要外部信息 → 调用搜索 API → 汇总结果并附来源 → 与知识库/问数结果结合回答 → 写审计日志。

### 8.5 定时任务链路

管理员配置任务 → 定时触发或手动触发 → 执行报表 SQL 或重建知识库索引 → 记录执行日志 → Webhook/邮件推送 → 可在任务页查看结果。

## 12. 主要风险与约束

| 风险 | 说明 | 应对 |
|---|---|---|
| 范围偏大 | 2 周 Demo 覆盖多条链路 | 每模块只做最小闭环，降级项已确认 |
| NL2SQL 准确率 | 表结构复杂时 SQL 可能出错 | 首批限定样例数据与典型问题，Schema 检索 + 规则审核 |
| 权限复杂度 | 行/列权限后续做 | 第一期表级权限 + 知识库部门过滤 |
| 联网合规 | 外部搜索可能带出内部信息 | 手动开启，后续做脱敏与白名单 |
| 内网部署 | 云 LLM 与内网冲突 | 第一期出网环境，后续本地模型 |
| 调度可靠性 | 单实例调度能力有限 | Demo 接受，后续换分布式调度 |
