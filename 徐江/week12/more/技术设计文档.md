## 2. 模型接入设计

### 2.1 Provider 抽象

```python
# backend/providers/base.py
from abc import ABC, abstractmethod
from dataclasses import dataclass

@dataclass
class RawResult:
    text: str
    latency_ms: int
    provider: str
    model: str

class VisionProvider(ABC):
    name: str
    model: str

    @abstractmethod
    async def analyze(self, image_b64: str, system_prompt: str, user_text: str) -> RawResult:
        ...
```

### 2.2 DeepSeek Provider

```python
# backend/providers/deepseek.py
import time
from openai import AsyncOpenAI
from .base import VisionProvider, RawResult

class DeepSeekProvider(VisionProvider):
    name = "deepseek"

    def __init__(self, api_key: str, base_url: str, model: str, timeout: float = 30.0):
        if not api_key or not base_url:
            raise RuntimeError("DeepSeek provider 未配置 api_key / base_url")
        self.model = model
        self._client = AsyncOpenAI(api_key=api_key, base_url=base_url, timeout=timeout)

    async def analyze(self, image_b64: str, system_prompt: str, user_text: str) -> RawResult:
        t0 = time.perf_counter()
        resp = await self._client.chat.completions.create(
            model=self.model,
            messages=[
                {"role": "system", "content": system_prompt},
                {"role": "user", "content": [
                    {"type": "text", "text": user_text},
                    {"type": "image_url",
                     "image_url": {"url": f"data:image/jpeg;base64,{image_b64}"}},
                ]},
            ],
            temperature=0.1,
            max_tokens=800,
        )
        latency = int((time.perf_counter() - t0) * 1000)
        return RawResult(resp.choices[0].message.content or "", latency, self.name, self.model)
```

> **说明**：`base_url` 与 `model` 全部来自 `.env`，代码不假设 `deepseek-v4.1-flash` 的确切端点。请按服务商文档填写；若该模型实际不接受 `image_url` 数组格式，只需改本文件的消息组装方式，其他模块不动。

## 3. Prompt 设计

### 3.1 完整系统提示词（写入 `backend/prompt.py`）

```
你是住宅楼道消防安全风险识别助手。你只依据图像中肉眼可见的证据做判断，不得编造图像中不存在的物体。

【第一步：判定场景类型 scene_type】
从下列五值中选一个：
- stairwell：楼梯间、疏散走道、安全出口区域
- corridor：住宅公共走廊、电梯厅
- elevator：电梯轿厢内部
- garage_passage：地下或半地下车库的行人通道
- non_corridor：室内房间、户外、人物特写、截图/拼图、严重模糊或过暗无法辨识

【第二步：识别风险信号 signals】
逐项检查并列出可见信号，每条含 type、level、detail：
- 电动车 / 电瓶 / 飞线充电
- 大量堆积物严重阻碍通行
- 大量纸箱 / 木质家具 / 泡沫箱等可燃堵塞物
- 少量堆物（通道基本畅通）
- 通道干净无堆物

【电动车分场景规则】
- stairwell / corridor / elevator 中出现电动车、电瓶或飞线充电 → 该信号等级为"高风险"
- garage_passage 中电动车停放本身不判高风险；但飞线充电 → "高风险"，堵塞行人通道 → "中风险"
- 楼栋外空地、单元门外露天区域的车辆不属于楼道信号

【等级判据】
- 高风险：楼道内出现电动车、电瓶、飞线充电等可能起火的元素
- 中风险：大量堆积物严重影响通行，或堆放大量纸箱、木质家具、泡沫等可燃堵塞物（两者满足任一即中风险）
- 低风险：存在堆物但不严重，通道基本畅通
- 无风险：干净整洁，无堆放物品
- 非楼道：与楼道无关的图像

【不计入堆物的对象】
灭火器箱、消火栓、信报箱、固定消防柜、疏散指示牌、地面标识线。
（鞋柜、婴儿车、晾衣架、纸箱、泡沫箱、木质家具、自行车计入堆物）

【冲突规则】
- 多个信号时取最高等级：高 > 中 > 低 > 无
- 单一信号时直接输出该信号等级
- scene_type 为 non_corridor 时，risk_level 必须为"非楼道"，忽略其他信号

【图像质量兜底】
若图像过暗、过曝、严重模糊或无法辨识场景 → scene_type=non_corridor，risk_level=非楼道，confidence=low，evidence 说明"图像质量不足"。

【输出格式】
只输出以下 JSON，不要任何前后缀文字、不要 Markdown 代码围栏：
{
  "scene_type": "stairwell|corridor|elevator|garage_passage|non_corridor",
  "risk_level": "高风险|中风险|低风险|无风险|非楼道",
  "confidence": "high|medium|low",
  "evidence": "引用图像中可见的具体线索，80 字以内",
  "signals": [
    {"type": "电动车", "level": "高风险", "detail": "画面左侧楼梯口停放一辆两轮电动车"}
  ]
}
```

### 3.2 设计要点

- **两段式判定**：先定场景、再识别信号，最后按冲突规则合成等级。这与裁决器的服务端重算形成双保险。
- **白名单显式化**：把消防器材写进"不计入堆物"，减少误判。
- **garage_passage 的电动车例外**：直接对应需求澄清中"车库通道参与判定"与"电动车仅在楼道内判高风险"两条的组合诉求，避免规则冲突。
- **禁止 Markdown 围栏**：降低解析失败率；后端仍保留剥离逻辑兜底。
- **temperature=0.1**：分类任务需要稳定输出。

## 5. 数据模型

```python
# backend/schemas.py
from pydantic import BaseModel, Field
from typing import Literal

RiskLevel = Literal["高风险", "中风险", "低风险", "无风险", "非楼道"]
SceneType = Literal["stairwell", "corridor", "elevator", "garage_passage", "non_corridor"]
Confidence = Literal["high", "medium", "low"]

class Signal(BaseModel):
    type: str
    level: RiskLevel
    detail: str = ""

class ModelOutput(BaseModel):
    scene_type: SceneType
    risk_level: RiskLevel
    confidence: Confidence
    evidence: str = Field(max_length=400)
    signals: list[Signal] = []

class AnalyzeResponse(BaseModel):
    request_id: str
    risk_level: RiskLevel
    confidence: Confidence
    evidence: str
    scene_type: SceneType
    signals: list[Signal]
    arbiter_override: bool
    provider: str
    model: str
    latency_ms: int
```

## 6. 裁决器实现

```python
# backend/arbiter.py
WEIGHT = {"高风险": 3, "中风险": 2, "低风险": 1, "无风险": 0}
BY_WEIGHT = {v: k for k, v in WEIGHT.items()}

def arbitrate(model_out: ModelOutput) -> tuple[RiskLevel, bool]:
    if model_out.scene_type == "non_corridor":
        return "非楼道", model_out.risk_level != "非楼道"
    if not model_out.signals:
        return model_out.risk_level, False
    weights = [WEIGHT[s.level] for s in model_out.signals if s.level in WEIGHT]
    if not weights:
        return model_out.risk_level, False
    final = BY_WEIGHT[max(weights)]
    return final, final != model_out.risk_level
```

## 7. 解析容错

```python
# backend/utils.py
import json, re

def parse_model_json(text: str) -> dict:
    s = text.strip()
    s = re.sub(r"^```(?:json)?\s*", "", s)
    s = re.sub(r"\s*```$", "", s)
    i, j = s.find("{"), s.rfind("}")
    if i == -1 or j == -1 or j <= i:
        raise ValueError("no json object found")
    return json.loads(s[i:j+1])
```

## 8. 前端技术要点

- **安全上下文**：`getUserMedia` 在非 `localhost` 下必须 HTTPS；真机调试用 `cloudflared` / `ngrok`。
- **`playsinline` + `muted`**：iOS Safari 必须加，否则视频不自动播放。
- **拍照压缩**：长边 1600 px、JPEG 0.85；实测可把 3–5 MB 原图压到 300–600 KB，显著降低 Base64 体积与推理延迟。
- **Base64 位置**：前端只传 Blob，Base64 在后端做，避免 JS 主线程大字符串拼接卡顿。
- **`AbortController`**：45 s 前端强制中断，防止无限等待。
- **摄像头释放**：`visibilitychange` 时 `stop()` 所有 track，避免手机端摄像头占用。
- **降级文件输入**：`<input type="file" accept="image/*" capture="environment">` 在 iOS 会弹"拍照/相册"选择，作为 F-04 通道。

## 9. 评测方案

### 9.1 数据集

- 每类 ≥ 15 张，总量 ≥ 75 张；建议 20/类，共 100 张。
- 来源：实地拍摄 + 公开消防宣传图 + 自建（注意版权，仅本地评测用）。
- 命名：`{label}_{序号}.jpg`，如 `high_001.jpg`。
- `labels.csv`：`filename,true_label`，`true_label` 用中文五类。

### 9.2 指标

- 总体准确率；
- 5×5 混淆矩阵；
- 各类 precision / recall / F1；
- 高风险类的 **召回率** 单独突出（漏报高风险代价最大）；
- 平均 / P95 延迟；
- 解析失败率（应接近 0）。

### 9.3 脚本骨架

```python
# eval/run_eval.py 核心逻辑
async def main(args):
    provider = build_provider(settings_override(args.provider))
    rows = load_labels(args.dataset)
    results = []
    for r in rows:
        b64 = encode_image(r.path)
        try:
            raw = await provider.analyze(b64, SYSTEM_PROMPT, USER_TEXT)
            mo = ModelOutput(**parse_model_json(raw.text))
            final, override = arbitrate(mo)
            results.append((r.filename, r.true_label, final, override, raw.latency_ms, "ok"))
        except Exception as e:
            results.append((r.filename, r.true_label, "PARSE_FAIL", False, 0, str(e)))
    report = build_report(results)   # 混淆矩阵 + P/R/F1 + 错误清单
    write_markdown(report, args.out)
```

### 9.4 建议的两轮评测

1. **基线轮**：直接用当前 Prompt，看各类准确率与高风险召回。
2. **调优轮**：针对混淆最多的类别补充 Prompt 反例（如"纸箱 vs 泡沫箱""车库电动车"），再跑一遍对比。报告里保留两轮结果。

## 12. 关键流程伪代码（`main.py`）

```python
@app.post("/api/analyze", response_model=AnalyzeResponse)
async def analyze(image: UploadFile = File(...)):
    rid = str(uuid4())
    data = await image.read()
    validate_image(data, image.content_type)          # F-05
    b64 = base64.b64encode(data).decode()
    raw = await call_with_retry(provider, b64)         # F-07
    model_out = ModelOutput(**parse_model_json(raw.text))
    final_level, override = arbitrate(model_out)       # F-08
    log.info("analyze rid=%s size=%d level=%s override=%s latency=%d",
             rid, len(data), final_level, override, raw.latency_ms)
    return AnalyzeResponse(
        request_id=rid, risk_level=final_level,
        confidence=model_out.confidence, evidence=model_out.evidence,
        scene_type=model_out.scene_type, signals=model_out.signals,
        arbiter_override=override, provider=raw.provider,
        model=raw.model, latency_ms=raw.latency_ms,
    )
```
