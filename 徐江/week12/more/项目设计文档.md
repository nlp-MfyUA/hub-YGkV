# 楼道消防安全多模态识别 Demo — 项目设计文档

## 1. 项目概述

构建一个 **Python 后端 + 移动端 Web 前端** 的多模态楼道消防风险识别 Demo。用户在手机浏览器打开网页、调用后置摄像头拍照、上传至后端；后端调用视觉大模型（`deepseek-v4.1-flash` 为主通道，`qwen-vl-max` 为备选通道），按五级分类输出风险等级、置信度与判定依据。项目附带自建测试集与评测脚本，用于量化分类效果。

**定位**：可演示、可解释、可评测的端到端原型，非生产系统。

## 4. 数据流

1. 前端 `<video>` 预览 → 用户点"拍照" → canvas 绘制当前帧 → `toBlob('image/jpeg', 0.85)`，长边限制 1600 px。
2. `FormData` 字段 `image` → `POST /api/analyze`。
3. 后端 `UploadFile` 校验：MIME ∈ {jpeg, png, webp}，大小 ≤ 8 MB，最小边 ≥ 224 px。
4. 读取 `bytes` → Base64 → `data:image/jpeg;base64,...`。
5. Prompt 构造：系统提示词（含场景分类、五级判据、冲突规则、电动车分场景规则、输出 JSON 要求）+ 用户消息（图片 + 一句任务指令）。
6. `VisionProvider.analyze(image_b64, prompt) -> RawResult`。
7. 解析 JSON（剥离 ```json 包裹、字段缺失补默认值、枚举越界视为失败）。
8. **服务端二次裁决**：若模型返回 `signals` 数组，后端按"取最高等级"重算 `risk_level`，避免模型自算错误。
9. 返回响应，记录日志（不含图片内容）。
10. 前端渲染。

## 5. 场景分类与判定规则矩阵

这是本 Demo 的核心业务逻辑，Prompt 与裁决器均以此为准。

### 5.1 场景类型（`scene_type`）

| 值 | 含义 |
|---|---|
| `stairwell` | 楼梯间、疏散走道、安全出口区域 |
| `corridor` | 住宅公共走廊、电梯厅 |
| `elevator` | 电梯轿厢内部 |
| `garage_passage` | 地下/半地下车库的行人通道 |
| `non_corridor` | 室内房间、户外、人物特写、截图拼图、无法辨识 |

### 5.2 等级枚举（`risk_level`）

`高风险` / `中风险` / `低风险` / `无风险` / `非楼道`

### 5.3 判定规则矩阵

| 观察信号 | stairwell / corridor | elevator | garage_passage | non_corridor |
|---|---|---|---|---|
| 电动车 / 电瓶 / 飞线充电 | **高风险** | **高风险**（电池入轿厢即高风险） | 停放本身不判高风险；**飞线充电 → 高风险**；堵塞通道 → 中风险 | — |
| 大量堆积物**且**严重阻碍通行 | **中风险** | **中风险**（轿厢内堆物影响乘梯） | **中风险** | — |
| 大量纸箱 / 木质家具 / 泡沫等可燃堵塞物 | **中风险** | **中风险** | **中风险** | — |
| 少量堆物、通道基本畅通 | **低风险** | **低风险** | **低风险** | — |
| 干净无堆物 | **无风险** | **无风险** | **无风险** | — |
| 非上述场景 | — | — | — | **非楼道** |

### 5.4 冲突裁决

- 图中存在多个信号时，**取最高等级**（高 > 中 > 低 > 无）。
- **单信号**直接输出对应等级，不触发冲突规则。
- 服务端裁决器对模型返回的 `signals` 重算等级，与模型自报的 `risk_level` 不一致时，**以服务端重算为准**，并在响应中标记 `arbiter_override: true`。

### 5.5 不计入堆物的对象

消防器材（灭火器箱、消火栓）、信报箱、固定消防柜、消防疏散指示牌、地面标识线。鞋柜、婴儿车、晾衣架、纸箱、泡沫箱、木质家具、自行车计入堆物。

### 5.6 图像质量不足

过暗、过曝、严重模糊、纯色图 → 输出 `非楼道` + `confidence: low` + `evidence` 注明"图像质量不足，无法判定"。

## 6. 部署形态

- 本地开发：`uvicorn backend.main:app --host 0.0.0.0 --port 8000`，浏览器访问 `http://localhost:8000`。
- 手机真机：`cloudflared tunnel --url http://localhost:8000` 或 `ngrok http 8000`，用生成的 HTTPS 地址访问（`getUserMedia` 强制要求安全上下文）。
- 前端静态文件由 FastAPI `StaticFiles` 托管，同端口，无需 CORS。
- 评测子系统离线运行：`python eval/run_eval.py --dataset eval/dataset --provider qwen`。

## 9. 明确不做

用户体系 / 数据库 / 历史持久化 / 视频流 / 模型微调 / 生产级并发与限流 / 语音 TTS 与 ASR / 多语言。

## 10. 实施顺序建议

1. 搭后端骨架 + `check_provider.py` 验证主通道连通性。
2. 写 Prompt 并用 10 张图粗测。
3. 补前端（摄像头、拍照、上传、渲染）。
4. 建评测集跑基线。
5. 按混淆结果迭代 Prompt，跑调优轮。
