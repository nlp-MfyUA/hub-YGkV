# 两个 ESG Skill：带脚本与不带脚本对照实验报告

日期：2026-11-26（Asia/Shanghai）

状态：已完成 12 次紧凑主实验与 1 次完整包采购试跑；完整包月报两次均在 45 分钟限制内未写出交付物，作为执行通道失败记录，不计入评分。联网补充与采购监控序列本轮未执行，原因见第 8 节。

## 1. 主要结论与适用范围

1. 月报案例：带脚本版与不带脚本版内容质量持平。两版各 3 轮的平均综合分均为 85.0 分，事实检查均为 87.5%，报告长度分别约 6.5 千字和 6.4-6.6 千字。没有观察到固定脚本带来的内容提升。
2. 采购案例：不带脚本版平均 64.08 分，带脚本版平均 40.83 分；事实检查平均 40.0% 对 0.0%。带脚本版的问题主要来自固定脚本与模型证据 schema 的兼容性：procurement_data.py 要求来源 status=ok 且 URL 为 http/https，模型生成的证据在补齐 URL 前被标记 unverified_original_evidence，归一后只有 9 个项目、20 个标包，cohort 全部排除，金额统计为空。无脚本版在 R1 达到 11 个项目、22 个标包、20 个披露金额、总额 28,567,254.95 元，与金标一致。
3. 脚本检查通过不等于事实正确：带脚本月报的 validate_evidence.py 全部返回 exit 1，主要问题是报告中的 [Cxxx] 缺少对应 Markdown 来源链接定义和部分发布日期为空；这只能说明结构检查发现问题，不能说明报告内容错误。
4. 适用范围：本次只覆盖中国神华月报与中国全国 ESG 招投标研究两个案例、同一模型（anyrouter/gpt-6.1-sol）、每版 3 轮、紧凑输入包。结论不能外推为“固定脚本普遍无效”或“无脚本普遍更好”，只能作为本实现下的探索性结果。

## 6. 数据处理、重复运行与成本

- 重复运行：月报两版 3 轮都稳定在 85.0；采购无脚本版三轮为 91.25、48.75、52.25，方差明显大于月报，说明采购任务对提示词和数据结构更敏感。

## 8. 版本选择建议与局限

- 月报：本次两版无差异。若需要交付前结构自检，带脚本版提供 validate_evidence.py，但它会对 Markdown 链接定义和日期字段提出较多告警；若不希望维护脚本，不带脚本版更简单。不能据此断言脚本无用。
- 采购：当前 procurement_data.py 对输入 schema、来源 URL、币种和状态要求较硬，模型生成的证据经常无法通过归一，导致统计为空；在修复兼容性前，不带脚本版的实测表现更好。建议先修脚本：对缺失 URL 的来源给出明确错误清单，允许从 metadata 补 URL，对 unit=元/万元且无其他币种说明的金额给出可配置的 CNY 归一策略，并输出归一前后记录数。
- 局限：样本仅 2 个案例、每版 3 轮；同一模型但存在随机波动；紧凑输入包只包含核心原文，完整包只完成 1 次采购试跑；月报完整包两次超时；联网补充与采购监控序列未执行；评分由自动事实检查与单次独立评审合成，评审者只看到报告与摘要，未看到完整 evidence 文件，d3 追溯分由结构检查补足；工作目录隔离不是操作系统级隔离。以上条件写入结论，不能外推为普遍规律。
