# ESG 招投标研究与监控

自主寻找原始公告，筛选真正相关项目，把证据转为可复算的统计及可评估的采购机会。首次默认中国全国、截至研究日过去24个月、中文 Markdown，纳入专业服务、软件与数据、设备与工程及混合项目。用户可覆盖范围、日期和模式；沿用已经确认的参数。

## 输入与模式

- **历史研究**：默认按原文核验的已确认中标/成交公告发布日期研究过去24个月的项目；可指定按原文明示成交日期。附当前仍可投标的机会时另列，不混入成交统计。
- **单次监控**：检索近期新公告及更正，读取已有状态，生成新增、变更、延期、终止、临近截止及覆盖失败的日报。运行一次不等于已建立定时任务。
- 参数：`mode`、`as_of`、`start` / `end`、`regions`、`categories`、采购方类型、输出目录、状态文件；监控默认重叠回看7天、提示未来3天截止。按 Asia/Shanghai 确定研究日，展示实际时间端点。
- 在当前 Codex 使用实际提供的联网搜索和网页访问工具。无内置搜索时按研究参考文档使用打包搜索、原文快照脚本或可用浏览器；没有搜索或正文访问能力时说明阻塞和已有证据，不能把缓存或搜索摘要写成实时结果。

研究前读 [research.md](references/research.md)。提取数据时读 [data-contract.md](references/data-contract.md)。写报告和监控时读 [reporting.md](references/reporting.md)。

## 工作流程

1. **确定范围与检索计划。** 先按主题、地区、来源和历史月份分线检索。全国是地域目标，报告披露实际覆盖；不能把搜索结果总额称为全国全量市场规模。用业务词扩展 ESG，含节能改造、污染治理、环保工程，不仅查标题含“ESG”的项目。
2. **发现并核验公告。** 优先采购方、政府采购、公共资源交易及国企采购官方原文。媒体和聚合站用于发现；访问正文及可取得的原始附件，核对公告类型、主体、日期、标包、金额和状态。来源不可访问时保存线索与失败原因。
3. **保存证据与项目快照。** 输出 `records` 和 `sources` 的 JSON，按数据契约保存原文链接、定位、摘录、时间、金额原文及筛选理由。项目编号、采购人、标包和采购轮次要稳定；不确定身份的项目保留需核实状态，不能仅因标题相近合并。
4. **归一并检查。** 用 `scripts/procurement_data.py normalize` 处理明确的金额、关联和版本。查看 `issues`、`needs_review`、`conflicts`，回到原文修复重要问题，再归一。程序不会替你判断 ESG 相关性或填补公告缺失事实。
5. **分析或监控。** 历史模式运行 `stats`，按服务、软件数据、设备工程、混合项目分层，并按地区、采购方、季度及联合中标主体分析。监控模式运行 `monitor`，由其比较版本及生成可追溯的日报底稿；在底稿上补充资格、技术需求、适配理由和行动建议。
6. **完成报告与核验。** 结论对应明细和原文；重点金额、撤销更正和核心结论逐条核查。报告包含覆盖局限、金额缺失、未核实线索及访问失败。统计只能说明取得的公开样本。
7. **交付与通知。** 保存完整 Markdown、来源台账、归一明细和可复算统计，向当前聊天展示摘要与绝对路径链接。已安装时公共入口是 `python scripts/notify_report.py --report <md> --title <title> --summary-file <md> [--report-id ID] [--config PATH] [--state PATH]`；默认 preview，缺失配置默认 Codex 内部。只有已有安装及投递授权时加 `--send`。该入口不存在时完成本地交付并说明状态。可配置邮件、企业微信和钉钉单选或多选，机器人发适配摘要、邮件附完整报告；外部渠道不能把本地磁盘路径当作可访问链接。安装时再收集渠道、秘密引用与推送时间，不能把安装 Skill 当成创建自动化。

## 金额与项目边界

- 预算、最高限价、候选报价、确定成交价、合同价、单价及框架上限分别保存；候选人与未确定总额的框架协议不进入确定成交总额。
- 成交统计仅使用已核验、状态确定、身份清楚且无未解决冲突的 `award` 金额。合同金额另列，不与同项目成交金额相加。
- 保留金额原文、币种、单位、税口径、合同期及核算范围。用 Decimal 归一，不使用浮点、不暗自换汇、不将缺失当零、不自行年化。
- 一个标包有多个联合中标人时只计一次；供应商分析使用完整联合主体，不把金额复制给每家供应商。
- 多标包分别提取。未披露分项金额的混合项目单列，不分摊给服务或工程。没有可核实标包划分时不把总额重复复制到标包。
- 更正、撤销、终止和重招保留版本；不同采购轮次不能因编号复用而误合并。稀疏更正需结合其明确引用的原公告建立带证据的完整快照，不能凭缺失字段猜测继承关系。

## 本地辅助入口

以下是标准库 Python 脚本；`<skill>` 指当前 Skill 的实际绝对目录，`<out>` 指用户输出目录。先运行 `--help` 核对参数。

```text
python "<skill>/scripts/procurement_data.py" window --as-of 2026-11-25
python "<skill>/scripts/procurement_data.py" normalize --input "<out>/evidence.json" --output "<out>/normalized.json"
python "<skill>/scripts/procurement_data.py" stats --input "<out>/normalized.json" --output "<out>/statistics.json" --markdown "<out>/statistics.md" --as-of 2026-11-25
python "<skill>/scripts/procurement_data.py" monitor --input "<out>/normalized.json" --state "<out>/monitor-state.json" --output "<out>/daily.md" --as-of 2026-11-25
```

`stats` 支持 `--from` / `--to` 及 `--date-basis published_date|award_date`，默认公告发布日期；更正不移动原成交公告统计日期。`monitor` 先原子写出本地日报，再更新状态；`--dry-run` 写日报但不更新状态。真实报告需要研究判断，脚本输出的统计表及日报只是底稿。连续监控应在同一运行身份下复用同一状态文件，避免并发写入；断档时根据返回的 `query_start` 补查，来源失败期间不能宣称覆盖连续。
