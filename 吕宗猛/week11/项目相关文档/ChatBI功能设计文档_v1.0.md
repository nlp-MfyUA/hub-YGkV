### 1.3 术语

| 术语 | 定义 |
| --- | --- |
| 业务库 | 现有单个 MySQL 数据库；ChatBI 仅使用受限只读账号查询 |
| 应用存储 | 保存 ChatBI 自身用户、权限、配置、元数据、会话、历史等信息，不等同于业务库 |
| Schema | 表、字段、类型、注释、主外键及索引等结构描述 |
| 查询条件 | 用户明确指定或追问继承的指标、时间、组织、过滤、分组及排序 |
| 权限约束 | 服务端根据当前身份强制施加的访问限制，不属于可随意修改的用户条件 |
| 查询任务 | 一次提交及其有限内部尝试形成的可追踪任务，有独立任务 ID |
| 查询版本 | 条件变化或重新执行产生的独立版本，不覆盖此前成功版本 |
| 结果快照 | 某次查询在某时刻形成的受控数据副本，不保证反映当前业务数据 |
| 结果摘要 | 受控汇总、单位、条件及展示元信息，不等同于原始明细 |
| 成功查询基准 | 当前会话最近一次通过权限处理且结果可用的成功查询版本 |
| 授权共享 | 给指定登录用户访问共享内容的资格，不授予额外业务数据权限 |

## 2. 项目背景、目标与第一版边界

### 2.1 背景与目标

【已确认；REQ-01–REQ-06】业务数据位于单个 MySQL，约 20–100 张表，涉及多个业务模块；初期约 10–50 名用户。业务人员通过自然语言获取自然语言回答、表格和图表，不需要查看或编辑 SQL。

平台目标是构建“问题理解 → 相关 Schema 检索 → 候选 SQL → 程序化安全与权限校验 → 受限查询 → 脱敏展示 → 历史与审计”的完整链路，而非让模型直接执行数据库操作。

### 2.2 第一版纳入范围

| 功能域 | 第一版内容 | 关联需求 |
| --- | --- | --- |
| 身份与权限 | 独立用户管理、管理员开通、部门和角色、用户权限例外、表/字段/行权限及脱敏 | REQ-03、REQ-13–REQ-18 |
| 问数与对话 | 自然语言查询、动态 Schema、多轮条件继承与纠正、最近成功结果引用、取消及有限重试 | REQ-04–REQ-12 |
| 展示与导出 | 回答、表格、图表、普通用户隐藏 SQL、受控 Excel 导出 | REQ-05、REQ-06、REQ-43 |
| 历史与共享 | 长期个人历史、手动删除、查看与重查、指定用户共享、快照/重查双模式、访问重新授权 | REQ-19–REQ-24 |
| 业务语义 | 自动采集结构、批量导入与手工维护、术语、外键关联、核心指标、主题审核发布、每日同步 | REQ-25–REQ-30 |
| 系统管理 | 按用途配置模型、主备切换、后台密钥、双类审计、限流、监控与告警 | REQ-31–REQ-36 |
| 运维与验收 | Linux + Compose、内网 HTTPS、应用数据备份、初始性能目标、云端数据边界、全面验收 | REQ-37–REQ-42 |

### 2.3 明确不纳入

- 修改业务库的数据写入、更新、删除、DDL 或自动化业务操作。
- 普通用户任意 SQL 编辑器、绕过校验的自定义 SQL 执行入口。
- 多数据源、跨数据库查询、未经确认的预测或因果分析。
- 持链接即可访问的公开共享、部门共享、自助注册或企业 SSO 集成。
- 自定义本人/部门之外的行级范围、模型自动推测后直接执行的无外键关联。
- 定时自动导出、原始敏感值无授权导出，以及默认向云端发送原始明细。

## 4. 第九轮确认总结

### 4.1 已确认需求

【已确认；REQ-37–REQ-42】Linux + Docker Compose 部署；内网通过反向代理使用 HTTPS；备份完整应用数据；约 10–50 人的常规查询目标 5–10 秒，复杂查询可更久并以测试为准；云端不默认接收原始明细；上线全面验收功能、安全、权限、脱敏、导出、审计、模型切换、性能与恢复。

### 4.2 暂定方案

- 应用、反向代理、必要持久化存储构成轻量部署，暂不强制微服务拆分。
- 测试使用合成或脱敏业务数据；生产业务库只读接入，应用写入使用独立凭据。
- 备份加密并保存在受控独立位置，包含配置版本与恢复所需密钥材料的安全托管。
- 性能分解记录排队、Schema 检索、各模型调用、SQL、结果处理及总体耗时。
- 云端调用前执行最小化、脱敏和字段发送检查；禁止发送的数据由程序拦截。
- 按第 22 节测试矩阵形成证据包，P0 安全事项通过后再开展有限用户试点。

### 4.3 待决策事项

部署资源与镜像策略（DEC-21）；备份频率、期限、RPO/RTO 和恢复演练（DEC-19）；常规/复杂问题分类、并发和 P95 口径（DEC-21）；供应商区域与保留条款及摘要风险策略（DEC-07）；SQL 正确率及完整验收阈值（DEC-22）。“复杂可更久”不取消查询硬超时和资源保护。

## 5. 用户角色、业务场景与功能地图

### 5.1 角色模型

【已确认；REQ-03、REQ-13、REQ-14】由管理员创建用户并分配部门和角色，以角色模板为主，支持用户例外。具体角色名称、职责拆分与多角色能力未定。

【暂定方案】以下为职责而非必须预置的四个角色：

| 职责 | 操作范围 | 边界 |
| --- | --- | --- |
| 普通业务用户 | 问数、追问、查看本人可访问历史、共享、在授权下导出 | 不查看 SQL，不配置权限、不越权访问对象 |
| 系统管理职责 | 账号、部门、角色、模型、资源、备份和监控 | 管理系统不自动取得全部业务数据权限 |
| 权限/语义管理职责 | 权限模板、敏感规则、身份字段映射、术语、指标、主题 | 是否与系统管理员分离见 DEC-02 |
| 审计职责 | 查询审计、安全事件、管理变更 | 审计可见范围独立授权；不默认查看原始明细和密钥 |

### 5.2 典型场景

| 场景 | 用户目标 | 关键控制 |
| --- | --- | --- |
| 部门统计 | “统计本部门上季度报销金额” | 部门映射、时间口径、指标定义、行权限 |
| 连续追问 | “再按员工分组” | 继承指标、时间与部门；新增分组后重新授权 |
| 条件纠正 | “不是上季度，是本季度” | 替换而非叠加时间；展示前后变化 |
| 结果引用 | “这些结果里金额最高的是谁” | 最近成功结果、可用性检查、字段和行权限 |
| 个人回顾 | 查看历史或重新执行 | 显示原时间和条件；重查生成新版本、使用当前权限 |
| 指定用户共享 | 分享统计快照或查询定义 | 接收者身份校验和当前权限，不借分享者权限查询 |
| 元数据变更 | 每日同步后字段失效 | 保留业务说明、标记受影响对象、不执行失效查询 |
| 模型故障 | SQL 生成主模型不可用 | 有限切换；备用输出仍完整校验 |

示例中的表、字段、指标名称只用于说明，不视为业务库已存在或口径已确认。

## 6. 页面结构与交互约定

【暂定方案；支持 REQ-04–REQ-36】页面设计以功能权限决定入口，服务端仍独立校验，不靠隐藏按钮授权。

| 页面 | 主要区域及操作 | 空状态/异常行为 |
| --- | --- | --- |
| 登录页 | 登录标识、密码、错误提示 | 账号或密码错误统一提示；锁定和重置策略见 DEC-01 |
| 问数工作台 | 已发布主题、问题输入、会话消息、条件摘要、任务状态、结果卡片 | 无主题可直接输入；无权限数据不泄露结构；处理中可取消 |
| 结果卡片 | 回答、表格、图表、执行时间、数据范围、截断提示、导出与共享 | 空数据不等于零；摘要生成失败可展示已授权表格 |
| 个人历史 | 列表、时间/状态筛选、详情、重查、删除 | 无访问权限显示受限，不展示旧敏感回答 |
| 我的共享 | 发出的共享、收到的共享、模式及状态 | 过期/撤销/源记录删除的处理见 DEC-10 |
| 用户/部门/角色 | 账号维护、角色模板、用户例外 | 冲突或映射缺失不得静默扩大授权 |
| 权限与敏感策略 | 资源清单、字段用途、固定范围映射、脱敏配置 | 校验错误不发布新版本；展示生效影响 |
| 元数据与语义 | 同步状态、结构差异、导入预览、术语、指标、主题审核 | 失效对象标记；导入不覆盖未明确允许的内容 |
| 模型管理 | 模型用途、主备、启用、连接测试、密钥替换 | 只显示掩码/已配置状态，故障有可追踪提示 |
| 审计与监控 | 审计检索、指标、告警、资源配置 | 未授权日志不可见，日志值脱敏 |

交互约定：任务提交后立即返回标识和阶段；重复点击不创建重复内部执行；条件变化先显示摘要，再启动查询，不额外强制一次确认，除非存在歧义或需用户澄清。适配桌面及窄屏布局的具体视觉稿不属于本次交付。

| 项目 | 设计 |
| --- | --- |
| 参与角色/前置 | 管理员具备用户维护权；部门、角色已存在且有效 |
| 输入 | 唯一登录标识、显示名称、部门、角色、账号状态、初始化凭据方式 |
| 主流程 | 校验标识与归属 → 创建用户 → 赋予模板 → 建立业务身份映射 → 审计 → 交付账号 |
| 输出 | 用户 ID、开通状态；一次性初始化方式，不返回已有密码 |
| 异常 | 重复标识、无效部门/角色、身份映射缺失返回明确错误；映射缺失时可登录管理个人信息但不得查询相关数据 |

登录使用服务端校验密码哈希，建立受控登录态；退出使登录态失效。不得在查询请求中信任客户端自报的用户/部门。登录失败、重置、启停记录审计，提示不得暴露用户是否存在。密码复杂度、锁定、会话时限、首次修改及重置渠道见 DEC-01。

### 7.2 用户维护与禁用

【暂定方案】支持列表、搜索、修改显示信息、调整部门/角色和启停。部门或角色变更触发权限版本更新；后续请求读取当前身份。禁用用户后阻止新请求，并对尚未交付的查询/导出重新校验，尽可能终止任务；不能撤回此前已经下载的文件。账号删除、注销方式及运行中任务撤销细节见 DEC-05。

### 7.3 部门与角色

【暂定方案】部门维护名称、状态和业务部门映射；第一版按单部门、通常单角色简化界面。不自动把下级部门纳入“所属部门”，不推定支持部门树授权。删除仍被用户或规则引用的部门/角色时拒绝删除或先迁移；不得用删除造成权限回退到全量。多角色与职责拆分见 DEC-02。

## 8. 权限、行级范围与敏感字段管理

### 8.1 权限配置与合成

【已确认；REQ-14–REQ-18】角色模板为主、单用户例外；模块/表、字段与行级权限；固定本人及所属部门；越权拒绝并审计；保存立即生效。

【暂定方案】权限保存流程：资源存在性检查 → 字段用途及行映射校验 → 检查例外冲突 → 原子发布新权限版本 → 使缓存失效 → 记录变更人和影响资源。失败则保留原有效版本，不部分发布。

| 维度 | 建议配置内容 | 执行约束 |
| --- | --- | --- |
| 模块/表 | 可查询模块、表及允许访问路径 | 所有引用含 JOIN、子查询、CTE 等均需授权 |
| 字段 | 查询使用、原值展示、脱敏展示、过滤、分组、排序、JOIN、导出、云端发送 | 展示权不自动推导所有用途权；防止间接推断 |
| 行级 | 登录用户到业务人员标识、所属业务部门及各表路径 | 范围固定，不允许管理员通过界面扩展到任意部门 |
| 用户例外 | 资源、操作、允许/拒绝及理由 | 与模板冲突时不静默执行，优先级见 DEC-03 |
| 敏感策略 | 字段类别、掩码、原值/脱敏/禁止、发送策略 | 数据库结果、图表、摘要、历史、导出统一执行 |

用户例外是否可扩大模板权限尚未确认；暂定冲突“默认拒绝并提示管理员”，待 DEC-03 定案后再实现统一合成规则。管理权、共享权和业务数据权分别检查。

### 8.2 固定本人及所属部门

【已确认；REQ-15】不提供自定义数据范围。本人和部门来自服务端身份映射，不来自问题或模型生成内容。

【待决策；DEC-04】“本人及所属部门”在具体表上是并集、交集还是按表选择，以及是否包括本人在其他部门的历史记录，材料未给出。所属部门不默认包含下级部门或多个部门。

【暂定方案】每张可查询业务表明确身份字段、部门字段或已验证关联路径，并有测试样例。公共字典/无部门表也需明确分类，不自动设为全员可见。无法可靠映射或约束的表拒绝查询；问题可缩小范围，但不能移除服务端固定约束。关联、聚合、UNION、子查询等受支持语法需证明权限完整，不支持则拒绝。

### 8.3 敏感字段与越权请求

【已确认；REQ-16、REQ-17】无原值权限时展示脱敏值，禁止原始值导出；越权字段或范围拒绝并记录审计。

【暂定方案】区分两类请求：

- 允许访问但只允许脱敏展示的字段：如权限允许查询手机号掩码，服务端仅输出掩码。
- 完全无权使用的字段/用途或越权行范围：拒绝该项请求，不自动删字段后假装完成原问题；暂定整次查询拒绝，告知调整问题，部分拒绝交互见 DEC-06。

通过无权字段精确过滤、排序、分组、连接或反复计数也可能泄露原值，不能仅通过隐藏表格列处理。字段掩码类型、小样本聚合限制和用途粒度见 DEC-06、DEC-07。敏感原值若为本地处理所必需，仅存在受控执行区域，不进入普通日志、客户端或云端调用。

### 8.4 权限变更检查点

【已确认；REQ-18、REQ-24】保存立即生效；后续查询、历史、共享与下载重新校验。

【暂定方案】

| 检查点 | 行为 |
| --- | --- |
| 请求受理、SQL 执行前 | 校验最新身份、权限及版本，排队期间变化也要复核 |
| 查询结果发布、摘要生成前 | 再检查；权限收缩则安全重算/重裁剪或丢弃，不能按旧权限交付 |
| 历史/共享打开 | 校验所有权或共享资格，再检验当前资源、字段、行权限及摘要安全 |
| 导出生成及下载 | 分别检查当前权限；生成时授权不替代下载时授权 |
| 会话追问/缓存读取 | 不沿用旧权限缓存；缓存键至少含用户、权限版本和语义版本 |
| 运行中权限撤销 | 标记结果不可发布，尽可能停止任务；取消能力不足仍不得泄露结果 |

生效时点建议定义为服务端权限发布事务提交完成。已传送到用户端或模型供应商的数据无法追溯撤回；因此需在外发和交付前再次检查，并明确下载管理边界。运行中撤权、长下载连接及缓存策略详见 DEC-05、DEC-13。

## 9. 自然语言问数与 Schema 检索

### 9.1 提交和问题理解

【已确认；REQ-04、REQ-05】自然语言生成 SQL 并按授权展示结果，动态选择相关结构和注释。

【暂定方案】

| 项目 | 设计 |
| --- | --- |
| 前置 | 用户有效、具备查询权、数据源及相关元数据可用、资源配额可用 |
| 输入 | 问题、会话 ID、可选已发布主题、客户端幂等键；不接收用户自行声明的授权范围 |
| 主流程 | 认证限流 → 意图识别/条件归一 → 歧义澄清 → 检索相关 Schema 与指标 → 最小化模型请求 → 候选 SQL → 全部安全权限检查 → 受限执行 → 脱敏展示与历史审计 |
| 输出 | 任务 ID、查询版本、条件摘要、阶段状态、授权结果或安全错误 |
| 异常 | 空问题/过长问题、歧义、无可用元数据、未授权、模型不可用、资源超限、SQL 不支持等分类处理 |

生成模型只提供候选 SQL，不负责认证、授权或批准危险语法。用户问题、元数据注释、模型响应均视为不可信内容；其中“忽略权限”等指令不能改变系统规则。

### 9.2 相关结构选择

【暂定方案】检索链路先按用户可访问模块筛选，使用中文别名、术语、表字段注释匹配候选，再补充必要外键路径、核心指标口径和时间/状态字典。仅发送与当前问题相关且获准的结构，不把全部 20–100 张表默认放进提示词。

优先结构化/关键词检索；向量或混合检索是技术选型而非已确认功能。记录检索候选、命中术语、指标及元数据版本用于后台排查，但普通用户不见内部 SQL 和敏感结构。若缺少可验证关联，不用模型猜测后直接执行，提示问题暂不支持。

### 9.3 指标与歧义

【已确认；REQ-28】核心指标使用统一定义，临时分析可动态生成。

【暂定方案】“订单金额”等已有核心指标始终使用有效口径，不能在不同问法中任意切换。时间字段、单位、状态过滤、软删除条件应关联语义定义。临时指标标记为临时，不自动写入核心库；计算表达式仍经过 SQL、权限及资源校验。

金额含义、部门归属、时间字段或“有效订单”不明确时，返回可理解的澄清问题，不猜测后执行。相对日期建议以应用配置业务时区和问题提交时间解析，并在重查时明确是否重新计算，见 DEC-08。

## 10. 多轮上下文、条件继承、纠正与澄清

### 10.1 上下文对象与固定窗口

【已确认；REQ-07–REQ-11】固定窗口最近几轮；追问继承已有条件，仅修改明确部分；纠正先展示变更摘要；默认最近成功结果。

【暂定方案】模型消息窗口与结构化状态独立：消息只保留最近 N 轮；结构化查询状态保存当前成功基准、条件、指标、分组、排序、语义版本、时间解析和结果摘要。淘汰早期模型消息不删除长期个人历史，也不无限拼接全部历史到提示词。

N、轮次定义、单轮长度、摘要大小、状态存储及会话恢复期限见 DEC-09。窗口中较早权限信息不作为授权依据。

### 10.2 条件合并

【暂定方案】用户条件与权限约束分别保存；对用户条件执行增/改/删补丁，权限约束每次重新生成。

| 用户表达 | 继承/修改行为 | 摘要示例 |
| --- | --- | --- |
| “再按员工分组” | 保留指标、时间、已有筛选，增加分组 | 新增：按员工分组 |
| “不是上季度，是本季度” | 替换时间，不同时保留两段冲突时间 | 时间：上季度 → 本季度 |
| “只看已完成” | 增加状态过滤，其他条件不变 | 新增：状态为已完成 |
| “取消状态筛选” | 删除用户状态条件，保留强制业务/权限规则 | 移除：用户状态筛选 |
| “换成客户数” | 替换指标；检查旧条件、维度是否仍适用 | 指标变化；不兼容条件需澄清 |
| “看所有部门” | 不得移除固定授权范围 | 拒绝越权范围，提示可查询范围 |

展示“原值 → 新值”与保持项；摘要是解释变化，不代表额外扩大授权。无明确新条件不凭空增删。若新问题明显切换主题，暂定先确认是否另开查询，不把不兼容旧条件强行带入。

### 10.3 成功基准、失败与恢复

【暂定方案】“上一轮条件”一般来自最新成功状态；若上一轮为失败/取消或待澄清，单独保留候选条件但不覆盖成功基准。用户明确修正失败任务时可参考其候选条件并显示来源，否则默认最近成功版本，无法判断时澄清（DEC-09）。

结果引用先检查基准归属、可用性、当前权限及元数据。可在本地对已授权完整结果做简单再整理；结果被截断时不能声称覆盖全部业务数据，需基于条件安全重查。快照不可用或权限不能安全证明时提示重查，不使用失效结果或跨会话用户数据。

恢复旧会话后重新加载有效权限，显示历史数据时间；无法恢复结果仍可保留问题和条件。摘要失败但授权表格已交付可视为成功并带警告；取消中的新任务暂定不更新成功基准，即使数据库刚完成也丢弃尚未交付结果。

## 11. 查询任务状态、取消、修正与重试

### 11.1 状态与结果一致性

【暂定方案；支持 REQ-12、REQ-35】任务 ID 稳定，内部尝试有独立 attempt ID。建议状态：

```text
ACCEPTED -> QUEUED -> UNDERSTANDING -> RETRIEVING -> GENERATING
  -> VALIDATING -> EXECUTING -> PROCESSING -> ANSWERING -> SUCCEEDED

中间状态 -> NEEDS_CLARIFICATION / REJECTED / FAILED / TIMED_OUT
中间状态 -> CANCEL_REQUESTED -> CANCELLED
```

| 状态 | 用户含义 | 后续规则 |
| --- | --- | --- |
| NEEDS_CLARIFICATION | 需要补充条件，未执行 SQL | 答复后形成关联新版本，重新授权 |
| REJECTED | 安全、权限或策略拒绝 | 不自动修正绕过，可修改问题重新提交 |
| FAILED / TIMED_OUT | 允许的重试耗尽或达到预算 | 保留追踪 ID、错误类别，不暴露内部堆栈 |
| SUCCEEDED | 可用授权结果已形成 | 可带摘要/图表降级警告；空结果也可成功 |
| CANCEL_REQUESTED | 已接收取消，正在停止 | 停止后续调用、禁止发布迟到结果 |
| CANCELLED | 应用逻辑已停止 | 数据库物理停止情况单独反馈，不虚报已中断 |

状态变更原子化；重复取消幂等；终态不得被迟到响应覆盖。超时/断线不能导致后台无限执行，资源清理情况须可观察。

### 11.2 取消与停止生成

【已确认；REQ-12】支持取消 SQL 查询和停止后续生成。

【暂定方案】仅任务本人或获授权运维可取消。收到取消后停止排队、重试、主备新调用和结果生成；模型响应若不能中断则丢弃。执行器验证任务与数据库连接/执行句柄绑定后尝试中断，避免连接复用后误取消他人查询。

| 时机 | 用户反馈与执行行为 |
| --- | --- |
| 排队或生成 SQL | 停止本任务后续阶段，显示已取消 |
| 数据库执行 | 先显示正在停止；驱动确认后记录物理取消结果 |
| 驱动不支持立即中断 | 显示应用已停止、数据库可能继续至硬超时；隔离仍运行的连接，不作为空闲连接复用 |
| SQL 已完成、回答未完成 | 停止后续生成，丢弃尚未发布的新结果；此前已交付内容无法撤回 |
| 任务已终态 | 返回当前终态，不伪造新的取消成功 |

MySQL 只读账号不为取消无条件授予高权限；可使用驱动取消或受控机制，由 DBA 验证账号权限与连接安全。取消确认时间、强制终止支持和前端断线策略见 DEC-12。

### 11.3 错误分类与有限尝试

【已确认；REQ-12】失败自动重试有限次数后再提示；B0 要求每次修正重新校验。

【暂定方案】区分传输重试、SQL 修正和主备切换，但由统一任务总次数/总耗时预算约束，不使三种机制相乘形成无限调用。

| 错误类别 | 建议动作 | 禁止行为 |
| --- | --- | --- |
| 模型网络短暂故障、可恢复服务错误 | 退避重试、必要时按模型路由切备用 | 无限循环、取消后继续重试 |
| 模型认证错误/配置无效 | 停用故障配置并告警，是否备用按配置处理 | 重复使用同一无效密钥请求 |
| 普通 SQL 语法/有效字段引用错误 | 筛选安全错误信息，有限修正，再从头校验 | 将凭据、原始结果或越权资源提示给模型 |
| 权限拒绝、危险 SQL、不支持语法 | 直接拒绝或人工调整 | 通过删除权限条件/切模型规避 |
| SQL 超时、成本超限、取消、配额超限 | 结束或提示缩小分析范围 | 自动扩大超时/行数或连续重跑重查询 |
| 数据库短暂断连 | 确认旧执行结束且预算允许时有限重试 | 执行状态不明时启动并行重复 SQL |
| 回答/图表生成失败 | 展示已授权表格及本地说明，记录降级 | 重跑已成功 SQL 或编造结论 |

修正次数、退避、可重试代码、总预算及备用切换关系见 DEC-11、DEC-15。重新点击“重试”创建关联新任务，仍重新授权和限流，不沿用失效成功结论。

## 12. 回答、表格、图表及受控 Excel 导出

### 12.1 统一结果契约

【已确认；REQ-05、REQ-06】自然语言、表格、图表；普通用户不展示 SQL。

【暂定方案】结果包括 query ID/版本、数据查询时间、条件摘要、列名及类型/单位、授权行、返回行数、截断标志、警告、图表配置和回答。总记录数仅在安全且成本允许时计算，不能把 LIMIT 后行数当成总量。

先本地完成类型规范化和脱敏，再生成图表和模型摘要。图表、提示气泡、回答、浏览器接口响应不得存在表格中已隐藏的敏感原值。前端不是脱敏执行边界。

### 12.2 表格、图表与自然语言

【暂定方案】

- 表格显示中文业务列名、单位、空值、日期；金额使用确定精度，零和空值区分。
- 暂建议柱形用于分类、折线用于时间序列、饼图用于有限类别占比；具体图表类型、切换和交互见 DEC-13。不适配时只展示表格。
- 对截断/抽样/快照显示明确标签，不能把部分结果称为完整汇总；汇总统计由受限 SQL 或本地完整授权结果计算，不能交给模型凭空计算。
- 空结果提示“当前条件下无记录”，不直接解释为指标等于零；业务口径允许时才明确零。
- 回答引用条件、时间、指标单位和可验证结果；发现与授权结果不一致时降级本地说明，不输出虚构数据。
- 分页如用于固定结果只操作已授权快照；若重新访问业务库则每页重新授权并标注查询一致性，不默认提供无成本的全量翻页。

### 12.3 受控 Excel 导出

【已确认；REQ-16、REQ-24、REQ-43】设计 Excel 导出，禁止无原值权限的敏感原值导出，访问文件前重新校验。

【暂定方案】

| 项目 | 设计 |
| --- | --- |
| 前置 | 用户当前具备导出操作权、来源结果可访问且处于可导出状态 |
| 输入 | 查询版本、允许选择的列；不接受客户端上传原始数据后直接生成 |
| 主流程 | 当前权限校验 → 解析数据来源/是否截断 → 应用字段和行规则 → 配额检查 → 异步生成 → 安全存储 → 下载前再次授权 |
| 输出 | 导出任务 ID、处理状态、文件名称、生成时间、数据范围与受控下载入口 |
| 异常 | 来源过期、权限变化、超额度、取消、文件生成失败提示可追踪原因；不交付部分未验证文件 |

第一版暂定只导出当前可见、已授权的结果范围，不自动去掉 LIMIT 重新导出全量；若将来允许大结果导出需单独额度、执行和审计设计（DEC-14）。文件标注条件、时间、单位、截断及脱敏信息，避免敏感原值进入隐藏列或工作表元数据。

导出生成与下载分别检查权限；如果权限收缩后无法安全证明旧文件仍可访问，则拒绝下载，要求重新生成。下载走认证授权的服务端流或等效即时鉴权方式，不使用可长期绕过权限检查的裸存储链接。防止把以 `=`、`+`、`-`、`@` 等开头的不可信文本作为 Excel 公式执行，区分数字负值与文本。

文件期限、行数/字节限制、并发、格式样式和共享接收者能否导出见 DEC-14。已下载到本地的文件无法被系统撤回，需告知管理边界。

## 13. 历史保存、复用、快照及指定用户共享

### 13.1 个人历史与查看

【已确认；REQ-19–REQ-21、REQ-24】长期保存，用户手动删除；保存问题、回答、查询条件、结果摘要和执行状态；可查看结果也可重查；访问前重新授权。

【暂定方案】历史列表默认仅本人；查询详情保存时间、任务和版本、条件、指标口径、结果摘要、状态、必要警告。问题文本、旧回答及摘要也可能含敏感内容，当前权限不足时不能只隐藏表格而继续显示完整旧回答。

历史查看显示原执行时间和“历史结果”，不自动查询当前业务库；重查是显式操作。摘要长期保存不代表全明细无限保存，受控结果快照单独存储。快照过期/丢失时显示可授权摘要及“明细不可用，可重查”，不得宣称保留了完整结果（DEC-10）。

### 13.2 基于历史重新执行

【暂定方案】重新执行使用原问题、结构化条件作为参考，重新解析当前权限、Schema 和核心指标，生成新任务/版本，保留与原记录的关系，不直接执行历史 SQL 并复用旧授权结论。

固定日期建议保留原日期；“本月”等相对日期由用户选择或明确提示使用当前日期，不能默默改变。指标版本和结构变化时展示差异；无法匹配已删除字段则要求澄清或安全失败（DEC-08、DEC-17）。

### 13.3 指定用户共享与模式

【已确认；REQ-22、REQ-23】只能指定用户；分享者选择快照或重新查询，不采用公开链接。

【暂定方案】共享流程：分享者确认源记录可访问 → 选择有效用户与模式 → 校验共享操作权 → 创建受控授权 → 接收者登录打开 → 校验共享资格及当前数据权限 → 按模式处理 → 审计。

| 模式 | 展示/执行行为 | 权限与限制 |
| --- | --- | --- |
| 结果快照 | 展示源查询时刻的授权快照和条件 | 分享者当前权限与接收者当前权限均校验；快照不产生额外授权 |
| 接收者重新查询 | 展示获准查询定义，由接收者显式发起新查询 | 使用接收者身份与当前权限；结果可能不同，不能借用分享者连接/身份 |

快照可安全裁剪时才裁剪。普通明细若缺少可信行归属信息则拒绝；聚合、排行榜、去重、小样本和模型回答常已含被撤权数据，不能简单按列隐藏/按行过滤即断言安全。无法证明整份快照与摘要均在接收者范围内时拒绝快照展示，提示选择重查模式，但不擅自把模式替换后静默执行。

“重查共享”不自动放宽原问题范围；若原定义明确指定接收者无权部门则拒绝并提示调整，不悄悄换成接收者部门后声称回答了原问题。语义适配规则见 DEC-10。

### 13.4 撤销、删除与访问撤权

【暂定方案】提供撤销入口，撤销后阻止新访问；源历史删除同时撤销其共享、失效快照/缓存/文件引用，可清理对象异步处理。具体同步行为与保留法规见 DEC-10、DEC-18，未确认前不写为既定业务规则。

用户删除历史不默认删除独立审计日志；共享接收者不删除源记录。系统只控制后续访问，无法撤回已查看或下载的数据。删除请求使用幂等逻辑和引用检查，避免留下仍可访问的孤立文件入口。

## 14. 元数据、术语、外键关联、指标与主题

### 14.1 自动采集与维护

【已确认；REQ-25、REQ-30】自动读结构，支持批量导入、手动维护；每日同步并支持手动触发。

【暂定方案】物理信息与业务信息分离：物理表/列名、类型、注释、主外键、索引来自 MySQL；业务别名、解释、敏感策略、指标和主题由应用维护。手工维护不修改业务库 DDL，不允许通过导入虚构实际不存在的可执行字段。

| 功能 | 前置/输入 | 主流程与输出 | 异常规则 |
| --- | --- | --- | --- |
| 自动采集 | 管理权限、元数据读取连接 | 读取结构 → 比较差异 → 生成版本和同步报告 | 失败保留旧有效版本，禁止发布半套结构 |
| 手工维护 | 已存在资源 ID、业务说明 | 校验长度/冲突 → 保存业务语义 → 审计 | 保留物理来源，业务说明不能覆盖物理标识 |
| 批量导入 | 管理权限、模板文件 | 上传校验 → 预览新增/修改/错误 → 确认 → 应用 → 报告 | 超大小、重复、未知字段、歧义条目明确拒绝 |
| 定时/手动同步 | 调度配置或人工触发 | 防重入 → 读取差异 → 原子更新物理版本 → 标记影响 → 记录 | 同步失败告警，不擦除业务说明 |

Excel/CSV 是否均支持、导入模板、覆盖策略、整批原子或部分成功见 DEC-16。暂定先预览、默认整批验证通过后发布，减少半成功歧义。同步时间和时区见 DEC-17。

### 14.2 中文术语

【已确认；REQ-26】管理员维护中文别名、同义词与解释。

【暂定方案】术语包含名称、同义词、业务模块、对应表/字段/指标、说明和状态。相同“金额”可在不同模块映射不同指标，冲突时要求业务限定，不由模型随机选择。普通用户只使用有效条目，模型发现的新词不自动发布。

### 14.3 外键关联

【已确认；REQ-27】自动识别数据库外键辅助 JOIN。

【暂定方案】采集两端表字段、键与方向；仍需检查表/字段授权、基数、行权限传播和聚合重复计数。物理外键存在不意味着所有关联业务语义均正确或查询均允许。

无外键表第一版默认不开放推测 JOIN，可进行独立授权查询。管理员手工补充关联能力见 DEC-17，不擅自纳入已确认。外键删除或字段变更使相关路径失效，不继续使用缓存关系。

### 14.4 核心指标与临时分析

【已确认；REQ-28】核心指标统一定义，临时动态分析仍允许。

【暂定方案】指标字段包括业务名、定义、计算表达式、粒度、单位、时间字段、过滤、状态/软删除规则、依赖表及权限、版本。指标表达式不可作为管理员任意 SQL 绕过入口，需程序解析、资源和权限检查。

版本管理、审批及变更日志是否完整建设见 DEC-17。至少记录本次使用的有效口径，以便解释历史与重查差异。临时指标不自动覆盖核心指标。

### 14.5 主题建议、审核和发布

【已确认；REQ-29】系统提供初始主题建议，管理员审核后发布维护。

【暂定方案】建议/草稿 → 待审核 → 已发布 → 停用；配置名称、模块、说明、示例问题、依赖指标。审核者检查口径、权限及示例查询，不允许模型建议自动对用户可见。用户只见已发布且当前可访问主题。依赖字段删除时暂定自动标记不可用并禁止相关执行，自动停用业务策略见 DEC-17。

## 15. 模型按用途配置、密钥及故障切换

### 15.1 模型配置

【已确认；REQ-31–REQ-33】多个模型按用途配置；连续失败自动切备用，恢复后可切回；后台录入密钥仅显示脱敏值。

【暂定方案】用途示例：问题理解、SQL 生成、辅助 SQL 评估、回答总结。辅助模型评估不能替代程序化 SQL 校验。每个配置建议有服务商、Endpoint、模型名、用途、启用状态、超时、调用上限、采样参数、版本和密钥引用；各用途是否分别配置主备见 DEC-15。

管理员录入 → 地址及配置校验 → 用不含业务数据的最小请求测试 → 保存密文/密钥引用 → 绑定用途 → 审计。禁用仍被路由使用的模型需提示影响，未配置可用 SQL 生成模型则阻止新问数，不能无约束改路由。

### 15.2 API 密钥保护

【暂定方案】浏览器只提交新密钥或执行替换/删除，不读取已存明文；详情响应只返回“已配置”及固定掩码，空值不默认为删除。服务端加密存储，主密钥不与密文放在同一明文配置表中；解密仅限模型调用的受控路径。普通日志、审计变更、错误堆栈、导出及备份目录不泄露明文。

后台 Endpoint 必须验证 HTTPS 和允许的目标，限制重定向、回环/元数据服务等非授权地址，防止配置页面成为 SSRF 或密钥外传入口。允许地址策略、加密算法、主密钥来源、轮换与恢复见 DEC-15。连接测试失败不得回显请求认证头。

### 15.3 主备故障状态

【暂定方案】路由健康状态为正常、降级、熔断、恢复观察。计数只统计约定的模型服务故障，不把权限拒绝、用户歧义或 SQL 安全拒绝算作主模型故障。

1. 主模型调用失败，按当前任务有限预算重试。
2. 达到连续失败阈值后熔断主路由，切换已配置且健康的备用。
3. 记录切换原因、用途、配置版本、尝试次数与告警，不记录密钥。
4. 备用响应经过相同的最小数据输入、SQL 安全及权限处理。
5. 主模型健康探测使用合成最小请求，恢复观察达标后允许切回；自动/人工切回见 DEC-15。
6. 主备均不可用时安全失败；若只是回答模型不可用，则保留授权表格并给出本地说明。

切换不能放宽云端数据范围、超时、权限或 SQL 白名单。阈值、恢复周期及任务总预算尚未确认。

## 16. SQL 安全、生产库资源保护与云端数据边界

### 16.1 SQL 安全与只读边界

【已确认；REQ-01、REQ-15、REQ-17、REQ-35】只读业务查询、权限强制和资源上限。

【暂定方案】执行入口唯一，候选 SQL 必须通过以下程序检查：

1. 使用支持目标 MySQL 方言的解析器构建结构；仅支持明确白名单语法，解析失败默认拒绝。
2. 仅允许单条受控查询，禁止写语句、DDL、存储过程、多语句、事务控制等非授权操作。
3. 遍历所有表字段与访问路径，校验实际标识符、别名、子查询和函数；禁止通过 `SELECT *` 暴露未授权字段。
4. 拒绝 `INTO OUTFILE`、`LOAD_FILE`、危险 UDF、`SLEEP`、`BENCHMARK`、锁定读取等可外传或耗尽资源的查询能力；语法及函数白名单由 DEC-04 决定，成本与资源边界由 DEC-11 决定。
5. 禁止用户问数访问系统库、权限库和应用配置。元数据采集是独立受控操作，不意味着生成 SQL 可访问系统元数据。
6. 应用并验证固定行权限，覆盖每条访问路径；重新检查改写后查询的结构和语义。
7. 检查复杂度、连接路径和成本，施加执行/等待超时、结果行数/字节上限与并发。
8. 使用最小化只读凭据执行；结果交付及外发前再授权、脱敏。

只读账号、关键词正则、模型“安全”评价或 SQL 末尾追加 LIMIT 均不能替代完整检查。不要简单在任意 SQL 末尾追加部门 WHERE；JOIN、已有 WHERE、外连接、聚合、子查询、CTE、UNION 的注入位置和语义不同。

SQL AST 改写、受控语义层或数据库受限视图均为候选方案，技术实现与支持语法必须由 DEC-04 评审测试。无法证明行权限正确的语法先拒绝；不能因模型要求或业务催促自动放开。

### 16.2 生产库资源控制

【暂定方案】

| 控制 | 执行位置与行为 |
| --- | --- |
| 用户/全局速率 | 受理前同时检查，超限返回可重试等待信息但不自动创建重任务 |
| 用户/全局并发 | 调度层与执行器统一计数，取消、失败、超时均释放或标记占用 |
| 队列和等待 | 有界队列与等待时限；过载排队或拒绝策略见 DEC-11 |
| SQL 硬超时 | 应用及数据库/驱动共同控制；HTTP 超时不能视为 SQL 已终止 |
| 返回行/字节 | 执行读取阶段即限制，超过上限明确截断或拒绝，不先无界读取再截断 |
| 复杂度/成本 | 限制笛卡尔积、深层子查询、大范围排序聚合等；LIMIT 不代表扫描成本低 |
| 连接池 | 连接数、等待、有效性和污染连接清理；运行未停止的连接不能复用 |
| 导出 | 单独并发、额度和存储生命周期，不绕过查询和脱敏规则 |
| 熔断/停用 | 业务库压力或错误异常时暂停新查询，保留管理和审计能力 |

沿用 B0 作为压测起点的建议：SQL 10 秒、结果 1,000 行、SQL 修正 2 次、单用户并发 1–2、模型单次 30 秒。**这些不是已确认默认值，也不能保证整体查询 5–10 秒。** 总超时、全局并发、每分钟额度、队列长度和结果字节数由 DEC-11 测试后确定。

是否接只读副本、生产查询窗口、负载预算、表和连接来源白名单由 DBA 确认（DEC-20）。不得把“只读”解释为“不会影响生产”。

### 16.3 云端数据允许范围

【已确认；REQ-41】默认仅发送必要问题、相关 Schema/字段注释、必要摘要，不发送原始明细。脱敏或抽样后的明细也不能据此默认开放。

【暂定方案】

| 数据 | 发送策略 |
| --- | --- |
| 用户问题 | 检查并去除凭据和不必要的个人敏感信息；无法安全处理则拒绝外发并提示 |
| Schema/注释/术语 | 当前问题所需且授权的最小集合；清理注释中的秘密或非结构敏感内容 |
| SQL 与错误 | 仅候选/修正必要部分，敏感常量最小化或使用受控参数引用；错误去内部路径、账号、业务值 |
| 会话内容 | 固定窗口内最小必要消息及结构化状态，不上传整个长期历史 |
| 查询结果 | 原始明细禁止默认发送；本地形成最小授权摘要后再检查外发 |
| 小样本汇总 | 可能推断个人，需阈值或禁止规则；未能证明安全则不外发 |
| 密码、API/数据库密钥 | 不进入模型提示词、请求日志或异常响应 |

云端网关执行字段发送策略和内容最小化，不能依赖模型自觉。必要摘要也要防止无权字段、低样本、唯一组合和反复追问推断。供应商、数据处理区域、保留/训练政策、允许摘要清单与小样本阈值见 DEC-07。模型总结不可用或摘要不允许外发时，提供本地授权统计说明与表格。

## 17. 审计、日志、监控与告警

### 17.1 审计事件与字段

【已确认；REQ-34、REQ-36】查询和系统管理日志，运行指标、错误统计和异常告警。

【暂定方案】

| 类别 | 事件 | 建议记录 |
| --- | --- | --- |
| 查询审计 | 提交、候选校验、执行、拒绝、修正、重试、取消、超时、结果发布 | 用户、任务/attempt/trace ID、时间、资源、权限/元数据版本、阶段、状态、耗时、行数、拒绝类型 |
| 数据访问 | 历史打开、共享创建/访问/撤销、导出生成/下载 | 操作者、对象 ID、模式、当前权限校验结果，不默认记录结果正文 |
| 管理操作 | 用户/部门/角色、权限、术语、指标、主题、模型和资源配置变更 | 管理者、目标、脱敏前后差异、版本、时间、操作结果 |
| 安全和运行 | 登录失败、异常访问、模型切换、数据库异常、备份恢复 | 追踪 ID、错误类别、服务/用途、影响范围、处置状态 |

普通用户 API 和日志不返回 SQL。后台受权审计可查看受保护的 SQL 信息，SQL 中敏感常量需脱敏或独立受控加密保存；是否保存完整 SQL/模型请求响应由 DEC-18 决定，不默认为全部存储。

审计与个人历史分离；历史删除不能随意抹掉安全证据。审计访问自身也要授权和记录，限制编辑及删除权限。审计落盘失败时查询是否停止、如何避免“成功但无证据”由 DEC-18 定案；暂定安全关键事件须可靠持久化，不能悄悄丢弃。

### 17.2 指标与面板

【暂定方案】提供成功/失败/拒绝率、端到端 P50/P95、分阶段耗时、SQL 超时/慢查询、队列长度、并发、连接池、结果行/字节、模型成功率/限流/延迟/用量/切换、权限拒绝分布、导出状态、同步和备份结果。模型 token/费用统计依供应商可用性，不承诺每个供应商都精确返回费用。

### 17.3 告警与处置

【暂定方案】模型连续故障/主备不可用、数据库连接异常、超时和资源超限激增、元数据同步失败、备份失败、密钥解密失败和异常拒绝数量触发告警。告警包含类型、级别、发生时间、受影响服务、trace ID 和处理建议，不能带明文密钥或业务明细。

同类告警聚合、去重、恢复通知和抑制策略避免告警风暴。告警渠道、通知对象、阈值、确认和升级流程见 DEC-18；在渠道未定前不声称已配置邮件、短信或企业 IM。

## 18. 逻辑架构与端到端业务流程

### 18.1 逻辑组件

【暂定方案】此为职责分解，不强制拆分独立容器或冻结框架。

```text
内网用户浏览器 -> HTTPS 反向代理 -> Web / 应用 API
                                     |
                         身份、部门、角色、当前权限
                                     |
                    会话 / 历史 -> 查询编排与任务调度
                                     |
                   业务术语 / 指标 / 相关 Schema 检索
                                     |
                      云端模型网关（最小化输入、主备）
                                     |
                   程序化 SQL 解析、安全、权限与成本校验
                                     |
                     受限只读执行器 -> 生产 MySQL
                                     |
                  当前权限复核、脱敏、本地摘要、图表整理
                                     |
                   获准摘要 -> 回答模型 / 本地降级说明
                                     |
                  授权结果 -> 历史 / 受控快照 / Excel 导出

应用存储：用户、权限、语义、会话、任务、共享、配置、审计
横向能力：取消、总预算、限流、追踪、监控告警、备份恢复
```

| 组件 | 职责 | 必须避免 |
| --- | --- | --- |
| API/身份 | 认证、参数校验、对象授权、幂等与状态返回 | 信任前端自报用户/权限 |
| 权限服务 | 发布有效版本、合成模板例外、固定范围映射、敏感策略 | 旧会话授权永久有效 |
| 语义服务 | 结构采集、术语、指标、主题及版本检索 | 未确认关系直接执行 |
| 会话/任务 | 固定窗口、结构化条件、成功基准、状态及总预算 | 失败覆盖成功基准、跨用户结果串用 |
| 模型网关 | 数据最小化、密钥使用、用途路由、超时和主备 | 模型批准权限、无界循环 |
| SQL 安全/执行器 | 解析与白名单、行权限、成本、只读连接、硬限制和取消 | 仅正则、LIMIT 或 HTTP 超时保护 |
| 结果/共享/导出 | 当前授权复核、脱敏、快照/文件生命周期 | 存储链接绕过重新授权 |
| 审计/监控/运维 | 事件留存、指标、告警、备份及恢复 | 凭据日志、无演练备份 |

### 18.2 首次问数交互顺序

1. API 校验登录身份、问题、会话归属、幂等键及配额，创建 task ID。
2. 整理最近消息与结构化状态；存在歧义则等待澄清，不调用执行器。
3. 基于当前权限检索结构与语义，形成条件摘要及版本。
4. 网关检查外发信息，调用 SQL 用途模型，记录尝试及配置版本。
5. 程序校验候选、强制固定范围、检查最终 SQL，执行前重载权限。
6. 调度与执行器施加查询限制，通过业务只读账号执行。
7. 读取期间限制行/字节；本地规范化、授权复核、脱敏及摘要。
8. 摘要满足云端规则时调用回答模型，否则本地回答；取消则不再启动新阶段。
9. 原子更新任务可用结果、成功基准及历史，写审计；返还用户安全结果。
10. 任何拒绝、异常或预算耗尽沿第 11 节安全退出，不遗漏连接/额度清理。

### 18.3 共享/下载交互顺序

先验证对象可访问资格，再验证当前业务数据权限；共享模式决定快照或显式重查，文件模式决定安全下载或要求重新生成。身份检查、源记录状态、权限版本与存储读取需避免检查后使用失效授权的竞态（DEC-05、DEC-13）。

| 数据类别 | 已确认边界 | 暂定生命周期与待决策 |
| --- | --- | --- |

## 20. 接口设计草案与错误分类

### 20.1 公共约定

【暂定方案】以下为建议 REST 能力清单，路径、方法、字段与传输方式须技术评审，不是已冻结 API。

- 所有业务接口校验登录态和对象授权；管理接口另校验操作权限。客户端 ID 只定位对象，不代表对象归属。
- 提交任务建议异步受理，返回 task/query ID；轮询或 SSE 推送待选型。流式推送各内容块仍受授权和取消状态约束。
- 请求携带 trace/幂等标识，任务返回状态、错误码和用户安全提示；密码密钥不进入通用请求日志。
- 幂等键按用户与操作作用域隔离，重复相同请求返回同一受理结果，内容冲突则拒绝；保存期限见 DEC-12。
- 列表分页均服务端限制条数；普通用户任何响应字段均不含 SQL、内部堆栈、密钥或未授权数据。

### 20.2 能力清单

| 能力 | 建议方法与路径 | 输入/输出要素 | 授权检查 |
| --- | --- | --- | --- |

| 当前身份 | `GET /api/me` | 用户、部门、角色、可见功能 | 当前有效身份，不返回秘密 |

| 术语/指标/主题 | `/api/admin/terms`、`/api/admin/metrics`、`/api/admin/topics` | 定义、审核、发布 → 有效版本 | 管理/审核权、依赖校验 |

| 任务状态 | `GET /api/queries/{id}` | 阶段、状态、警告、trace ID | 本人或单独运维授权 |
| 取消任务 | `POST /api/queries/{id}/cancel` | 任务 ID → 逻辑/物理停止状态 | 所有权、幂等及绑定验证 |
| 获取结果 | `GET /api/queries/{id}/result` | 授权回答、列/行、图表、范围及时间 | 当前权限重新检查 |

| 审计/监控/告警 | `/api/admin/audits`、`/api/admin/metrics-view`、`/api/admin/alerts` | 时间/事件过滤 → 脱敏记录 | 审计/运维权限 |

### 20.4 错误分类

| 建议错误码 | 用户行为 | 处理 |
| --- | --- | --- |
| AUTH_REQUIRED / ACCOUNT_DISABLED | 登录或联系管理员 | 不受理任务 |
| OBJECT_NOT_ACCESSIBLE | 检查本人历史/共享资格 | 不泄露对象是否属于其他用户 |
| PERMISSION_DENIED | 调整问题或联系管理员 | 审计，禁止自动修正绕过 |
| NEEDS_CLARIFICATION | 补充条件 | 未执行 SQL，保留关联状态 |
| METADATA_UNAVAILABLE / STALE | 稍后重试或联系管理员 | 不执行失效结构 |
| SQL_UNSAFE / SQL_UNSUPPORTED | 修改问题或联系管理员 | 默认拒绝，记录安全类别 |
| RATE_LIMITED / CAPACITY_EXCEEDED | 稍后提交 | 提供安全的等待建议，不自动重跑 |
| MODEL_UNAVAILABLE | 稍后重试 | 有限主备耗尽后失败或回答降级 |
| QUERY_TIMEOUT / DB_UNAVAILABLE | 缩小条件或稍后再试 | 清理/隔离执行资源，记录原因 |
| CANCEL_REQUESTED / CANCELLED | 查看停止状态 | 不启动后续生成，不伪报数据库物理终止 |
| RESULT_EXPIRED / EXPORT_EXPIRED | 重新查询或生成文件 | 不返回失效存储入口 |
| INTERNAL_ERROR | 提供 trace ID 给支持人员 | 通用安全提示，不带堆栈和凭据 |

HTTP 状态建议：认证 401、授权 403（对象隐藏场景可统一 404）、输入 400、冲突 409、限流 429、依赖故障 503；已受理的任务错误通过状态接口返回任务终态，不混同 API 传输成功与查询成功。

## 21. 部署、备份恢复及非功能要求

### 21.1 部署与网络

【已确认；REQ-37、REQ-38】Linux + Docker Compose，内网经反向代理 HTTPS。

【暂定方案】反向代理提供证书和 HTTPS；应用端口不直接对用户网段暴露。浏览器不直连 MySQL、对象存储私有入口或密钥接口。应用出站仅允许所需云端模型和受控依赖；入站内网访问并不免除认证、授权、CSRF/CORS 和安全响应头策略。

应用逻辑可先单体或少量服务，必要组件包括 API/Web、应用持久存储、查询执行、调度和反向代理；是否 Redis/独立队列/向量库属于技术选型，不默认强制增加。生产业务库在既有环境，不作为 Compose 中新建业务库替换。

容器建议非 root、最小镜像、健康检查、资源限制、受控持久卷和日志轮转。区分开发/测试/生产；镜像/配置版本可回滚，存储迁移要有兼容及备份策略。生产访问边界见 DEC-20；部署主机、资源、镜像仓库、证书更新及发布回滚见 DEC-21，不在文档列入服务器或仓库密码。

### 21.2 密钥与持久化

【暂定方案】模型密钥由后台录入后密文保存，解密主密钥由部署密钥或等效安全机制托管，二者不混为“页面配置即可安全”。业务只读和应用写入凭据分离，不进镜像、代码仓库或普通日志。数据卷存储应用状态，快照/文件可采用受控存储；所有对象的访问仍由当前权限决定。

### 21.3 备份与恢复

【已确认；REQ-39】备份 ChatBI 自身用户、权限、元数据、指标、配置、历史及审计；不代替生产 MySQL 的备份职责。

【暂定方案】备份清单同时覆盖部门/角色/用户例外、敏感和身份映射、术语/主题、模型配置密文、必要共享状态及历史关联关系；快照是否全部备份和临时导出文件是否排除见 DEC-19。不得因文件被排除而声称所有历史明细均可恢复。

备份流程：一致性快照/事务导出 → 清单及版本 → 加密 → 完整性检查 → 受控独立位置 → 记录状态/告警。主密钥单独安全托管；只有密文而无恢复能力的备份不可视为可用。备份访问权应高于普通业务查询权限。

恢复流程：选择已验证备份 → 隔离环境恢复应用数据及必要密钥 → 校验版本/引用 → 验证登录、权限、指标、历史和审计 → 对齐恢复后外部业务数据与有效撤权状态 → 再开放查询。旧任务不得恢复成自动重跑；旧文件/共享访问重新校验，避免从旧备份复活已删除或撤销的入口。

备份频率、保留、异地副本、RPO/RTO、加密托管、恢复演练和删除记录对齐见 DEC-19。

### 21.4 性能与稳定性

【已确认；REQ-02、REQ-40】约 10–50 人，常规查询初始目标 5–10 秒，复杂可更久，具体以测试为准。这是规模/目标，不表示同时有 50 个 SQL 并发，也不等同于已经承诺 P95 不超过 10 秒。

【暂定方案】端到端耗时从服务端受理至可用结果，包含队列、模型和 SQL；另记录首个阶段反馈及摘要完成时间。固定测试问题、样本数据、模型版本、网络和缓存状态；分层报告常规与复杂问题 P50/P95、超时比例和并发。

高负载以有界队列/拒绝保护生产库，不因性能目标放宽权限。模型总结不可用时降级；业务库不可用时不编造或伪装当前结果，历史快照只能明确作为历史显示。任务异常资源可回收、服务重启中间任务标记未完成并核对旧执行，不自动重复重查询。
